# Frontend Polish and Interaction Design

日期：2026-05-19  
状态：已批准，可直接实施  
适用项目：安卓背单词 Android App  
设计方向：Apple 操作清晰度 + Claude 暖纸编辑感

## 目标

把现有 Jetpack Compose 前端从“功能可用”提升到“长期可用、克制、高级、操作清晰”的学习工具体验。首页仍是学习台，不做营销化视觉，不扩展账号、同步、社交或 AI 功能。

## 设计原则

- 视觉使用暖纸背景、暖黑文字和赤陶主色，避免纯白、冷黑、蓝紫渐变、玻璃拟态和装饰光斑。
- 操作遵循移动端学习工具逻辑：主任务明确、触控目标大、状态反馈即时、失败可恢复。
- 使用留白、细边框和轻微色块建立层级，减少厚阴影和卡片堆叠。
- 360px 宽度下优先保证可读和可点，不追求复杂布局。
- Compose 组件保持简单，不为一次性场景创建复杂抽象。

## Design Token

`core/designsystem` 继续作为唯一主题入口，统一 light / dark token：

- 浅色：暖纸背景、暖白 surface、暖黑正文、低对比边框。
- 深色：暖黑背景、棕黑 surface、暖白正文、低亮度边框。
- 主色：赤陶色，只用于主行动、当前选中和关键强调。
- 成功、警告、错误只用于语义状态，避免大面积铺色。
- 圆角收敛到 12dp 左右；重点面板可稍大，但不使用过度胶囊化卡片。
- 阴影降低，优先使用边框、背景层次和留白。

## 全局布局

- 页面 padding 使用稳定节奏：窄屏 16dp，常规 20dp，上下 18-20dp。
- `VocabScreen` 保留滚动能力，但减少过大的 section 间距。
- 底部导航降低存在感：保留清晰选中态，减少悬浮大胶囊和明显阴影，避免抢占学习内容注意力。
- 页面标题更像工具页标题，不做营销式 hero。

## Today 页面

Today 是学习台，优先表达三件事：

1. 今天还剩多少。
2. 现在应该做什么。
3. 完成后未来压力如何变化。

调整方向：

- “今日队列”作为主面板，主按钮视觉最强。
- 新学、复习、已完成作为辅助指标，不喧宾夺主。
- 完成进度和未来 14 天负载保留，但解释文字更短。
- 导入中、导入失败、空状态都提供明确下一步。

## Review 页面

Review 是最高优先级体验，要求专注、低噪音、反馈可靠。

正面：

- 只展示新词/词书标签、发音、单词、音标和“显示释义”。
- 单词字号根据长度降级，长词不撑破屏幕。
- 点击卡片或按钮都可翻面。

背面：

- 释义层级更清晰：主释义优先，词性/英文定义/标签次之。
- 四档反馈保持 2x2，按钮最小高度不低于 56dp。
- 提交中禁用反馈按钮，保留当前卡片；成功后再切换下一张。
- 失败时保留当前卡并显示可读错误，用户可重新提交。

## Stats 页面

Stats 负责解释学习状态，不制造数据噪音。

- 首屏展示连续学习、记忆保持和关键摘要。
- 趋势、热力图、未来负载使用低饱和色。
- 困难词避免大面积红色，仅用错误色作为小面积强调。
- 词书进度保持可扫读，不把所有行都做成强卡片。

## Wordbook 与 Settings

- Wordbook 强调选择、搜索、状态筛选和进度，减少视觉装饰。
- Settings 使用清晰分组，危险/导出/许可证等操作状态明确。
- 表单和开关遵循平台原生交互，所有写入操作应有成功或失败反馈。

## 交互状态

关键交互至少覆盖：

- 默认、按下、禁用、加载中、成功、失败、空状态。
- 超过 300ms 的操作显示 loading 或状态变化。
- 复习提交、词库导入、数据导出失败时必须提供恢复路径。
- 不只依赖颜色表达状态，重要状态配合文字说明。

## 验证计划

最小验证：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

如本地有可用设备或模拟器，再验证：

- 360x800
- 390x844
- 412x915
- 768x1024

重点检查：

- Today、Review、Stats、Wordbook、Settings 无重叠。
- Review 四个反馈按钮窄屏可点击。
- 长单词、长释义、无音标数据可读。
- 浅色 / 深色模式可读。
- 复习提交失败不会跳过当前卡片。
