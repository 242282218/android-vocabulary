# 2026-05-25 持续优化第 163 轮

## 当前审查范围

本轮接着第 162 轮，补齐 release readiness 正向路径的隔离回归测试。此前 `verify-release-scripts.ps1` 主要依赖源码结构断言，能防止关键字段被删，但不能证明完整 fake evidence 可以让 readiness 输出 `runStatus=completed`。

## 发现

`verify-release-readiness.ps1` 的真实仓库负向门禁已经能列出失败 requirement，但正向路径缺少最小 fixture 覆盖。这样后续修改 readiness evidence 归档、hash 交叉校验或 `failedRequirementNames=<none>` 时，可能出现源码断言仍通过、实际正向流程失败的问题。

实现 fixture 时还发现一个测试层面的编码问题：仓库路径包含中文目录名，使用 `Set-Content -Encoding Ascii` 写入 metadata 会把路径写成 `?????`，导致 `releaseArtifacts` 校验误失败。这不是 readiness 逻辑错误，而是 fixture evidence 写入方式不保真。

## 方案

- 方案 A：继续只用源码结构断言。成本最低，但不能覆盖 readiness 正向运行结果。
- 方案 B：在 `verify-release-scripts.ps1` 中构造隔离临时仓库和最小 evidence，运行真实 `verify-release-readiness.ps1`。成本稍高，但能验证完整正向路径。

本轮采用方案 B，并把包含路径的 metadata 写入改为 UTF-8 无 BOM，避免中文路径和 BOM 污染首个 key。
