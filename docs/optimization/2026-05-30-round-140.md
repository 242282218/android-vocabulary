# 第 140 轮：Review 提交成功后旧卡防重复

## 审查证据

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt` 在提交成功后会清空背面状态，但队列刷新前 `uiState.item` 仍可能是刚提交的旧卡。
- `ReviewRoute` 只有在背面可见时展示反馈按钮；但旧卡仍可再次点击显示背面，如果数据库 Flow 刷新稍慢，就可能再次提交同一张旧卡。
- 已有测试覆盖“提交中重复点击”防抖，但没有覆盖“第一次提交已成功、队列尚未刷新”的窗口。

## 方案

- 方案 A：ViewModel 记录刚提交成功的 `cardId`，在队列首项变化前禁止该卡再次 `showBack()` / `submit()`；当队列首项变化或清空时自动释放。范围小，修 UI 层竞态。
- 方案 B：依赖 Room Flow 足够快刷新队列。实现为零，但保留极短竞态窗口。

采用方案 A。

## 修改

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 新增 `submittedCardId`。
  - 提交成功后记录 cardId。
  - 队列首项变化后释放该记录。
  - 对已成功提交但仍停留在 UI 的旧卡，`showBack()` / `submit()` 直接忽略。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 新增 `submittedCardCannotBeSubmittedAgainBeforeQueueRefresh`。
