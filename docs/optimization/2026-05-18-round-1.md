# 2026-05-18 持续优化第 1 轮

## 当前状态判断

项目已从早期 Vue/Capacitor 规划转为 Kotlin + Jetpack Compose + Room + DataStore + WorkManager + FSRS 的原生 Android 路线。当前已经具备词库导入、今日队列、复习反馈、ReviewLog、统计、设置、提醒、导出和基础测试。

本轮基线：

- `scripts/test/verify-vocab-assets.ps1` 通过，assets 是 publish-safe。
- 直接运行 `gradlew.bat testDebugUnitTest` 失败，根因是当前 shell 未设置 `JAVA_HOME`；后续完整验证使用 `scripts/test/verify-local.ps1`。
- 当前目录不是 Git 仓库，不能依赖 git diff/status 做变更审计。

## 对标项目可借鉴点

- Android 官方架构建议：数据层通过 Repository 暴露数据，UI 层消费不可变状态，Room/DataStore 作为本地事实来源。
- Now in Android：多模块、offline-first、Flow 驱动 UI、fake/fixture 优先测试。
- AnkiDroid：复习写入必须是事务，调度失败不能产生半条学习记录。
- FSRS-Kotlin / open-spaced-repetition：算法细节隔离在 scheduler adapter，业务层只依赖四档反馈和调度结果。

## 差距清单

### P0

- 复习调度异常未统一包装：scheduler 抛错时 UI 可能得到低质量错误信息。影响复习主路径；根因是 Repository 直接调用 scheduler；建议转换为 `AppError.SchedulerFailed`；收益是可诊断且事务不落脏数据；风险低。

### P1

- Wordbook 搜索只查单词和主释义：别名、替代释义无法命中。影响查词可用性；根因是 SQL 未关联 `word_aliases`，导入也未写入 `altMeanings`；建议导入 alias + altMeaning 并让搜索走 alias exists 子查询；收益高；风险中低，需注意 LIKE 转义。
- Review 页面不可滚动：窄屏、长释义、较大字体可能挤压反馈按钮。影响实际学习体验；根因是页面 Column 缺少滚动容器；建议加 `verticalScroll`；风险低。

### P2

- 今日 due 队列尚未按近 30 天困难度二级排序。
- UI smoke test 只渲染，不做重叠/可见性强断言。
- `daily_stats` 有缓存，但缺少显式重建入口。

### P3

- 底部 Tab 仍是英文，可后续统一产品文案。
- 统计图可补空态和极端值说明。

## 本轮要做的优化项

1. 搜索能力补齐：导入 `altMeanings` 到别名表，Wordbook 搜索命中别名。
2. 复习错误边界：scheduler 失败统一为 `SchedulerFailed`，并用测试确认不写卡片/日志。
3. 窄屏稳定性：Review 页面支持滚动。

## 本轮风险

- alias 搜索增加一个 `EXISTS` 子查询，词库规模约万级，当前 limit 80，风险可接受；后续若搜索变慢，再加 `word_aliases(value)` 或 FTS。
- Review 页面滚动可能改变首屏视觉高度，但不会改变业务状态。
