# 2026-05-25 持续优化第 137 轮

## 当前审查范围

本轮接着第 136 轮，审查 `smoke-release-bundle.ps1 -AllowDebugSigning` 生成的 APK Set 中间产物命名，避免本地调试产物继续沿用 release 前缀。

## 发现

第 136 轮已经让 AAB smoke 在 bundletool 前校验输入 AAB，并允许 `-AllowDebugSigning` 继续跑本地链路。但默认 APK Set 文件名仍使用输入 AAB 的文件名前缀。

当前历史 AAB 是：

```text
dist/AndroidVocabulary-release-v0.1.0-1.aab
```

因此本地调试路径会生成：

```text
build/bundle-smoke/AndroidVocabulary-release-v0.1.0-1-debug-signing.apks
```

虽然文件名包含 `debug-signing`，但前缀仍像正式 release 记录，长期归档时容易混淆。

## 方案

- 方案 A：保留现状，只依赖 `debug-signing` 后缀区分。改动小，但语义不够明确。
- 方案 B：本地验证 APK Set 默认使用 `AndroidVocabulary-build-validation-v<versionName>-<versionCode>-debug-signing.apks`；只有 AAB 已验签且未使用本地覆盖参数时，才保留 release 前缀。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 新增 `Test-BundleSmokeReleaseReady()`，集中判断 bundle smoke 是否可作为 release-ready 记录。
- 新增 `Get-DefaultApksPath()`，集中生成 APK Set 默认路径。
- local-only 路径默认输出：

```text
build/bundle-smoke/AndroidVocabulary-build-validation-v<versionName>-<versionCode>-debug-signing.apks
```

- 自定义 `-ApksPath` 如果在 local-only 路径下看起来像 release 命名，会输出 warning。
- metadata 新增 `bundleSmokeReleaseReady`。
- build-only 和安装 smoke 的最终成功输出都基于 `Test-BundleSmokeReleaseReady()` 区分 release-ready / not release-ready。

`scripts/test/verify-release-scripts.ps1`

- 增加 APK Set 默认命名回归，防止 local-only APKS 输出重新使用 release 前缀。
