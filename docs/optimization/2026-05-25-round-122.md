# 2026-05-25 持续优化第 122 轮

## 当前审查范围

本轮审查单独运行 `smoke-release-bundle.ps1` 时的可追溯性。第 121 轮已经为 APK smoke 增加轻量 run metadata；AAB smoke 仍主要依赖终端输出和生成的 `.apks` 文件。

## 发现

`smoke-release-bundle.ps1` 会在 `build\bundle-smoke` 生成 APK Set，但没有固定 metadata 文件记录本次运行状态、AAB 来源、APK Set 输出路径、签名类型、设备和失败阶段。

这会让单独运行 AAB smoke 后难以快速判断：

- 是否使用了显式 `BundlePath`
- APK Set 是 debug-signing 还是 release-signing
- 是 build-only、bundletool install 失败，还是安装后启动 smoke 失败

## 方案

- 方案 A：为 AAB smoke 新增 `-LogDir` 并生成完整日志目录。更完整，但会扩大调用契约，并影响 `verify-device.ps1` 的调用边界。
- 方案 B：在既有 `build\bundle-smoke` 目录写轻量 metadata 文件，不新增参数，不改变 bundletool 行为。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 新增 `Get-BundleSmokeArtifactDir`。
- 新增 `Get-BundleSmokeRunMetadataPath`。
- 新增 `Resolve-BundleSmokeFailureStage`。
- 新增 `Save-BundleSmokeRunMetadata`。
- 普通 AAB smoke 运行写入：

```text
build\bundle-smoke\smoke-release-bundle-run.txt
```

- metadata 覆盖 started / completed / failed 三种状态，并记录：

```text
versionName
versionCode
deviceSerial
bundlePath
bundlePathSource
bundlePathExpectedName
bundlePathMatchesCurrentVersionedName
apksPath
apkSetSigning
bundleToolJar
buildOnly
allowDebugSigning
failureStage
failureMessage
```
