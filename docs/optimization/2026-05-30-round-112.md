# 第 112 轮：Review 反馈失败提示可访问性

## 审查证据

- `ReviewRoute.FeedbackButtons` 当前使用两列 `FlowRow`，按钮间距 10dp，每个反馈按钮最小高度 64dp；四个中文标签和说明都较短，已满足小屏触控目标的基本要求。
- 提交失败后，页面会保留当前卡片并显示“反馈没有保存，当前卡片已保留。”，但错误卡片没有 live region。
- 复习反馈保存失败会阻断学习事实写入，属于需要即时感知的状态；Settings 页在第 109/110 轮已为同类失败状态使用 assertive live region。
- `ui-ux-pro-max` 查询结果强调移动端关键反馈要满足至少 44dp 触控目标，错误状态不能只依赖视觉呈现。

## 方案

- 方案 A：不修改按钮，仅记录当前两列布局和 64dp 高度已经满足小屏基础触控要求。最小，但不会解决失败提示的可访问性缺口。
- 方案 B：保留反馈按钮布局，只给提交失败卡片增加 assertive live region。范围最小，并与 Settings 状态语义保持一致。
- 方案 C：重做反馈按钮为单列大按钮并增加 Compose UI 截图测试。更强，但会改变复习节奏和页面密度，超出本轮证据。

采用方案 B。

## 修改

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewRoute.kt`
  - 给提交失败 `VocabCard` 增加 `Modifier.semantics { liveRegion = LiveRegionMode.Assertive }`。
  - 保持四个反馈按钮的两列布局、10dp 间距和 64dp 最小高度不变。
