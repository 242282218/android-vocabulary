# 2026-05-25 持续优化第 73 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1 -ApksPath` 指向不存在目录时，脚本是否有清楚行为。

## 发现

上一轮已经为自定义 `-ApksPath` 增加签名类型 warning。本轮继续检查如果调用方传入：

```powershell
.\build\bundle-smoke\nested-output\custom-debug-signing.apks
```

而 `nested-output` 目录不存在，bundletool 是否失败或自动创建。

## 验证结果

执行：

```powershell
.\scripts\test\smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning -ApksPath .\build\bundle-smoke\nested-output\custom-debug-signing.apks
```

结果：通过。bundletool 输出：

```text
Output directory '.\build\bundle-smoke\nested-output' does not exist, creating it.
```

脚本最终输出：

```text
[info] APK Set signing=debug-signing
[ok] APK Set: .\build\bundle-smoke\nested-output\custom-debug-signing.apks
[ok] bundle smoke build-only passed with debug signing; not release-ready
```

产物检查：

```powershell
Get-ChildItem build/bundle-smoke/nested-output -File
```

结果：生成 `custom-debug-signing.apks`。

忽略规则检查：

```powershell
git check-ignore -v build/bundle-smoke/nested-output/custom-debug-signing.apks
```

结果：匹配 `.gitignore:3:**/build/`，该产物不会进入仓库。

空白检查：

```powershell
git diff --check -- scripts/test/smoke-release-bundle.ps1 docs/release.md docs/optimization/2026-05-25-round-72.md
```

结果：通过，仅有 `docs/release.md` 的 LF/CRLF 工作区提示。

## 结论

`-ApksPath` 指向不存在目录时不需要改脚本；bundletool 会自动创建输出目录。只要文件名包含 `debug-signing` / `release-signing`，当前记录可读性足够。
