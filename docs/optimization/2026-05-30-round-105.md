# 第 105 轮：首复习统计同时间戳去重

## 审查证据

- `review_daily_stats.newCount` 原来用 `first_reviews.firstReviewedAt = review_logs.reviewedAt` 判断首复习。
- `first_reviews` 原来只保存 `MIN(reviewedAt)`。
- 当同一卡片存在多条相同最早 `reviewedAt` 的异常、手工或历史日志时，这些日志都会被算作 new，导致 `newCount` 偏大、`reviewCount = completedCount - newCount` 偏小。
- 第 104 轮已把同时间戳排序统一为 `reviewedAt ASC, id ASC`，统计应沿用同一 tie-breaker。

## 方案

- 方案 A：只记录风险。零改动，但发布阶段仍会留下统计错误。
- 方案 B：让 `first_reviews` 定位唯一首条日志 `(reviewedAt ASC, id ASC)`，`newCount` 只统计 `firstLogId`。需要升 Room schema，但只重建 view，不搬表数据。
- 方案 C：增加 `(cardId, reviewedAt)` 唯一约束。可从写入层禁止异常数据，但会影响历史数据迁移，风险较高。

采用方案 B。
