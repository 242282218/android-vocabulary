# 第 100 轮：Dependency Check 发布门禁 fail-fast

## 审查证据

- `git status --short` 显示当前工作树已有大量未提交改动，本轮只继续处理发布证据链相关文件。
- `.github/workflows/android.yml` 当前 CI 已运行 `dependencyCheckAggregate`，并通过 `NVD_API_KEY` secret 传入 key。
- `scripts/lib/android-env.ps1` 的 required checks 已包含 `dependencyCheckAggregate`。
- `scripts/test/verify-release-scripts.ps1` 已覆盖 release evidence、GitHub Actions evidence 和 dependency-check required check。
- 本机实测未设置 `NVD_API_KEY` 时，`dependencyCheckAggregate` 会进入 NVD 更新后以 403/404 失败，失败原因正确但不够早、不够清晰。

## 方案

- 方案 A：只保留文档说明。改动最少，但本地和 CI 仍会慢失败，错误信息依赖 OWASP 插件输出。
- 方案 B：只在 GitHub Actions 中增加 secret 检查。CI 更清楚，但本地仍会慢失败。
- 方案 C：在 root Gradle 配置里对 dependency-check 任务做 NVD key fail-fast，并同步文档与回归脚本。覆盖本地和 CI，改动范围仍小。

采用方案 C。

## 修改

- `build.gradle.kts`
  - 抽出 `nvdApiKeyProvider`。
  - 对 `dependencyCheckAggregate`、`dependencyCheckAnalyze`、`dependencyCheckUpdate` 增加执行前 key 检查。
  - 缺少 `NVD_API_KEY` / `-PnvdApiKey` 时抛出项目化错误信息。
- `README.md`
  - 补充未设置 NVD key 时会 fail-fast。
- `docs/release.md`
  - 补充 dependency-check 缺 key 的 fail-fast 行为。
- `scripts/test/verify-release-scripts.ps1`
  - 增加 root Gradle dependency-check fail-fast 配置的回归断言。

## 验证

通过：

```powershell
.\scripts\test\verify-release-scripts.ps1
.\gradlew.bat --no-daemon --console=plain help
git diff --check -- build.gradle.kts README.md docs/release.md scripts/test/verify-release-scripts.ps1 .github/workflows/android.yml scripts/lib/android-env.ps1 scripts/test/verify-release-artifacts.ps1 scripts/test/verify-release-readiness.ps1
```

预期失败路径通过：

```powershell
.\gradlew.bat --no-daemon --console=plain dependencyCheckAggregate
```

在本机未设置 `NVD_API_KEY` 时，输出：

```text
NVD API key is required for dependencyCheckAggregate. Set NVD_API_KEY or pass -PnvdApiKey=<key>.
```
