# 第 119 轮：Review 提交失败后冻结首次决策耗时

## 审查证据

- `ReviewViewModel.submit()` 原来每次提交都会调用 `reviewDurationMs()`，按“答案显示时间 -> 当前点击时间”重新计算耗时。
- 提交失败后 UI 会保留当前卡片并允许 retry；用户第一次点击反馈时已经完成复习决策，后续等待和重试属于技术失败恢复时间。
- 现有 `submitFailureKeepsAnswerVisibleAndAllowsRetry` 覆盖了错误清除和 retry，但没有断言 retry 后写入的 `durationMs`。

## 方案

- 方案 A：保持现状，只补测试记录当前行为。会把失败后的等待时间计入学习耗时。
- 方案 B：首次提交失败后冻结当次 `durationMs`，retry 复用该值；成功或切换卡片/重新显示答案后清空。能避免统计被技术失败拉长。
- 方案 C：把失败恢复时间单独记录到日志。信息更完整，但需要扩展日志模型和导出契约，超出本轮。

采用方案 B。

## 修改

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 新增 `failedSubmitDurationMs`。
  - 提交失败时用 CAS 保存首次决策耗时。
  - retry 时优先复用冻结耗时。
  - 成功提交或新卡片显示答案时清空冻结值。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 新增 `retryAfterSubmitFailureKeepsOriginalDecisionDuration`。
  - 覆盖失败后等待到 12 秒再 retry，最终写入仍为首次点击时的 3500ms。
