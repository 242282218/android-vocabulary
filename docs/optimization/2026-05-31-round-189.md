# 第 189 轮：按 selectedBooks 统一 Stats 页趋势、保持率、困难词与进度作用域

## 审查证据

- `feature/stats/src/main/java/com/zzz/androidvocab/feature/stats/StatsRoute.kt`
  - 本轮开始前，只有“未来负载”明确使用当前词书；复习趋势、热力图、连续学习、困难词、掌握分布、词书进度仍是全量词书。
  - 页面上部分卡片写了“全部词书”，部分卡片没有 scope 标签，整页混合语义。
- `feature/stats/src/main/java/com/zzz/androidvocab/feature/stats/StatsViewModel.kt`
  - `selectedBooks` 已经在 UI state 里，但大部分统计 usecase 没消费它。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetDailyActivityUseCase.kt`
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetRetentionStatsUseCase.kt`
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetStreakUseCase.kt`
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetDifficultWordsUseCase.kt`
  - 以上 usecase 本轮开始前都只看时间，不看 `settings.selectedBooks`。
- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
- `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeDailyActivity`、`observeRetentionStats`、`observeStreakStats`、`observeDifficultWords` 对应 SQL 之前都没有按词书过滤。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetBookProgressUseCase.kt`
  - 词书进度始终返回全部词书，和当前筛选脱节。

结论：Stats 页本轮开始前不是单一事实域。用户一旦筛选词书，未来负载看到的是当前词书，但趋势、保持率、连续学习、困难词、进度看到的是全量词书，跨卡片比较会失真。

## 方案

- 方案 A：维持混合作用域，只给还没写明 scope 的卡片补标签。
  - 优点：改动小。
  - 缺点：页面仍然不是同一事实域，用户需要自己在脑内切换上下文。
- 方案 B：让 Stats 页所有核心指标都遵循 `selectedBooks`；未筛选时自然退化为全部词书。
  - 优点：和 Today / Review / Wordbook 的筛选语义一致，整页数据可以直接对读。
  - 缺点：需要同步 domain、repo、DAO、测试和页面文案。

采用方案 B。
