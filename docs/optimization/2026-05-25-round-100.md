# 2026-05-25 持续优化第 100 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 的设备诊断日志保存，重点是 `Save-DeviceDiagnostics` 失败时是否会留下清晰证据并触发 logcat tail 归档。

## 发现

旧逻辑直接执行：

```powershell
& $adb devices -l | Set-Content devices.txt
& $adb -s <serial> shell getprop | Set-Content getprop.txt
```

问题有两个：

- 没有检查 `adb devices -l` 和 `adb shell getprop` 的 exit code，可能生成空/部分文件后继续执行。
- `Save-DeviceDiagnostics` 在主 `try/finally` 之前执行；如果诊断步骤抛错，`Save-LogcatTail` 不会运行。

## 方案

- 方案 A：把诊断步骤移入主 `try/finally`，并新增 `Save-DeviceDiagnosticCommand` 捕获 stdout/stderr、exit code 和输出文件。改动集中，失败时仍会进入 logcat tail 保存。
- 方案 B：保留位置，只在每个命令后检查 `$LASTEXITCODE`。能发现失败，但仍无法保证 logcat tail。

本轮采用方案 A。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Save-DeviceDiagnosticCommand`。
- `devices.txt` 和 `getprop.txt` 现在通过捕获模式写入，并检查 exit code。
- 诊断命令失败时错误包含命令名、exit code、输出文件和原始输出。
- `Save-DeviceDiagnostics` 移入主 `try/finally`，诊断失败也会尝试保存 `logcat-tail.txt`。

结果：诊断命令捕获、输出文件和 logcat tail 归档路径均可定位。

最小捕获实验：

```powershell
$ErrorActionPreference='Stop'; $dir=Join-Path $env:TEMP 'android-vocab-diagnostic-command-test'; New-Item -ItemType Directory -Force -Path $dir | Out-Null; function Invoke-CapturedNative { param([string]$Name,[string]$FileName,[string[]]$Arguments) $outputPath=Join-Path $dir $FileName; $previous=$ErrorActionPreference; $ErrorActionPreference='Continue'; try { $output=& cmd @Arguments 2>&1; $exitCode=$LASTEXITCODE } finally { $ErrorActionPreference=$previous }; $outputText=@($output | ForEach-Object { $_.ToString() }); Set-Content -LiteralPath $outputPath -Value $outputText; if ($exitCode -ne 0) { throw "$Name failed with exit code $exitCode. See $outputPath. Output: $($outputText -join "`n")" } }; try { Invoke-CapturedNative 'cmd failure' 'failure.txt' @('/c','echo diagnostic-output && exit 7') } catch { "caught=$($_.Exception.Message)"; "file=" + (Get-Content -Raw (Join-Path $dir 'failure.txt')) }
```

结果：非 0 退出能保留输出文件和原始输出。
