# 2026-05-18 持续优化第 7 轮

## 当前状态判断

第 6 轮补了 release 构建脚本，但继续验证后发现 `dist/AndroidVocabulary-release-v0.1.0-1.apk` 是未签名产物，`apksigner verify` 报 `DOES NOT VERIFY`。这意味着它不能作为真实安装或发布包。

## 对标项目可借鉴点

- Android 官方要求 APK 在安装或更新前必须数字签名。
- 发布签名信息不应写死在 `build.gradle` 中，应放到安全的外部配置或 CI secret 中。
- 发布脚本应默认阻止未签名产物流入分发目录，只允许显式的编译链路验证模式生成未签名包。

参考：

- https://developer.android.com/studio/publish/app-signing

## 差距清单

### P0

- release APK 未签名但脚本仍标记成功。影响安装、更新和对外分发；根因是 release 脚本只检查构建成功，不检查 APK 签名；建议接入环境变量签名配置并用 `apksigner verify` 验签；收益是发布链路不会误产出不可安装包；风险低。

### P1

- Gradle 缺少 release signing config。影响正式发布；根因是 `app/build.gradle.kts` 只配置了 debug 构建产物复制；建议用环境变量驱动 release 签名；收益是 CI 和本地都能安全签名；风险低。

### P2

- 缺少“无 keystore 时只做编译验证”的显式模式。影响开发便利；建议脚本增加 `-AllowUnsigned`，并明确警告不可安装；收益是安全和便利兼顾；风险低。

## 本轮要做的优化项

1. `app/build.gradle.kts` 增加环境变量驱动的 release signing config。
2. `scripts/release/build-release.ps1` 默认要求签名环境变量，并在构建后执行 `apksigner verify`。
3. 脚本增加 `-AllowUnsigned`，只用于非安装构建验证。
4. 更新 README 和发布文档，说明签名环境变量、keystore 生成和未签名模式。

## 具体修改方案

- `app/build.gradle.kts`
  - 新增 `ANDROID_VOCAB_RELEASE_STORE_FILE`
  - 新增 `ANDROID_VOCAB_RELEASE_STORE_PASSWORD`
  - 新增 `ANDROID_VOCAB_RELEASE_KEY_ALIAS`
  - 新增 `ANDROID_VOCAB_RELEASE_KEY_PASSWORD`
  - 任何变量部分缺失时直接失败，避免半配置。
- `scripts/release/build-release.ps1`
  - 默认缺少签名变量即失败。
  - 自动定位 Android SDK 下的 `apksigner.bat`。
  - 构建后复制 APK 到 `dist/` 并验签。
  - `-AllowUnsigned` 模式允许未签名包，但打印警告。
- `docs/release.md`
  - 增加环境变量、`keytool` 示例和不可提交 keystore 的说明。
- `README.md`
  - 说明 release 脚本默认需要签名，`-AllowUnsigned` 只验证编译链路。
