# 2026-05-25 持续优化第 121 轮

## 当前审查范围

本轮审查单独运行 `smoke-release-apk.ps1` 时的可追溯性。第 120 轮已经为显式 `-ApkPath` 增加 warning，但如果不通过 `verify-device.ps1` 包装执行，运行结果仍主要依赖终端输出。

## 发现

APK smoke 已经会生成失败 UI dump：

```text
build\apk-smoke\last-window.xml
```

但没有固定 metadata 文件记录本次运行状态、设备、APK 路径来源、是否显式覆盖当前版本名，以及失败原因。单独运行脚本后，发布验收复盘缺少结构化依据。

## 方案

- 方案 A：为 APK smoke 新增 `-LogDir` 参数并生成完整日志目录。更完整，但会扩大调用契约，也要同步 AAB smoke 调用。
- 方案 B：在既有 `build\apk-smoke` 目录写轻量 metadata 文件，不新增参数，不改变安装和启动流程。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 新增 `Get-ApkSmokeArtifactDir`。
- 新增 `Get-ApkSmokeRunMetadataPath`。
- 新增 `Save-ApkSmokeRunMetadata`。
- 普通 smoke 运行写入：

```text
build\apk-smoke\smoke-release-apk-run.txt
```

- metadata 覆盖 started / completed / failed 三种状态，并记录：

```text
versionName
versionCode
deviceSerial
apkPath
apkPathSource
apkPathExpectedName
apkPathMatchesCurrentVersionedName
skipInstall
resetAppData
grantNotificationPermission
lastWindowDump
failureMessage
```
