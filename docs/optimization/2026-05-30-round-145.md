# 第 145 轮：Wordbook pending query 筛选搜索修正

## 审查证据

- `WordbookViewModel` 的搜索请求由 `settingsFlow`、`query.debounce(300)` 和 `statusFilter` 组合生成。
- 旧实现把 debounced query 直接作为搜索 query；如果用户输入新 query 后未满 300ms 就切换状态筛选，筛选变化会立即触发搜索，但使用的是旧 query。
- 这会导致 UI 上 query 已更新，而一次即时搜索仍按旧 query 执行；debounce 追上后还可能重复发同一请求。

## 方案

- 方案 A：只补测试记录现状。能暴露风险，但不解决 UI query 和搜索请求短暂不一致的问题。
- 方案 B：保留 query debounce 作为“输入触发搜索”的节流信号，但构造请求时读取最新 raw query，并对 `SearchRequest` 做 `distinctUntilChanged()`。范围小，能修正筛选即时搜索并避免重复请求。

采用方案 B。

## 修改

- `feature/wordbook/src/main/java/com/zzz/androidvocab/feature/wordbook/WordbookViewModel.kt`
  - 搜索请求构造改为在筛选或词书变化触发时读取最新 `query.value`。
  - 增加 `distinctUntilChanged()`，避免 pending query 被即时筛选搜索消费后，debounce 到期再次发同一请求。
- `feature/wordbook/src/test/java/com/zzz/androidvocab/feature/wordbook/WordbookViewModelTest.kt`
  - 新增 `statusFilterChangeUsesPendingLatestQueryImmediately`。
  - 断言切换筛选会立即用最新 query 搜索，且 debounce 到期不会重复同一请求。
