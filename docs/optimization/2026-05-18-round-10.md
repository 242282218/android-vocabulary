# 2026-05-18 持续优化第 10 轮

## 当前状态判断

第 8、9 轮补强了发布和设备验证链路。继续检查日常可用性，提醒功能还有一个容易误导用户的边界：用户可能在系统设置里关闭通知权限，但 App 设置页仍只显示“提醒已开启”和提醒时间。Worker 会因为权限缺失静默不发通知，用户难以理解。

## 对标项目可借鉴点

- Android 13+ 通知是运行时权限，提醒类功能需要把系统权限状态纳入 UI 反馈。
- 成熟提醒/学习 App 通常会区分“用户设置开启”和“系统权限允许”，避免开关状态与真实效果不一致。
- 平台权限检查应留在 UI/app 边界，业务层继续只保存用户设置。

参考：

- https://developer.android.com/develop/ui/views/notifications/notification-permission
- https://developer.android.com/topic/architecture

## 差距清单

### P0

- 暂无新 P0。

### P1

- 系统通知权限被外部关闭时，设置页没有明确状态反馈。影响提醒功能可信度；根因是设置页只展示 DataStore 中的 reminderEnabled，不展示运行时权限状态；建议 SettingsRoute 在前台恢复时刷新权限，并在提醒开启但权限缺失时显示警告；收益是用户能理解为什么提醒不会出现；风险低。

### P2

- 权限状态 UI smoke 未覆盖。影响回归发现能力；建议已有布局 smoke 添加无权限文案断言；收益是后续改设置页时不容易误删提示；风险低。

### P3

- 还没有一键跳转系统通知设置。增强价值有，但不是当前最小闭环必须项。

## 本轮要做的优化项

1. 设置页维护 `hasNotificationPermission` UI 状态。
2. App 回到前台时刷新系统通知权限。
3. 用户开启提醒时使用最新权限状态决定是否请求权限。
4. 提醒开启但权限缺失时显示明确警告。
5. 更新布局 smoke，覆盖提示文案。

## 具体修改方案

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 使用 `LifecycleEventEffect(Lifecycle.Event.ON_RESUME)` 刷新通知权限状态。
  - `SettingsScreen` 增加 `hasNotificationPermission` 参数。
  - 提醒卡片在 `reminderEnabled && !hasNotificationPermission` 时显示“系统通知权限未开启，每日提醒不会显示。”
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - Settings smoke 使用 `hasNotificationPermission = false`。
  - 增加权限警告文案断言。

## 本轮风险

- 本轮只显示权限状态，不自动关闭 reminderEnabled，避免用户系统权限变更导致 App 设置被隐式改写。
- 如果后续要做“打开系统设置”按钮，需要补 Intent 跳转和设备差异测试。
