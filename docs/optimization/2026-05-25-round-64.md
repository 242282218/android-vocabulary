# 2026-05-25 持续优化第 64 轮

## 当前审查范围

本轮审查发布前操作路径是否足够线性可执行，重点是正式签名、版本号递增、APK smoke、AAB smoke、设备验收和 GitHub Actions managed device 的关系。

## 发现

`docs/release.md` 已分别说明 release APK、AAB、签名、APK smoke、AAB smoke 和设备验收脚本，但缺少一个从准备发布到保留验证记录的线性 checklist。

风险是发布执行者可能只运行其中一部分脚本，或者把 `-AllowUnsigned` / `-AllowDebugSigning` 的本地验证结果误判为可发布结果。

## 完成项

`docs/release.md`

- 新增 `发布前 Checklist`。
- 明确正式发布顺序：
  1. 检查 `androidVocab.versionCode` / `androidVocab.versionName`。
  2. 确认 release keystore 已备份并设置签名环境变量。
  3. 运行 `verify-local.ps1`。
  4. 确认 GitHub Actions，特别是 `pixel2Api30DebugAndroidTest`。
  5. 构建并验签 release APK。
  6. 跑 APK smoke。
  7. 构建并验签 release AAB。
  8. 通过 `verify-device.ps1 -SkipBundleBuild -BundlePath ...` 跑设备验收，覆盖 `connectedDebugAndroidTest`、AAB bundletool 安装级 smoke 和日志归档。
  9. 保留 dist 产物、CI 结果和设备验收日志。
- 明确 `-AllowUnsigned` 和 `-AllowDebugSigning` 只代表本地链路验证；出现 `not release-ready` 或 `not uploadable` 不得分发。

`README.md`

- 在 Release 构建段补充指向 `docs/release.md#发布前-checklist`。
- 明确 `-AllowUnsigned` 和 `-AllowDebugSigning` 不代表可发布。
