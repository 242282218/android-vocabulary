# 2026-05-25 持续优化第 147 轮

## 当前审查范围

本轮接着第 146 轮，审查设备验收父日志和 bundle smoke 子日志是否能互相证明同一个 AAB。第 146 轮已经让父级 `verification-completed.txt` 写入 `bundleSha256`，但 readiness 仍只读取父级字段，没有校验归档的 `smoke-release-bundle-run.txt` 中 bundletool 实际消费的 AAB hash。

## 发现

`verify-device.ps1` 会把 `build/bundle-smoke/smoke-release-bundle-run.txt` 复制到设备验收日志目录，但父级 metadata 只记录 `bundleSmokeRunMetadata=smoke-release-bundle-run.txt`。如果父级路径解析和子流程实际消费的 AAB 出现偏差，`verify-release-readiness.ps1` 无法发现。

## 方案

- 方案 A：让 readiness 直接读取设备验收目录里的 `smoke-release-bundle-run.txt`。校验直接，但 readiness 需要依赖设备日志目录结构。
- 方案 B：`verify-device.ps1` 在父级 metadata 中摘要归档子日志的关键字段，readiness 只读取父级 metadata 并做交叉校验。

本轮采用方案 B。它让最终门禁输入保持集中，同时保留子日志原文作为审计证据。

## 完成项

`scripts/test/verify-device.ps1`

- 新增父级读取归档 `smoke-release-bundle-run.txt` 的 key-value helper。
- `verification-run.txt` / `verification-completed.txt` / `verification-failed.txt` 增加：
  - `bundleSmokeRunStatus`
  - `bundleSmokeBundleSha256`
  - `bundleSmokeBundlePathMatchesCurrentVersionedName`
  - `bundleSmokeReleaseReady`
- `-SkipBundleSmoke` 时这些字段写入 `<not used>`。

`scripts/test/verify-release-readiness.ps1`

  - `bundleSmokeBundlePathMatchesCurrentVersionedName=True`
  - `bundleSmokeReleaseReady=True`
  - `bundleSmokeBundleSha256` 是 64 位小写 SHA-256
  - `bundleSmokeBundleSha256` 同时等于父级 `bundleSha256` 和 release artifact `releaseBundleSha256`
- readiness metadata 增加 `deviceBundleSmokeSha256`。

`scripts/test/verify-release-scripts.ps1`

## 剩余风险

- 当前没有在线 Android 设备，未验证新版 `verify-device.ps1` 正向成功 metadata。
- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- `verify-release-readiness.ps1` 仍隐式选择最新 `verification-completed.txt`，不能由发布人显式指定设备验收证据文件。
