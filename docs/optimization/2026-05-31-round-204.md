# 第 204 轮：为发布文档补充 release readiness 证据速查

## 审查证据

- `docs/release.md`
  - 已详细描述 APK/AAB 构建、smoke、device verification、readiness checklist。
  - 问题是这些信息分散在多个章节和 checklist 步骤里，缺少一段把“四类 evidence -> 最终 readiness”串起来的导航。
- `scripts/test/verify-release-readiness.ps1`
  - 当前已经稳定支持：
    - `blockerSummary`
    - `blockerActionSummary`
    - evidence 归档到 `build/release-readiness/evidence-*.txt`
  - 文档还没有明确告诉用户“准备哪四类证据、分别落在哪个文件、最终先看哪两个字段”。
- `.github/workflows/android.yml`
  - 已经会上传 `github-actions-release-evidence` artifact。
- `scripts/test/write-github-actions-evidence.ps1`
  - 默认输出是 `build/release-readiness/github-actions-evidence.txt`。

## 方案

- 方案 A：在 `docs/release.md` 增加一段短的 evidence 速查
  - 优点：外科手术式修改，直接提升可操作性，不改任何脚本
  - 缺点：只改善文档，不改变脚本行为
- 方案 B：另建独立发布流程文档
  - 优点：结构更自由
  - 缺点：会和现有 `docs/release.md` 重复，维护成本更高

采用方案 A。

## 修改

- 修改 `docs/release.md`
  - 新增 `## Release Readiness 证据速查`
  - 明确最终门禁是：

```powershell
.\scripts\test\verify-release-readiness.ps1
```

  - 将 readiness 依赖的 4 类 evidence 串起来：
    1. `release artifacts`
    2. `APK smoke`
    3. `device verification`
    4. `GitHub Actions evidence`
  - 为每类证据补充：
    - 生成命令
    - 关键文件路径
    - 在 readiness 中的用途
  - 明确最终显式传参示例
  - 明确失败时优先看：
    - `blockerSummary`
    - `blockerActionSummary`

## 验证

本轮只改文档，做最小内容验证：

1. 搜索新增章节与关键字段：

```powershell
rg -n "Release Readiness 证据速查|blockerSummary|blockerActionSummary|github-actions-release-evidence|verification-completed.txt|smoke-release-apk-run.txt|release-artifacts-run.txt" docs/release.md
```

结果：命中正常。

关键命中包括：

- `## Release Readiness 证据速查`
- `build/release-artifacts/release-artifacts-run.txt`
- `build/apk-smoke/smoke-release-apk-run.txt`
- `build/device-verification/v<versionName>-<versionCode>-<timestamp>/verification-completed.txt`
- `github-actions-release-evidence`
- `blockerSummary`
- `blockerActionSummary`

结论：新增导航段已和当前脚本字段、artifact 名称、默认输出路径对齐。
