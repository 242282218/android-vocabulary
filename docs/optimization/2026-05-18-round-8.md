# 2026-05-18 持续优化第 8 轮

## 当前状态判断

第 7 轮已经让 release APK 默认必须签名并通过 `apksigner verify`。继续检查部署可行性后，剩余的主要缺口是：签名产物生成后，缺少一条可重复的真机/模拟器 smoke 路径来确认它能安装、启动、渲染首屏且没有启动崩溃。

## 对标项目可借鉴点

- AnkiDroid 这类成熟离线学习 App 不只验证单元逻辑，还保留设备侧测试入口，避免数据库、资源、Manifest、权限或签名问题只在安装时暴露。
- Android 官方发布链路要求签名后再安装验证，设备侧验证应覆盖 `adb install`、启动、权限和日志。
- Now in Android 这类官方样例强调清晰的工程入口和可重复验证脚本，降低交接成本。

参考：

- https://github.com/ankidroid/Anki-Android
- https://github.com/android/nowinandroid
- https://developer.android.com/tools/adb

## 差距清单

### P0

- 暂无新 P0。发布签名已被脚本阻断，词库 publish-safe 校验也已接入。

### P1

- release APK 缺少设备 smoke 自动化入口。影响真实可安装性和启动稳定性验证；根因是 release 脚本停在构建和签名校验，没有继续覆盖设备安装与启动；建议新增 `scripts/test/smoke-release-apk.ps1`；收益是内部验收前能快速发现安装失败、首屏崩溃、权限和资源问题；风险低。

### P2

- 发布文档只有手工冒烟清单，没有脚本化命令。影响交接和重复验证；建议 README 和 release 文档补 smoke 命令、参数和数据清理风险；收益是执行路径更明确；风险低。

### P3

- GitHub Actions 尚未跑设备测试。CI 模拟器成本较高且可能受虚拟化环境限制，后续可在测试机或稳定设备池中补。

## 本轮要做的优化项

1. 新增 `scripts/test/smoke-release-apk.ps1`。
2. 脚本默认查找 `dist/` 或 release 输出目录中的 APK，并先做签名校验。
3. 脚本支持多设备指定、安装、启动、首屏文本检查、启动崩溃日志检查。
4. 文档补 smoke 命令和 `-ResetAppData` 风险说明。

## 具体修改方案

- `scripts/test/smoke-release-apk.ps1`
  - 自动定位 Android SDK、`adb`、`apksigner`。
  - `-ListDevices` 查看可用设备。
  - `-DeviceSerial` 指定设备。
  - `-ApkPath` 指定 APK；不传时优先使用 `dist/` 最新 APK。
  - `-SkipInstall` 复用已安装 App。
  - `-GrantNotificationPermission` 在 Android 13+ 尝试授予通知权限。
  - `-ResetAppData` 显式清理本地数据，用于首次导入路径验证。
- `README.md`
  - 增加 smoke 脚本入口。
  - 发布阻断项增加“签名 release APK 未通过 smoke”。
- `docs/release.md`
  - 增加 smoke 脚本推荐命令、常用参数和数据清理风险。

## 验证方案

已执行：

- PowerShell 语法解析：通过。
- `scripts/test/smoke-release-apk.ps1 -ListDevices`：通过，当前无在线设备，脚本能正常列出空设备列表。
- `scripts/test/smoke-release-apk.ps1 -SkipInstall` 无设备场景：通过，能明确失败并提示连接设备。
- `scripts/test/verify-local.ps1`：通过，包含 publish-safe 词库校验、`ktlintCheck`、`detekt`、`testDebugUnitTest`、`assembleDebug`。

待有真机/模拟器时执行：

```powershell
.\scripts\release\build-release.ps1
.\scripts\test\smoke-release-apk.ps1 -GrantNotificationPermission
.\scripts\test\smoke-release-apk.ps1 -ResetAppData
```

验收标准：

- APK 签名校验通过。
- `adb install -r` 成功。
- App 启动后进程存在。
- UIAutomator 能看到 Today / Review / Wordbook / Stats / Settings 或导入失败提示之一。
- 启动后 `AndroidRuntime` 日志中没有该包名的 `FATAL EXCEPTION`。

## 本轮风险

- `-ResetAppData` 会清理目标设备上的 App 数据，因此默认不开启。
- UIAutomator 首屏文本检查依赖系统可访问性树；如果未来首屏文案大改，脚本需要同步更新匹配文本。
- 本轮没有在线设备，因此只完成脚本语法和设备枚举验证，真实安装 smoke 需在有设备时补跑。
