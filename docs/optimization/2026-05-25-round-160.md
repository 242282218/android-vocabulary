# 2026-05-25 持续优化第 160 轮

## 当前审查范围

本轮接着第 159 轮，审查 `release-readiness-run.txt` 的 metadata key 唯一性。上一轮给每条 requirement evidence 增加了 `archive` / `archiveSha256`，但发现 `githubActionsEvidence` 同时被用作路径 metadata 和 requirement 名。

## 发现

同一个 metadata 文件里同时出现：

- `githubActionsEvidence=<path>`
- `githubActionsEvidence=passed|...`

这会让简单的 key-value 读取器只保留最后一个值，也让人工复核时混淆“路径字段”和“requirement 结果”。

## 方案

- 方案 A：重命名 requirement。会影响历史记录中长期使用的 requirement 名。
- 方案 B：保留 requirement 名 `githubActionsEvidence`，把路径 metadata 改为 `githubActionsEvidenceMetadata`。

本轮采用方案 B。它不改变门禁语义，只消除重复 key。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 将路径字段从 `githubActionsEvidence` 改为 `githubActionsEvidenceMetadata`。
- requirement 名 `githubActionsEvidence` 保持不变。
