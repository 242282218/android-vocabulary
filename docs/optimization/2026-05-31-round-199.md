# 第 199 轮：增强 release artifact 审计证据，显式识别 stale current-version release 产物

## 审查证据

- `scripts/test/verify-release-artifacts.ps1`
  - 脚本能判断 release APK/AAB 是否验签通过，也能记录 build-validation 产物存在与否。
  - 但原实现只会报“签名失败”，无法明确指出：
    - 当前版本的 release 命名文件是否其实比 build-validation 更新链路更旧
    - 这类旧 release 证据是否正在遮挡当前 build-validation 判断
- `dist/`
  - 当前状态：
    - `AndroidVocabulary-build-validation-v0.1.0-1.aab`：2026-05-31
    - `AndroidVocabulary-build-validation-v0.1.0-1.apk`：2026-05-30
    - `AndroidVocabulary-release-v0.1.0-1.aab`：2026-05-25
    - `AndroidVocabulary-release-v0.1.0-1.apk`：2026-05-25
    - `app-release.aab`：历史遗留
- 直接运行：

```powershell
.\scripts\test\verify-release-artifacts.ps1
```

  - 失败符合预期：
    - release APK `DOES NOT VERIFY`
    - release AAB `jar is unsigned`
  - 但失败前的旧脚本没有把“current release files are stale relative to build-validation”明确写入 metadata。

结论：这轮不是修 release 产物本身，而是增强审计证据，让发布阻断项更可诊断。

## 方案

- 方案 A：保持现状，只保留“签名失败”
  - 优点：零改动
  - 缺点：碰到 `dist/` 混有旧 release 命名文件时，定位不够直接
- 方案 B：在审计 metadata 中补时间戳和 stale 判定，并在 remediation 中明确提示
  - 优点：能区分“签名失败”和“当前 release 命名产物比 build-validation 更旧”
  - 缺点：需要同步更新脚本回归测试

采用方案 B。

## 修改

- `scripts/test/verify-release-artifacts.ps1`
  - 新增：
    - `Get-ReleaseArtifactLastWriteTimeValue`
    - `Test-ReleaseArtifactOlderThan`
  - metadata 新增字段：
    - `releaseApkLastWriteTime`
    - `releaseApkOlderThanBuildValidation`
    - `releaseBundleLastWriteTime`
    - `releaseBundleOlderThanBuildValidation`
    - `buildValidationApkLastWriteTime`
    - `buildValidationBundleLastWriteTime`
    - `staleCurrentVersionArtifacts`
  - 新增 warning：
    - 当前版本 release 命名产物如果比 build-validation 更旧，会显式输出 stale warning
  - remediation 新增具体说明：
    - 当前版本 release 命名产物比匹配的 build-validation 产物更旧时，提示要么用签名 release 覆盖，要么移出 `dist/`
- `scripts/test/verify-release-scripts.ps1`
  - 增加回归约束，要求上述 metadata 字段、helper 和 remediation 文案必须存在

## 验证

1. 回归脚本自检：

```powershell
.\scripts\test\verify-release-scripts.ps1
```

结果：通过。

2. 回跑 release artifact 审计：

```powershell
.\scripts\test\verify-release-artifacts.ps1
```

结果：失败，且失败更精确，符合当前仓库状态。

新增关键输出：

- `Current-version release-named artifacts appear stale relative to build-validation outputs`
- `releaseApkOlderThanBuildValidation=True`
- `releaseBundleOlderThanBuildValidation=True`
- `staleCurrentVersionArtifacts=AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk`

生成的 metadata：

- `build/release-artifacts/release-artifacts-run.txt`

现在能直接证明：

1. 当前 release 命名 APK/AAB 确实未通过签名验证
2. 它们还都比当前 build-validation 产物更旧，是 stale current-version evidence

## 未验证项

- 这轮没有跑 `build-release.ps1 -AllowUnsigned` / `build-bundle.ps1 -AllowUnsigned`，因为当前目标是先增强审计证据，不是重新产生产物。
- 这轮没有跑完整 `verify-local.ps1`，因为改动只在 PowerShell 发布脚本，`verify-release-scripts.ps1` 已覆盖主要回归风险。

## 下一轮建议

- 继续发布链路，优先二选一：
  1. 运行 `build-release.ps1 -AllowUnsigned` 和 `build-bundle.ps1 -AllowUnsigned`，确认当前 build-validation 产物更新链路没有新问题
  2. 继续增强 `verify-release-readiness.ps1`，让它在读取 `release-artifacts-run.txt` 时也显式展示 stale current-version release artifact 线索

- 如果目标是清当前红灯，下一步最直接的是：
  - 生成新的签名 release APK/AAB 覆盖 `dist/AndroidVocabulary-release-v0.1.0-1.*`
  - 或先把旧 release 命名文件人工移出 `dist/`，避免本地 unsigned build-validation 路径被它们持续遮挡
