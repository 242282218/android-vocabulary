# 2026-05-25 持续优化第 135 轮

## 当前审查范围

本轮接着第 134 轮，审查 `scripts/release/build-release.ps1` 和 `scripts/release/build-bundle.ps1` 的 `-AllowUnsigned` 本地构建验证链路，重点是它是否会和正式 release 归档产物混淆。

## 发现

`-AllowUnsigned` 只用于没有正式 keystore 时验证编译链路，但脚本此前仍把 APK/AAB 复制到正式版本化文件名：

```text
dist/AndroidVocabulary-release-v0.1.0-1.apk
dist/AndroidVocabulary-release-v0.1.0-1.aab
```

这会造成两个风险：

- 本地未签名验证产物覆盖同名正式归档。
- 后续 smoke 或发布记录只看文件名时，容易把不可发布产物误当成正式 release 产物。

## 方案

- 方案 A：保留正式文件名，只加强 warning。改动小，但仍会污染正式归档路径。
- 方案 B：给本地验证产物使用独立命名，并把命名规则集中到共享脚本库。正式 release 名称只在无本地覆盖且验签通过时使用。

本轮采用方案 B。

## 完成项

`scripts/lib/android-env.ps1`

- 新增 `Get-AndroidVocabularyBuildValidationApkName()`。
- 新增 `Get-AndroidVocabularyBuildValidationBundleName()`。

`scripts/release/build-release.ps1`

- 先对 Gradle 原始 APK 输出执行 `apksigner verify`。
- 只有验签通过且未使用 `-AllowUnsigned` 时，才复制到 `AndroidVocabulary-release-v<versionName>-<versionCode>.apk`。
- `-AllowUnsigned` 路径复制到 `AndroidVocabulary-build-validation-v<versionName>-<versionCode>.apk`。
- 如果旧的 release 命名 APK 已存在，保留不动并输出 warning。

`scripts/release/build-bundle.ps1`

- 先对 Gradle 原始 `app-release.aab` 执行 `jarsigner -verify`。
- 只有验签通过且未使用 `-AllowUnsigned` 时，才复制到 `AndroidVocabulary-release-v<versionName>-<versionCode>.aab`。
- `-AllowUnsigned` 路径复制到 `AndroidVocabulary-build-validation-v<versionName>-<versionCode>.aab`。
- 如果旧的 release 命名 AAB 已存在，保留不动并输出 warning。

`scripts/test/verify-device.ps1`

- 当使用 `-AllowUnsignedBundle` 且脚本本轮负责构建 AAB 时，后续 bundle smoke 自动使用 `AndroidVocabulary-build-validation-v<versionName>-<versionCode>.aab`。
- 正式设备验收路径仍默认要求 `AndroidVocabulary-release-v<versionName>-<versionCode>.aab`。

`scripts/test/verify-release-scripts.ps1`

- 新增命名回归检查，防止发布脚本重新把 `-AllowUnsigned` 产物写回正式 release 文件名。

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有正式 release signing 环境，未验证 `[ok] release APK signature verified` 和 `[ok] release AAB signature verified` 的正式成功路径。
- 当前没有在线 Android 设备，未验证真实安装、启动、`connectedDebugAndroidTest` 或 AAB install smoke 成功路径。
- `dist/` 中历史 release 命名文件来源于此前本地验证链路，不能作为可发布产物使用。
