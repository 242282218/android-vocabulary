# 2026-05-25 持续优化第 144 轮

## 当前审查范围

本轮接着第 143 轮，审查 release-ready 证据链是否能复核 `dist/` 中正式 release APK/AAB 的文件指纹。此前 `verify-release-artifacts.ps1` 只记录路径、签名状态和验签输出，没有记录 SHA-256；即使审计后产物被替换，readiness 也只能靠路径和签名状态判断。

## 发现

`build/release-artifacts/release-artifacts-run.txt` 缺少正式 APK/AAB 的 SHA-256。发布记录可以说明“当前版本 release 命名产物曾经验签”，但不能提供可复核指纹，也不能防止审计后文件被同名替换。

## 方案

- 方案 A：文档要求人工执行 `Get-FileHash` 并保存结果。改动少，但容易漏记。
- 方案 B：`verify-release-artifacts.ps1` 自动写入 SHA-256，`verify-release-readiness.ps1` 重新计算当前 `dist/` 产物 SHA-256 并与审计 metadata 比对。

本轮采用方案 B。它不改变签名和设备验收流程，只增强本地证据链。

## 完成项

`scripts/test/verify-release-artifacts.ps1`

- 新增 `Get-ReleaseArtifactSha256`。
- metadata 增加：
  - `releaseApkSha256`
  - `releaseBundleSha256`
- 即使当前历史 release 命名产物验签失败，也会记录其 SHA-256，便于定位具体文件。

`scripts/test/verify-release-readiness.ps1`

- 新增 `Test-Sha256String` 和 `Get-Sha256OrDefault`。
- 根据当前版本重新定位：
  - `dist/AndroidVocabulary-release-v<versionName>-<versionCode>.apk`
  - `dist/AndroidVocabulary-release-v<versionName>-<versionCode>.aab`
- 重算当前 APK/AAB SHA-256，并要求与 `release-artifacts-run.txt` 中的 SHA-256 完全一致。
- readiness metadata 增加：
  - `releaseApkSha256Metadata`
  - `releaseApkSha256Current`
  - `releaseBundleSha256Metadata`
  - `releaseBundleSha256Current`

`scripts/test/verify-release-scripts.ps1`

- 增加 release artifacts SHA-256 字段回归断言。
- 增加 readiness SHA-256 重算和比对逻辑的源码结构回归断言。

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有正式 release signing 环境，未验证 release artifacts/readiness 正向成功路径。
- 当前没有在线 Android 设备，缺少正式 APK smoke 和 AAB 安装级验收成功证据。
- 当前 hash 比对覆盖正式 release APK/AAB；APK smoke metadata 仍只证明路径和安装过程，尚未绑定 APK SHA-256。

## 下一轮建议

继续审查 `smoke-release-apk.ps1` metadata 是否应记录被安装 APK 的 SHA-256，并让 readiness 要求 APK smoke 使用的文件 hash 与 release artifact hash 一致。
