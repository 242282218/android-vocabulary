# 2026-05-25 持续优化第 83 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 的 `Invoke-LoggedStep` 是否能在子命令失败时保留根因。

## 发现

`Invoke-LoggedStep` 原逻辑在 `catch` 中执行：

```powershell
Write-Error "$Name failed. See $logPath"
throw
```

由于脚本顶部设置了 `$ErrorActionPreference = 'Stop'`，`Write-Error` 本身会抛出新的 terminating error，导致后面的裸 `throw` 不一定能重新抛出原始异常。

本地最小复现实验显示：

- native 命令 `exit 7` 会被包装成通用失败。
- PowerShell 子脚本 `throw 'child-boom'` 时，外层只得到 `child-script failed. See ...`，原始 `child-boom` 丢失。
- PowerShell 子脚本 `exit 9` 时，外层也只得到 `ps-exit failed. See ...`，原始 exit code 丢失。

这会降低设备验收失败时的定位效率。

## 方案

- 方案 A：在 `catch` 中直接 `throw "$Name failed. See ... Cause: ..."`，保留原始异常消息。改动小，行为明确。
- 方案 B：保留 `Write-Error`，但加 `-ErrorAction Continue` 再裸 `throw`。能保留原异常，但日志路径和 cause 不在同一条错误消息里。

本轮采用方案 A。

## 完成项

`scripts/test/verify-device.ps1`

- native 非 0 退出先抛出 `"$Name failed with exit code $LASTEXITCODE"`。
- `catch` 统一重新抛出：

```text
<step> failed. See <logPath>. Cause: <original error>
```

这样既保留固定日志路径，也保留原始失败原因。

## 验证结果

PowerShell 解析检查：

```powershell
$tokens=$null; $errors=$null; [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path 'scripts/test/verify-device.ps1'), [ref]$tokens, [ref]$errors) | Out-Null; if ($errors.Count -gt 0) { $errors | ForEach-Object { $_.Message }; exit 1 }; 'parse-ok'
```

结果：通过。

最小复现实验：

```powershell
$ErrorActionPreference='Stop'; $dir=Join-Path $env:TEMP 'android-vocab-step-test5'; New-Item -ItemType Directory -Force -Path $dir | Out-Null; function Invoke-TestStep { param([string]$Name,[scriptblock]$Command) $logPath=Join-Path $dir "$Name.log"; try { & $Command *>&1 | Tee-Object -FilePath $logPath; if ($LASTEXITCODE -ne 0) { throw "$Name failed with exit code $LASTEXITCODE" } } catch { throw "$Name failed. See $logPath. Cause: $($_.Exception.Message)" } }; try { Invoke-TestStep 'ps-throw' { Write-Host 'before-throw'; throw 'scriptblock-boom' } } catch { "outer=$($_.Exception.Message)"; "log=" + (Get-Content -Raw (Join-Path $dir 'ps-throw.log') -ErrorAction SilentlyContinue) }; try { Invoke-TestStep 'native-exit' { & cmd /c 'echo native-output && exit 7' } } catch { "outer=$($_.Exception.Message)"; "log=" + (Get-Content -Raw (Join-Path $dir 'native-exit.log') -ErrorAction SilentlyContinue) }
```

结果：PowerShell throw 和 native 非 0 退出都会保留日志路径和原始 cause。
