# 第 196 轮：修正 Room 历史 migration view SQL 漂移，恢复 core:database instrumentation 与 device 验收

## 审查证据

- `build/device-verification/v0.1.0-1-20260531-063833/connectedDebugAndroidTest.log`
  - 阻断测试集中在 `core/database/src/androidTest/java/com/zzz/androidvocab/core/database/VocabDatabaseMigrationTest.kt`
  - 失败项是：
    - `migratesVersionFourToFive`
    - `migratesVersionFiveToSix`
    - `migratesVersionSixToSeven`
    - `migratesVersionSevenToEight`
    - `migratesVersionOneToNine`
- `core/database/src/main/java/com/zzz/androidvocab/core/database/DatabaseViews.kt`
  - 当前运行时 `first_reviews` 已升级为 `firstLogId + firstReviewedAt`
  - 当前运行时 `review_daily_stats` 已改为基于 `firstLogId = l.id` 统计 `newCount`
- `core/database/schemas/com.zzz.androidvocab.core.database.VocabDatabase/6.json`
  - `first_reviews` 仍要求旧版 SQL：
    - `SELECT cardId, MIN(reviewedAt) AS firstReviewedAt FROM valid_review_logs GROUP BY cardId`
- `core/database/schemas/com.zzz.androidvocab.core.database.VocabDatabase/7.json`
  - `review_daily_stats` 仍要求旧版 SQL，且不包含输出列 `durationMs`
- `core/database/schemas/com.zzz.androidvocab.core.database.VocabDatabase/8.json`
  - `review_daily_stats` 仍要求旧版 `firstReviewedAt = l.reviewedAt`，但新增了输出列 `durationMs`
- `core/database/src/main/java/com/zzz/androidvocab/core/database/Migrations.kt`
  - 历史 migration 之前直接用多行 SQL 和当前运行时 view 常量，和 `6/7/8/9` 导出 schema 不完全一致

结论：不是 emulator/adb 问题，也不是 Room 运行时 view 本身坏了，而是历史 migration 创建出来的 view SQL 与对应版本导出 schema 发生漂移，导致 migration instrumentation 在 schema 校验阶段失败。

## 方案

- 方案 A：按版本维护历史 canonical view SQL，只修 `Migrations.kt`
  - 优点：最小修改，保留 v9 运行时 view 定义不变，直接对齐导出 schema
  - 缺点：需要在 migration 中维护少量历史 SQL 常量
- 方案 B：重导 `6/7/8` schema，或改 migration test 去适配当前运行时 view
  - 优点：代码表面更少
  - 缺点：会篡改历史 schema 语义，风险高，也不符合 migration 测试的目标

采用方案 A。

## 修改

- `core/database/src/main/java/com/zzz/androidvocab/core/database/Migrations.kt`
  - 新增历史版本专用 canonical SQL 常量：
    - `VALID_REVIEW_LOGS_VIEW_SQL`
    - `WORD_CARD_VIEW_SQL`
    - `FIRST_REVIEWS_VIEW_SQL_V6_TO_V8`
    - `REVIEW_DAILY_STATS_VIEW_SQL_V7`
    - `REVIEW_DAILY_STATS_VIEW_SQL_V8`
  - `MIGRATION_4_5`
    - 改为用单行 canonical SQL 创建 `valid_review_logs` 与 `word_card_view`
  - `MIGRATION_5_6`
    - 改为精确创建旧版 `first_reviews`
  - `MIGRATION_6_7`
    - 改为精确创建 v7 版 `review_daily_stats`
  - `MIGRATION_7_8`
    - 保留 drop/recreate，但创建 SQL 改为精确的 v8 版
  - `MIGRATION_8_9`
    - 继续切换到当前 v9 运行时 `first_reviews` / `review_daily_stats`

这次没有改生产 DAO/Repository 逻辑，也没有动 schema JSON；只修历史 migration 生成 view 的 SQL 文本。

## 后续建议

- 如果后面继续修改 `DatabaseViews.kt` 的运行时 SQL，必须同步检查：
  - `Migrations.kt` 中历史版本是否仍需保留旧定义
  - `VocabDatabaseMigrationTest.kt` 是否覆盖了跨版本差异
