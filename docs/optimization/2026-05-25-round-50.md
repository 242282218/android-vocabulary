# 2026-05-25 持续优化第 50 轮

## 当前审查范围

本轮继续审查设备验收脚本的失败诊断和设备选择边界，重点是测试机失败后是否留下足够日志，以及显式传入 `-DeviceSerial` 时是否可能误报通过。

## 发现

`scripts/test/verify-device.ps1` 只在所有步骤成功后才保存 `logcat-tail.txt`。如果 `connectedDebugAndroidTest`、release bundle build 或 AAB smoke 中途失败，脚本会直接抛错退出，失败现场缺少 logcat 尾部。

另外，`verify-device.ps1`、`smoke-release-apk.ps1`、`smoke-release-bundle.ps1` 都会直接信任显式传入的 `-DeviceSerial`。实测旧逻辑下：

```powershell
.\scripts\test\verify-device.ps1 -DeviceSerial __NO_SUCH_DEVICE__ -SkipConnectedTests -SkipBundleSmoke
```

会打印 `[ok] device verification passed`。这是验收脚本的假阳性风险。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Save-LogcatTail()`。
- 将主验收流程包进 `try/finally`，在已解析设备并创建日志目录后，无论中间步骤成败都会尽量保存 `logcat-tail.txt`。
- `Resolve-DeviceSerial()` 不再直接信任显式 serial，必须出现在 `adb devices` 的在线设备列表中。

`scripts/test/smoke-release-apk.ps1`

- `Resolve-DeviceSerial()` 同步校验显式 serial 是否在线。

`scripts/test/smoke-release-bundle.ps1`

- `Resolve-DeviceSerial()` 同步校验显式 serial 是否在线。
- 保持第 49 轮的同一设备贯穿 AAB build-apks、install-apks 和首屏 smoke。

## 剩余风险

- 当前机器没有在线设备，无法实际验证 `try/finally` 在真实 Gradle / bundletool 失败时保存的 logcat 内容。
- 本轮没有执行 `connectedDebugAndroidTest`、真实 AAB 安装、启动首屏 smoke。
- `-AllowDebugSigning` 只验证本地拆包链路，不能代表正式签名发布验收。
