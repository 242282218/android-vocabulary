# 2026-05-18 持续优化第 12 轮

## 当前状态判断

第 11 轮已经把 release APK/AAB 构建、签名检查和通知权限闭环补强。继续看发布可行性，当前最大缺口是 AAB 只做到了 `bundleRelease` 和 `jarsigner` 验签，尚未验证“应用商店拆包后设备能安装并启动”。这会留下一个真实发布风险：AAB 本身有效，不代表生成的设备 APK Set 一定能在目标设备上安装、启动和渲染首屏。

## 对标项目可借鉴点

- Android 官方建议使用 bundletool 在本地从 AAB 生成 APK Set，并可针对连接设备安装验证，模拟 Google Play 的分发路径。
- 成熟 Android 项目通常把“构建成功”和“可安装启动”拆成两个质量门；前者适合 CI，后者适合真机/模拟器 smoke。
- 本项目已有 `smoke-release-apk.ps1` 负责签名 APK 的安装、启动、首屏文本和崩溃检查，因此 AAB smoke 应复用这条检查链路，而不是重写 UI 检查。

参考：

- https://developer.android.com/guide/app-bundle/test
- https://developer.android.com/tools/bundletool
- https://github.com/google/bundletool

## 差距清单（按 P0/P1/P2/P3）

### P0

- 暂无新增 P0。本地总验证仍通过。

### P1

- AAB 缺少安装级 smoke。影响发布可信度；根因是现有脚本只构建和验签 AAB，没有把它转成 APK Set 并安装；建议新增 `smoke-release-bundle.ps1`，用 bundletool `build-apks` / `install-apks` 后复用 APK smoke；收益是更接近 Google Play 实际分发路径；风险中低，依赖 bundletool 和在线设备。

### P2

- bundletool 获取方式未标准化。影响新机器复现；根因是项目没有固定工具安装脚本；建议新增 `scripts/tooling/install-bundletool.ps1` 下载固定版本并设置稳定 alias；收益是文档和脚本可重复；风险低，下载依赖 GitHub 网络。
- bundletool 签名参数需要避免密码明文散落。影响安全和可维护性；建议使用临时密码文件，并在脚本结束后清理；收益是命令行更干净；风险是文件编码不当会导致 bundletool 读取失败，已通过显式 ASCII 编码修复。

### P3

- 还没有把 AAB smoke 接入 CI 或测试机自动执行。因为需要设备，建议后续放测试机或手动 release checklist。

## 本轮要做的优化项

1. 新增 bundletool 安装脚本，固定工具版本。
2. 新增 AAB smoke 脚本，支持 build-only 和设备安装两种模式。
3. AAB smoke 默认要求 release signing 环境变量；需要本地调试时显式使用 `-AllowDebugSigning`。
4. 复用现有 APK smoke 的启动、首屏和崩溃检查。
5. 更新 README 与 release 文档。

## 具体修改方案

- `scripts/lib/android-env.ps1`
  - 新增 `Get-BundleToolJar`，按显式参数、`BUNDLETOOL_JAR`、`.tools/bundletool/bundletool.jar` 和版本 jar 的顺序查找 bundletool。
- `scripts/tooling/install-bundletool.ps1`
  - 默认下载 `bundletool-all-1.18.3.jar` 到 `.tools/bundletool/`。
  - 复制稳定入口 `.tools/bundletool/bundletool.jar`。
- `scripts/test/smoke-release-bundle.ps1`
  - 自动选择最新 AAB，或用 `-BundlePath` 指定。
  - `-BuildOnly` 使用 `bundletool build-apks --mode=universal`，适合无设备环境验证 AAB 转换链路。
  - 默认模式使用 `bundletool build-apks --connected-device` 和 `bundletool install-apks`。
  - 安装后调用 `scripts/test/smoke-release-apk.ps1 -SkipInstall`，复用首屏与崩溃检查。
  - release signing 环境变量完整时传入 `--ks`、`--ks-key-alias`、`--ks-pass=file:`、`--key-pass=file:`。
  - 临时密码文件使用 ASCII 编码，脚本结束后清理。
- `docs/release.md`
  - 新增 AAB 安装级验证章节和发布阻断项。
- `README.md`
  - 增加 bundletool 安装和 AAB smoke 示例。

## 本轮风险

- `.tools/bundletool/` 是本地工具目录，新增 jar 用于开发机验证；正式 CI 仍应显式安装或缓存工具。
- `-AllowDebugSigning` 只适合本地 AAB 转换验证，不能代表应用商店发布签名。
- 设备安装级验证仍取决于在线设备；当前只完成 build-only 和签名参数验证。
