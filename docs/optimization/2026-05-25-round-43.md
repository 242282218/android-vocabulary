## 当前审查范围

本轮审查 Review 页四档反馈提交入口，重点确认快速重复点击不会写入重复日志或让 UI 状态异常。

## 发现

`ReviewViewModel.submit()` 已有同步 guard：

- `isSubmitting.value` 为 true 时直接返回。
- 读取当前卡片和计算答题耗时后，立即设置 `isSubmitting = true`。
- 成功后清理背面可见状态和答题开始时间。
- 失败时保留当前卡片并展示错误。
- `finally` 中复位 `isSubmitting = false`。

`ReviewRoute` 也会把 `isSubmitting` 传给四个反馈按钮，提交中禁用按钮。

现有测试已经覆盖快速连续点击：

- `submitIgnoresDuplicateClicksWhileFirstSubmitIsRunning()` 只记录第一次评分。
- `submitUsesElapsedTimeAfterAnswerIsShown()` 覆盖答题耗时。
- `backIsHiddenWhenCurrentCardChanges()` 覆盖队列切换后背面状态不会串卡。

数据库层也有重复日志保护：同一 `cardId + reviewedAt` 生成相同 log id，重复插入会被包装成用户可见的数据库写入失败，并保持卡片状态不被重复推进。
