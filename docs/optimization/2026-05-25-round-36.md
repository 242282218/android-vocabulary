# 2026-05-25 持续优化第 36 轮

## 当前审查范围

本轮继续审查导出 JSON 的救援价值。导出是本地离线 App 的数据保底路径，非核心诊断字段损坏时不应阻断用户导出复习记录。

## 发现

`AndroidExportRepository` 已经对 `vocabularyManifest` 做了容错：能解析为 JSON 就导出结构化对象，解析失败则保留原始字符串。但 `latestImportRun.bookCountsJson` 直接调用 `Json.parseToJsonElement()`，如果本地导入记录缓存异常，会导致整个导出失败。

这不符合导出的定位：`ReviewLog`、`ReviewCard`、设置和统计才是用户数据主体，词库导入诊断字段应尽量随包携带问题线索，而不是阻断导出。

## 完成项

1. `core/database/src/main/java/com/zzz/androidvocab/core/database/AndroidExportRepository.kt`
   - 将 JSON 容错转换提到文件级 `toJsonPayload()`。
   - `latestImportRun.bookCounts` 改为复用容错转换：合法 JSON 导出对象，非法 JSON 导出原始字符串。
2. `core/database/src/test/java/com/zzz/androidvocab/core/database/AndroidExportRepositoryTest.kt`
   - 新增 `exportUserDataKeepsMalformedImportRunBookCountsAsString()`。
   - 覆盖 `bookCountsJson` 损坏时导出仍成功，并保留原始内容。
