# 2026-05-25 持续优化第 84 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1` 调用 `smoke-release-apk.ps1` 后只检查 `$LASTEXITCODE` 是否会吞掉 PowerShell 子脚本抛出的异常信息。

## 发现

当前逻辑是：

```powershell
& (Join-Path $repoRoot 'scripts\test\smoke-release-apk.ps1') @smokeArgs
if ($LASTEXITCODE -ne 0) {
    throw "installed app launch smoke after bundle install failed with exit code $LASTEXITCODE"
}
```

这里需要区分两类失败：

- 子脚本内部 `throw`：PowerShell 会直接终止当前脚本，原始异常不会进入 `$LASTEXITCODE` 分支。
- 子脚本显式 `exit <non-zero>`：PowerShell 不会自动抛异常，后续 `$LASTEXITCODE` 分支负责转成失败。

本地最小复现实验确认当前逻辑没有吞掉 PowerShell `throw` 的原始异常。

## 方案

- 方案 A：不改脚本，只记录验证结论。现状能覆盖 `throw` 和非 0 `exit` 两类失败。
- 方案 B：额外加 try/catch 包装子脚本调用，把上下文强行加进异常。可读性略强，但会改变直接运行脚本时的错误形态，收益有限。

本轮采用方案 A，不改代码。

## 验证结果

最小复现实验：

```powershell
$ErrorActionPreference='Stop'; $dir=Join-Path $env:TEMP 'android-vocab-child-propagation'; New-Item -ItemType Directory -Force -Path $dir | Out-Null; $throwChild=Join-Path $dir 'throw-child.ps1'; Set-Content -LiteralPath $throwChild -Value "`$ErrorActionPreference='Stop'; Write-Host 'child-before'; throw 'child-boom'"; $exitChild=Join-Path $dir 'exit-child.ps1'; Set-Content -LiteralPath $exitChild -Value "Write-Host 'child-before-exit'; exit 9"; function Invoke-CurrentStyle { param([string]$Path) try { & $Path; if ($LASTEXITCODE -ne 0) { throw "after child failed with exit code $LASTEXITCODE" }; 'after-ok' } catch { "caught=$($_.Exception.Message)"; "lastExit=$LASTEXITCODE" } }; 'throw-child'; Invoke-CurrentStyle $throwChild; 'exit-child'; Invoke-CurrentStyle $exitChild
```

结果：

- `throw-child` 保留原始 `child-boom`。
- `exit-child` 被 `$LASTEXITCODE` 分支转成 `after child failed with exit code 9`。

引用检查：

```powershell
rg -n "smoke-release-apk|installed app launch smoke after bundle install failed|LASTEXITCODE|AAB smoke test passed" scripts/test/smoke-release-bundle.ps1 docs/optimization/2026-05-25-round-83.md
```

结果：当前 AAB smoke 子脚本调用和失败分支位置清晰。
