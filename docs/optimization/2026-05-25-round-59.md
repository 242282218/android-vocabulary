# 2026-05-25 持续优化第 59 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 在组合 `-AllowUnsignedBundle` / `-AllowDebugSigning` 时的顶层输出语义，重点是设备验收脚本是否会把本地验证路径误写成正式 release-ready。

## 发现

第 58 轮已经让底层脚本区分了：

- `build-validation APK, not release-ready`
- `build-validation AAB, not uploadable`
- `bundle smoke build-only passed with debug signing; not release-ready`

但 `verify-device.ps1` 作为顶层编排脚本，成功后仍统一打印：

```text
[ok] device verification passed
```

如果调用方式是：

```powershell
.\scripts\test\verify-device.ps1 -DeviceSerial <serial> -AllowUnsignedBundle -AllowDebugSigning
```

它实际只能证明本地调试签名路径的安装链路，不应被理解为正式发布验收通过。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `$usesLocalOnlyReleaseOverrides` 判断。
- 只有在执行 bundle smoke 且使用 `-AllowDebugSigning`，或执行 bundle build 且使用 `-AllowUnsignedBundle` 时，才标记为本地覆盖路径。
- 本地覆盖路径成功时，最终输出改为：

```text
[ok] device verification passed with local-only release overrides; not release-ready
```

- 正式签名路径或只跑 instrumentation tests 时，仍输出：

```text
[ok] device verification passed
```
