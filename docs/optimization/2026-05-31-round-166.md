# 第 166 轮：Settings 数据维护卡状态摘要与状态色收口

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `DataMaintenanceCard()` 之前固定使用红色边框。
  - 这意味着即使还没检查，或者检查结果完全正常，卡片也会呈现风险色。
  - 前一轮又新增了“上次检查结果 / 本次操作失败”的分层文案，因此现在更需要一个首屏可扫描的摘要状态。
- 项目视觉约束明确要求：红色只用于错误或风险，不应作为常态装饰。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 已有 `SettingsScreen` 的窄屏烟雾测试，可直接补状态摘要断言。

结论：当前数据维护卡的状态色和状态摘要都不够精确。未检查和正常态不应继续带红边，且用户需要在不读长文案的情况下先看到当前状态。

## 方案

- 方案 A：只把红边改成动态边框。
  - 优点：改动最小。
  - 缺点：虽然不再误用红色，但仍缺少首屏可扫描的状态摘要。
- 方案 B：同时补简短状态摘要，并让边框随状态动态切换。
  - 优点：既修正颜色语义，又建立清晰的第一眼状态。
  - 缺点：`SectionTitle` 会多一段 detail，但信息密度仍可控。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `SectionTitle("数据维护")` 改为带 detail 的标题，状态摘要来自 `DataMaintenanceUiState.statusSummary()`。
  - 新增状态摘要规则：
    - `处理中`
    - `结果已保留`
    - `处理失败`
    - `未检查`
    - `需要处理`
    - `状态正常`
  - 新增 `borderColor()`：只有存在错误或问题时才使用红色边框；未检查和正常态恢复为中性边框。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 默认设置页烟雾测试增加 `未检查` 断言。
  - “旧结果 + 新失败”场景烟雾测试增加 `结果已保留` 断言。
