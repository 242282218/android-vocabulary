# 2026-05-18 持续优化第 9 轮

## 当前状态判断

第 8 轮补齐了签名 APK 的设备 smoke 入口。继续看部署可行性，当前仍偏向“内部 APK 分发”，但如果后续上 Google Play 或应用商店，Android App Bundle 是更贴近正式分发的产物形态。项目已有 release signing config，可以低风险补齐 AAB 构建脚本。

## 对标项目可借鉴点

- Android 官方发布流程推荐使用 Android App Bundle 面向 Google Play 分发。
- 成熟 Android 项目会把 APK、AAB、签名校验、产物归档拆成可重复脚本，而不是依赖手工 Gradle 命令。
- 签名配置继续来自环境变量，不把 keystore 或密码写入 Gradle 文件。

参考：

- https://developer.android.com/guide/app-bundle
- https://developer.android.com/studio/publish/app-signing

## 差距清单

### P0

- 暂无新 P0。

### P1

- 缺少 AAB 构建和归档入口。影响应用商店分发准备；根因是 release 脚本只覆盖 APK；建议新增 `scripts/release/build-bundle.ps1`；收益是提前验证 bundle 构建、签名和归档；风险低。

### P2

- 发布文档没有区分内部 APK 与商店 AAB。影响交接和发布判断；建议补 AAB 章节和命令；收益是部署路径更完整；风险低。

### P3

- AAB 尚未用 bundletool 转成 APK Set 做安装级验证。后续可以在测试机补 `bundletool build-apks` 与安装验证。

## 本轮要做的优化项

1. 新增 `scripts/release/build-bundle.ps1`。
2. 默认要求 release signing 环境变量齐全。
3. 执行 publish-safe 词库校验、质量门禁、`bundleRelease`。
4. 将 AAB 复制到 `dist/`，并使用 `jarsigner -verify -certs` 校验签名。
5. 更新 README 和 release 文档。

## 具体修改方案

- `scripts/release/build-bundle.ps1`
  - 复用 JDK 17 自动查找逻辑。
  - 检查 `ANDROID_VOCAB_RELEASE_STORE_FILE`、`ANDROID_VOCAB_RELEASE_STORE_PASSWORD`、`ANDROID_VOCAB_RELEASE_KEY_ALIAS`、`ANDROID_VOCAB_RELEASE_KEY_PASSWORD`。
  - 执行 `ktlintCheck detekt testDebugUnitTest bundleRelease`。
  - 校验 `app/build/outputs/bundle/release` 中只有一个 `.aab`。
  - 复制到 `dist/` 后用 `jarsigner` 验证。
  - 支持 `-AllowUnsigned`，仅用于非上传的编译链路验证。
- `README.md`
  - 增加 AAB 构建入口。
- `docs/release.md`
  - 增加 Android App Bundle 章节。

## 本轮风险

- `-AllowUnsigned` 产物不能上传应用商店，只能验证编译链路。
- `jarsigner -verify` 只能证明 AAB 是 JAR 级签名产物；安装级验证仍需要 bundletool 或应用商店预检。

## 下一轮建议

1. 引入 bundletool 测试脚本，把 AAB 转成 APK Set 并在设备上安装验证。
2. 设置页补系统通知权限状态感知，处理用户在系统设置里关闭权限后的误导问题。
3. 为 release/smoke 脚本抽公共 PowerShell helper，减少 JDK、SDK、签名环境检测的重复。
