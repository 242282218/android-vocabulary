# 2026-05-25 持续优化第 55 轮

## 当前审查范围

本轮继续审查 GitHub Actions 的失败证据留存，重点是 CI 中 `ktlint`、`detekt`、单元测试和 managed device 测试失败后，是否能直接下载报告定位问题。

## 发现

当前 workflow 已经跑完整 CI 质量门，但没有上传 Gradle 报告。`Verify` 失败时只能从 Actions 日志里翻找错误，尤其是 managed device 测试、Compose smoke、lint / detekt 报告，排查成本较高。

本地构建已确认会生成以下报告路径：

- `**/build/reports/**`
- `**/build/test-results/**`
- `**/build/outputs/androidTest-results/**`

这些路径覆盖单元测试、ktlint、detekt、lint、connected androidTest 和 managed device androidTest 的主要诊断结果。

## 完成项

`.github/workflows/android.yml`

- 新增 `Upload verification reports` 步骤。
- 使用 `if: always()`，确保 `Verify` 成功或失败后都会尝试上传。
- 使用 `actions/upload-artifact@v4`。
- artifact 名称：`android-verification-reports`。
- 保留 14 天。
- 上传范围限定为报告和测试结果，不上传 APK / AAB 等构建产物。
