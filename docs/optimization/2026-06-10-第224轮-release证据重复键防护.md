# 第 224 轮：release 证据重复键防护

## 审查范围

- 复核 `README.md`、`docs/release.md` 的 release readiness 证据链要求。
- 检查 `scripts/test/verify-release-readiness.ps1` 对 release artifacts、APK smoke、设备验收、GitHub Actions evidence 的 key=value 解析和匹配逻辑。
- 对照 `scripts/test/verify-release-scripts.ps1` 中已有正负 fixture，确认发布门禁回归覆盖点。

## 发现

`Read-KeyValueMetadata` 原来用 hashtable 读取 evidence。若同一个 evidence 文件内出现重复 key，后一个值会静默覆盖前一个值。

这会让证据文件存在歧义：即使最终取到的值能通过 SHA-256、commitSha 或 runUrl 校验，文件本身仍不是明确的一组事实。发布准备阶段应拒绝这种 evidence，而不是继续解释。

## 修改

- `scripts/test/verify-release-readiness.ps1`
  - 读取 metadata 时记录重复 key 到内部 `__duplicateKeys`。
  - 新增 `Get-MetadataDuplicateKeys` 和 `Test-MetadataHasUniqueKeys`。
  - release artifacts、APK smoke、device verification、bundle smoke archive、GitHub Actions evidence 任一出现重复 key 时，对应 requirement 失败。
  - 输出 `releaseArtifactsDuplicateKeys`、`apkSmokeDuplicateKeys`、`deviceVerificationDuplicateKeys`、`deviceBundleSmokeArchiveDuplicateKeys`、`githubActionsDuplicateKeys`，方便定位问题 evidence。

- `scripts/test/verify-release-scripts.ps1`
  - 更新静态断言，要求 readiness 脚本保留重复 key 检测和 metadata 输出。
  - 增加 GitHub Actions evidence 重复 `runId` 的失败 fixture，验证重复 key 即使值一致也不能通过 readiness。
