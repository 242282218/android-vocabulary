# 2026-05-25 持续优化第 32 轮

## 当前审查范围

本轮审查导出 JSON 的诊断可用性。设置页已有学习数据检查入口，但导出文件本身缺少完整性摘要；用户反馈问题或迁移数据时，需要额外截图或手动执行检查，不利于发布前诊断。

## 方案取舍

1. 在导出 JSON 增加 `dataIntegrity` 摘要，复用现有 `ReviewRepository.inspectReviewDataIntegrity()`。改动小，不改变 `reviewCards`、`reviewLogs`、`dailyStats` 结构，推荐采用。
2. 新增完整原始日志诊断包。信息更完整，但会扩大导出协议，且可能把当前刻意过滤的孤儿日志重新暴露给普通备份。
3. 只保留设置页检查入口。零改动，但导出文件无法自带诊断上下文。

本轮采用方案 1。诊断失败时导出仍继续，`dataIntegrity.status` 写为 `unavailable`；导出是备份路径，不能因为诊断失败阻断用户取回数据。同时保留 `CancellationException` 正常传播，不把协程取消包装成导出失败。
