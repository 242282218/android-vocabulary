# 第 102 轮：Release readiness 失败 remediation 元数据

## 审查证据

- `scripts/test/verify-release-readiness.ps1` 已能列出 failed requirements，但不同失败项的下一步修复动作主要混在 `failureMessage` 和单个 `releaseArtifactsRemediation` 中。
- 第 101 轮新增 `gitWorktreeClean` 后，dirty workspace 会正确失败，但 metadata 还缺少同类 remediation 字段。
- `docs/release.md` 和 `README.md` 已说明最终 readiness 是正式发布前的证据链门禁。

## 方案

- 方案 A：继续只依赖 `failureMessage`。改动为零，但失败后仍要人工拆分每个 requirement 的处理动作。
- 方案 B：只给 dirty worktree 增加 remediation。能解决上一轮新增门禁，但其他失败仍不清楚。
- 方案 C：为每个 readiness requirement 写入 `*Remediation` 字段；通过时为 `<none>`，失败时给下一步动作。

采用方案 C。

## 修改

- `scripts/test/verify-release-readiness.ps1`
  - 新增 `Get-ReadinessRemediationText`。
  - 为 `gitWorktreeClean`、`releaseArtifacts`、`releaseApkSmoke`、`deviceAabVerification`、`deviceBundleSmokeArchive`、`githubActionsEvidence` 写入 remediation。
  - requirement evidence 中同步带上 `remediation=...`，失败时终端错误也能看到下一步。
- `scripts/test/verify-release-scripts.ps1`
  - 增加静态断言，防止 remediation 字段被误删。
  - clean fixture 断言所有 remediation 为 `<none>`。
  - dirty fixture 断言 `gitWorktreeRemediation` 存在。
- `README.md`、`docs/release.md`
  - 补充 readiness 失败 metadata 会写入 `*Remediation` 字段。

metadata 已记录：

```text
deviceBundleSmokeArchiveRemediation=Keep smoke-release-bundle-run.txt beside verification-completed.txt in the device verification archive.
githubActionsRemediation=Download github-actions-release-evidence from a successful Android workflow run for the current HEAD.
```
