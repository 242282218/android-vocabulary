# 2026-05-25 持续优化第 140 轮

## 当前审查范围

本轮接着第 139 轮，审查正式发布前的 release-ready 证据链是否只有文档 checklist，是否需要一个可重复的只读门禁把关键证据串起来。

## 发现

当前发布前证据分散在多个脚本和日志中：

- `build/release-artifacts/release-artifacts-run.txt`
- `build/apk-smoke/smoke-release-apk-run.txt`
- `build/device-verification/.../verification-completed.txt`
- GitHub Actions 通过结果

文档已经要求这些证据，但没有一个最终脚本检查它们是否同时满足当前版本、正式签名、非本地覆盖路径和 CI 通过证据。人工发布时仍可能漏看某一项。

## 方案

- 方案 A：继续只靠 checklist。改动少，但证据链不可机器复核。
- 方案 B：新增只读 release-readiness 门禁，读取现有 metadata 和 CI 证据文件，明确列出每项通过/失败。

本轮采用方案 B。

## 完成项

新增 `scripts/test/verify-release-readiness.ps1`：

- 读取 `build/release-artifacts/release-artifacts-run.txt`，要求：
  - `runStatus=completed`
  - 当前 `versionName` / `versionCode`
  - `releaseApkStatus=verified`
  - `releaseBundleStatus=verified`
- 读取 `build/apk-smoke/smoke-release-apk-run.txt`，要求：
  - `runStatus=completed`
  - 当前版本
  - `skipInstall=False`
  - `apkPathMatchesCurrentVersionedName=True`
- 读取最新 `build/device-verification/**/verification-completed.txt`，要求：
  - `runStatus=completed`
  - 当前版本
  - `usesLocalOnlyReleaseOverrides=False`
  - `bundlePathMatchesCurrentVersionedName=True`
  - `bundleSmokeApkSetSigning=release-signing`
- 要求显式传入存在的 `-GitHubActionsEvidencePath`。
- 写入 `build/release-readiness/release-readiness-run.txt`。

`scripts/test/verify-release-scripts.ps1`

- 将 `verify-release-readiness.ps1` 纳入 PowerShell 解析回归。
- 增加 readiness 四项要求的源码结构回归：
  - `releaseArtifacts`
  - `releaseApkSmoke`
  - `deviceAabVerification`
  - `githubActionsEvidence`

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，缺少正式设备 AAB 验收成功证据。
- 当前没有真实 GitHub Actions 通过证据文件。

## 下一轮建议

继续审查 release-readiness 门禁的证据定义是否过弱，例如 GitHub Actions 证据现在只要求文件存在，是否应要求文件内容包含提交、workflow 名称和通过状态。
