# 第 206 轮：补齐两阶段 ReviewLog 的 updateLog 回滚测试

## 审查证据

- `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - 上一轮把 `submitFeedback()` 改成了两阶段日志：
    1. `insertLog`
    2. `schedule`
    3. `updateLog`
    4. `upsertCard`
  - 新风险点是：如果第 3 步 `updateLog` 失败，前面已经插入的 `ReviewLog` 是否会和统计一起回滚。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryStatsAndRollbackTest.kt`
  - 之前已有：
    - scheduler 失败不写学习数据
    - card write 失败回滚 log 和 stats
  - 缺口是没有覆盖 `updateLog` 失败这个新中间步骤。

## 方案

- 方案 A：只加 `updateLog` 失败回滚测试
  - 优点：直接覆盖上一轮引入的新事务风险，改动最小
  - 缺点：不扩展到导出/完整性报告路径
- 方案 B：连带补“pending log 出现在完整性检查/导出里”的测试
  - 优点：覆盖更广
  - 缺点：当前不是上一轮新增风险的第一落点，优先级稍低

采用方案 A。

## 修改

- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryTestSupport.kt`
  - 新增 `FailingUpdateLogReviewDao`
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryStatsAndRollbackTest.kt`
  - 新增 `logFinalizeFailureRollsBackInsertedReviewLogAndStats()`
  - 断言内容：
    - 抛出 `AppError.DatabaseWriteFailed`
    - `review_logs` 没有残留记录
    - `review_cards` 没有残留 cache
    - `daily_stats` / `dailyStatsFromLogs` 没有脏统计

## 验证

运行：

```powershell
. .\scripts\lib\android-env.ps1
Use-AndroidVocabularyJavaHome
.\gradlew.bat --no-daemon --console=plain :core:database:testDebugUnitTest --tests "com.zzz.androidvocab.core.database.OfflineReviewRepositoryStatsAndRollbackTest" --tests "com.zzz.androidvocab.core.database.OfflineReviewRepositoryTest"
```

结果：通过。

结论：`insertLog -> schedule -> updateLog -> upsertCard` 这条新顺序在 `updateLog` 失败时仍保持整事务回滚，不会留下半成品 `ReviewLog`、`ReviewCard` 或统计缓存。
