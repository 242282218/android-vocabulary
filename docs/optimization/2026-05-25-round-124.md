# 2026-05-25 持续优化第 124 轮

## 当前审查范围

本轮接着第 123 轮，审查 `verify-device.ps1` 复制 AAB smoke metadata 时是否可能把上一轮全局文件误归档。

## 发现

第 123 轮让 `verify-device.ps1` 复制：

```text
build\bundle-smoke\smoke-release-bundle-run.txt
```

到本次设备验收日志目录。但如果 AAB smoke 本轮没有来得及写出新 metadata，而全局目录里残留上一轮文件，归档就可能混入旧数据。

## 方案

- 方案 A：复制时检查文件时间是否晚于本次验收开始时间。更严格，但对文件系统时间精度和时区更敏感。
- 方案 B：调用 AAB smoke 前先删除全局 metadata；之后只复制本轮新生成的文件。实现简单，能直接切断陈旧文件来源。

本轮采用方案 B。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Get-BundleSmokeRunMetadataPath`。
- 新增 `Clear-BundleSmokeRunMetadataArtifact`。
- `Save-BundleSmokeRunMetadataArtifact` 复用统一路径。
- 调用 `smoke-release-bundle.ps1` 前先清理旧的全局 metadata。

## 验证结果

PowerShell 解析通过：

```text
parse-ok
```

fake adb 缺失 AAB 失败路径通过：预先写入旧全局 metadata：

```text
runStatus=stale
staleMarker=ROUND124_STALE
```

运行 `verify-device.ps1` 后，本次归档仍包含新生成的 AAB smoke metadata：

```text
runStatus=failed
failureStage=resolveBundle
bundlePath=<unresolved>
bundlePathSource=explicit
bundlePathMatchesCurrentVersionedName=<unknown>
buildOnly=False
```

并确认旧标记没有被复制：

```text
COPIED_HAS_STALE_MARKER=False
```

## 剩余风险

- 当前没有在线 Android 设备，未验证真实 AAB install smoke 成功路径的归档。
- 当前没有正式 release signing 环境，未验证 release-signing APK Set metadata。

## 下一轮建议

继续审查 `smoke-release-bundle.ps1` 自身的 metadata 生命周期。当前脚本会在 `resolveBundle` 后写 started；如果在更早的 environment / bundletool 解析阶段失败，metadata 可能仍不可用。
