# 2026-05-25 持续优化第 74 轮

## 当前审查范围

本轮审查 AAB smoke 过程中 Java / bundletool 输出的中文项目路径是否会影响发布日志可读性。

## 发现

第 73 轮执行 `smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning -ApksPath ...` 时，bundletool 日志里出现过一次中文项目路径乱码。

进一步检查：

- PowerShell 当前 `$OutputEncoding`、`[Console]::OutputEncoding`、`[Console]::InputEncoding` 都是 UTF-8。
- `Get-AndroidVocabularyRepoRoot` 和 PowerShell 自己输出的 AAB 路径能正常显示 `安卓背单词`。
- Gradle 仍保留 `org.gradle.jvmargs=-Xmx3g -Dfile.encoding=GBK`，这是已有的 Windows 非 ASCII 路径兼容设置，本轮不改。

问题更像 bundletool Java 子进程输出编码不稳定，而不是脚本变量或路径解析损坏。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 将 bundletool Java 调用集中到 `$bundleToolJavaArgs`。
- 显式传入：

```text
-Dfile.encoding=UTF-8
-Dsun.stdout.encoding=UTF-8
-Dsun.stderr.encoding=UTF-8
```

- `build-apks` 和 `install-apks` 共用同一组 JVM 参数。
- 不修改 Gradle 全局编码配置，避免影响 Kotlin/Gradle 在中文路径下的既有兼容设置。

## 验证结果

$tokens = $null; $parseErrors = $null; $null = [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path 'scripts/test/smoke-release-bundle.ps1'), [ref]$tokens, [ref]$parseErrors)

结果：通过。

结果：bundletool 的 build 和 install 路径都使用同一组 UTF-8 JVM 参数。
