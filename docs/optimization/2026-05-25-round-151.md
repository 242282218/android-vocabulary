# 2026-05-25 持续优化第 151 轮

## 当前审查范围

本轮接着第 150 轮，审查 release readiness 输出是否自包含。前几轮已经让 release artifacts、APK smoke、设备验收三类本地 evidence 都可显式指定，但 `build/release-readiness/release-readiness-run.txt` 只记录源路径和摘要字段，没有复制本次读取的原始 evidence 文件。

## 发现

如果 readiness 完成后又运行 release artifact 审计、APK smoke、设备验收或下载新的 GitHub Actions evidence，源 metadata 可能被覆盖。此时 `release-readiness-run.txt` 仍有摘要字段，但缺少本次判定所读取的原始 evidence 快照。

## 方案

- 方案 A：只保留路径和摘要字段。改动少，但 release readiness 目录不自包含。
- 方案 B：在 readiness 运行时复制本次读取到的 evidence 文件到 `build/release-readiness/evidence-*.txt`，并在 metadata 中记录归档文件名；源文件缺失时写 `<missing>` 并删除对应旧归档，避免残留旧证据。

本轮采用方案 B。它不改变 readiness 判定逻辑，只增强最终发布记录的自包含性。
