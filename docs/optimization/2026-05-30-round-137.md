# 第 137 轮：今日剩余数饱和计算

## 审查证据

- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt` 中今日统计使用：
  - `remainingNew = (settings.dailyNewLimit - base.newCount).coerceAtLeast(0)`
  - `remainingCount = dueCount + remainingNew`
- `dueCount` 来自 DAO，`remainingNew` 来自设置和当日日志聚合。真实词库规模下不会接近 Int 上限，但仓库层计算仍不应依赖隐含规模假设。
- 如果异常 DAO 数据或损坏设置导致极大值，Int 加法会溢出，进而影响 `TodayStats.remainingCount` 和预计分钟数。

## 方案

- 方案 A：抽出 `remainingTodayCount()`，用 Long 做差与求和，负值夹到 0，最终夹到 `Int.MAX_VALUE`。范围小，只影响今日统计边界。
- 方案 B：保持现有 Int 加法，依赖词库规模和设置上限。改动为零，但异常数据下仍可能输出负剩余数。

采用方案 A。

## 修改

- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - 今日统计改用 `remainingTodayCount()`。
