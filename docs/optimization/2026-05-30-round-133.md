# 第 133 轮：分钟估算安全换算统一

## 审查证据

- `core/common/src/main/java/com/zzz/androidvocab/core/common/DateMath.kt` 的 `millisToCompletedMinutes()` 使用 `this + 59999`，在极大毫秒值下有加法溢出风险。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ClockProviderExt.kt` 和 `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt` 各自重复实现“剩余数量 × 单条耗时 -> 向上取整分钟”。
- 重复公式都直接做 Long 乘法和 `toInt()`，异常大值会溢出或窄化为错误分钟数。虽然正常词库规模较小，但统计和 UI 估算属于发布可见数据，不应依赖隐含规模假设。

## 方案

- 方案 A：在 `core:common` 提供安全的 `estimateCompletedMinutes(itemCount, millisPerItem)`，统一处理非正值、乘法溢出和 Int 上限夹取，domain/stats 复用。范围小，减少重复公式。
- 方案 B：保留各模块公式，只在每处补局部溢出判断。改动更分散，后续容易再次漏改。

采用方案 A。

## 修改

- `core/common/src/main/java/com/zzz/androidvocab/core/common/DateMath.kt`
  - 修复 `millisToCompletedMinutes()` 的加法溢出风险。
  - 新增 `estimateCompletedMinutes()`，对乘法溢出饱和到 `Long.MAX_VALUE`，最终分钟数夹到 `Int.MAX_VALUE`。
- `core/common/src/test/java/com/zzz/androidvocab/core/common/DateMathTest.kt`
  - 新增分钟向上取整、极大值夹取、乘法溢出饱和测试。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ClockProviderExt.kt`
  - `estimateRemainingMinutes()` 改用 common helper。
- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - 今日统计 `estimatedMinutes` 改用 common helper。
