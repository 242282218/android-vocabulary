# 第 155 轮：Wordbook 长词详情小屏收敛

## 审查证据

- `WordbookRoute.WordDetailCard()` 在详情头部直接展示 `detail.entry.word`，没有 `maxLines` 和 `overflow`。
- 详情主释义 `detail.entry.meaning` 也没有行数上限；长词或长中文释义会让详情卡在 360dp 小屏上快速增高。
- Wordbook 页面顺序是词书选择、筛选搜索、选中词详情、进度和词条列表；详情卡过高会挤压后续内容，并增加关闭控制不可见的风险。
- 移动端设计参考要求主任务和关键状态在小屏下可访问，长文本要有可控截断，不能让二级信息挤压主要操作。

## 方案

- 方案 A：只增加 UI smoke，记录当前行为。改动最少，但不降低长词详情卡膨胀风险。
- 方案 B：限制详情标题和主释义行数，并补长详情 smoke。改动小，保留足够上下文，同时保证小屏控制可见。

采用方案 B。

## 修改

- `feature/wordbook/src/main/java/com/zzz/androidvocab/feature/wordbook/WordbookRoute.kt`
  - 详情词头最多 2 行并省略。
  - 主释义最多 3 行并省略。
  - 拆出 `WordDetailHeader()`，避免详情卡函数过长并保持头部布局独立。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 新增长词详情场景。
  - 断言搜索入口和“关闭词条详情”按钮在参数化小屏 smoke 中仍可显示。
