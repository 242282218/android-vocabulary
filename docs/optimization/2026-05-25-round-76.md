# 2026-05-25 持续优化第 76 轮

## 当前审查范围

本轮审查 release APK 的 `apksigner` 验签输出，确认 `build-release.ps1` 和 `smoke-release-apk.ps1` 在中文路径下的日志可读性和失败提示是否一致。

## 发现

`build-release.ps1` 和 `smoke-release-apk.ps1` 都通过 Android SDK 的 `apksigner.bat` 执行：

```powershell
apksigner verify --verbose <apk>
```

与 bundletool / jarsigner 不同，本轮实测 `apksigner` 对中文项目路径输出正常，且未签名 APK 的失败信息清楚。

## 验证结果

PowerShell 解析检查：

```powershell
foreach ($file in @('scripts/release/build-release.ps1','scripts/test/smoke-release-apk.ps1')) {
  [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $file), [ref]$tokens, [ref]$parseErrors) | Out-Null
}
```

结果：通过。

未签名 APK 验签检查：

```powershell
.\dist\AndroidVocabulary-release-v0.1.0-1.apk
apksigner verify --verbose <apk>
```

结果：`apksigner` 返回退出码 `1`，输出：

```text
DOES NOT VERIFY
ERROR: Missing META-INF/MANIFEST.MF
```

中文路径显示正常：

```text
D:\PROJECT_ZZZZZZZZZ\安卓背单词\dist\AndroidVocabulary-release-v0.1.0-1.apk
```

## 结论

本轮不需要改 `build-release.ps1` 或 `smoke-release-apk.ps1`。当前 `apksigner` 失败路径可读，脚本通过退出码区分可发布 APK 和仅用于 build validation 的未签名 APK。

## 剩余风险

- 当前没有正式 release signing 环境，未验证 `[ok] release APK signature verified` 的正式签名路径。
- 当前没有在线设备，未跑 APK 安装和首屏 smoke。

## 下一轮建议

继续审查 `smoke-release-apk.ps1 -SkipInstall` 的语义是否清楚。该参数会跳过 APK 文件验签和安装，只检查已安装应用的启动状态；文档需要避免把它误认为完整 APK smoke。
