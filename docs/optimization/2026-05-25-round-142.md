# 2026-05-25 持续优化第 142 轮

## 当前审查范围

本轮接着第 141 轮，审查 GitHub Actions evidence 的生成链路。第 141 轮已经让 readiness 门禁校验 `workflow`、`conclusion`、`commitSha` 和必需检查项，但证据文件仍需要人工手写，容易和真实 CI 结果漂移。

## 发现

`.github/workflows/android.yml` 已运行 `verify-release-scripts.ps1`、`verify-vocab-assets.ps1`、Gradle 静态检查、单元测试、debug 构建、androidTest APK 编译和 `pixel2Api30DebugAndroidTest`。但 workflow 没有自动产出 `verify-release-readiness.ps1` 需要的 key-value evidence 文件。

这会留下两个风险：

- 发布人可能手工写错 `commitSha` 或漏掉检查项。
- CI 实际检查项调整后，readiness schema 和 workflow 可能不一致。

## 方案

- 方案 A：继续手工维护 evidence 文件。改动少，但证据链依赖人工。
- 方案 B：CI 成功后自动写入 evidence artifact，并让本地 readiness 使用下载后的文本文件。

本轮采用方案 B。它不需要 GitHub API token，也不改变 release signing 或设备验收流程。

## 完成项

`scripts/lib/android-env.ps1`

- 新增 `Get-AndroidVocabularyRequiredGitHubActionsChecks`，作为 CI 必需检查项的单一来源。

`scripts/test/verify-release-readiness.ps1`

- 改为使用 `Get-AndroidVocabularyRequiredGitHubActionsChecks`，避免本地门禁和 evidence 生成脚本维护两份检查列表。

新增 `scripts/test/write-github-actions-evidence.ps1`

- 只从 GitHub Actions 环境读取 `GITHUB_WORKFLOW` 和 `GITHUB_SHA`。
- 要求 workflow 名称为 `Android`。
- 写入 `build/release-readiness/github-actions-evidence.txt`：
  - `workflow=Android`
  - `conclusion=success`
  - `commitSha=<GITHUB_SHA>`
  - `checks=<shared required checks>`

`.github/workflows/android.yml`

- 在所有验证通过后运行 `write-github-actions-evidence.ps1`。
- 上传 `github-actions-release-evidence` artifact，包含 `github-actions-evidence.txt`。

`scripts/test/verify-release-scripts.ps1`

- 将新 evidence 写入脚本纳入 PowerShell 解析。
- 增加 shared checks 列表断言。
- 增加 evidence 写入脚本的离线 fake CI 环境回归。
- 增加 workflow 静态断言，确认 CI 仍调用必需检查、写入并上传 evidence artifact。

文档同步：

- `README.md` 说明 GitHub Actions 成功后会上传 `github-actions-release-evidence` artifact。
- `docs/release.md` 发布前 checklist 改为从 artifact 下载 evidence 文件，而不是手工编写。
