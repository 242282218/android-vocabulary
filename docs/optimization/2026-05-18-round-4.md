# 2026-05-18 持续优化第 4 轮

## 当前状态判断

项目已经是 Kotlin + Jetpack Compose + Room + DataStore + WorkManager + FSRS 的原生 Android 多模块结构。前三轮已经补过别名搜索、调度错误边界、困难词队列排序和导出统计从日志派生。本轮继续从实际可用性和数据可恢复性切入。

当前可用基础：

- publish-safe 词库校验通过。
- ReviewLog 是复习与统计事实来源。
- `scripts/test/verify-local.ps1` 可跑完整本地验证。
- 当前目录不是 Git 仓库，变更审计不能依赖 git。

## 对标项目可借鉴点

- Android 13 起通知属于运行时权限；只在 Manifest 声明不够，用户未授权时提醒不会展示。
- Android 官方架构建议把平台权限留在 UI/app 边界，业务层只处理设置状态和调度命令。
- Anki/FSRS 类 SRS 应保证学习日志可审计、可重放；聚合统计缓存应能从日志重建。

## 差距清单

### P0

- Android 13+ 提醒开关可能“开启但不响”。影响每日复习提醒主路径；根因是只声明 `POST_NOTIFICATIONS`，未在用户启用提醒时请求运行时权限；建议启用提醒时请求权限，拒绝后自动关闭提醒设置；收益是避免静默失败；风险低。

### P1

- `daily_stats` 缓存缺少显式重建入口。影响数据恢复、迁移和排障；根因是缓存只在提交反馈时按当天增量刷新；建议提供从 `review_logs` 全量重建缓存的 DAO/Repository/UseCase 入口；收益是缓存缺失或脏缓存可修复；风险低。

### P2

- 今日统计的 `newCount` 仍通过 `review_cards.firstReviewedAt` 判断，和“ReviewLog 为事实来源”的理想口径还有轻微差距。
- UI instrumentation 尚未覆盖系统权限弹窗和提醒拒绝后的设置回退。

### P3

- 底部导航仍是英文，后续可统一为中文产品文案。

## 本轮要做的优化项

1. 通知权限联动：用户开启提醒时检查并请求 Android 13+ 通知权限；拒绝后关闭提醒设置并取消 WorkManager 任务。
2. 统计缓存重建：新增 `rebuildDailyStatsCache`，从 `review_logs` 派生 `daily_stats`，并清理无日志对应的陈旧缓存。
3. 补单元测试：覆盖通知权限判断、统计缓存重建和空日志清缓存。

## 本轮风险

- 权限请求发生在提醒开关已开启且权限缺失时；如果用户拒绝，设置会自动回到关闭，避免误导。风险是用户需要再次手动开启提醒。
- 统计缓存重建会全量扫描 `review_logs`。MVP 本地日志规模可接受；后续日志量很大时可按日期增量重建。

## 下一轮建议

1. 统一今日统计 `newCount` 口径，让 UI 统计也完全从 `review_logs` 可复算，降低 `review_cards` 损坏带来的偏差。
2. 给设置页增加“提醒权限未授权”的明确状态文案或轻提示，避免用户拒绝权限后不理解为什么开关回退。
3. 强化 UI instrumentation：覆盖 360dp 长释义、深色模式、权限拒绝后的提醒开关状态。
