# 2026-05-25 持续优化第 155 轮

## 当前审查范围

本轮接着第 154 轮，审查 release readiness metadata 的缺失值表达一致性。上一轮已经增加 `evidenceArchives` 汇总清单，但缺少设备验收日志时，`deviceBundleSmokeMetadata` 仍输出为空字符串。

## 发现

空字符串不如 `<missing>` 明确。发布复核时，`deviceBundleSmokeEvidenceArchive=<missing>` 和 `deviceBundleSmokeEvidenceArchiveSha256=<missing>` 已经是显式缺失，但 `deviceBundleSmokeMetadata=` 容易被误读为字段写入异常。

## 方案

- 方案 A：保持空字符串。无改动，但 metadata 缺失语义不一致。
- 方案 B：将空的 bundle smoke 子日志路径统一写为 `<missing>`。

本轮采用方案 B。它不改变 readiness 判定，只统一输出语义。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 新增 `$deviceBundleSmokeMetadata` 输出变量。
- 当 `Get-DeviceBundleSmokeMetadataPath` 没有可用路径时，metadata 写入 `deviceBundleSmokeMetadata=<missing>`。
- 归档复制仍使用原始路径变量，保持缺失时清理旧归档的行为不变。

`scripts/test/verify-release-scripts.ps1`

- 增加 `deviceBundleSmokeMetadata=$deviceBundleSmokeMetadata` 的源码结构回归断言。
