# 2026-05-25 持续优化第 79 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 聚合日志是否能完整体现 AAB 安装级验收的输入产物和执行语义。

## 发现

第 78 轮已经让 `smoke-release-bundle.ps1` 在日志中区分：

- bundletool AAB 拆包安装。
- AAB 安装后的已安装应用启动复核。

但 `verify-device.ps1` 的 `verification-run.txt` 仍只记录原始 `BundlePath` 参数或 `<default>`。正式验收记录里，如果使用默认 AAB、相对路径 AAB、或 `-SkipBundleBuild` 后缺少当前版本 AAB，单看元数据无法确认最终预期使用的 AAB 文件。

## 方案

- 方案 A：只增强 `verify-device.ps1` 的运行元数据，记录 AAB 输入、解析路径、来源和状态。改动小，不改变安装链路。
- 方案 B：让 `verify-device.ps1` 自己解析并把绝对路径传给 `smoke-release-bundle.ps1`。可追溯性更强，但会把 AAB 选择逻辑从 smoke 子脚本复制到聚合脚本，维护成本更高。

本轮采用方案 A。问题本质是发布记录缺少可追溯字段，不是安装逻辑缺陷。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Get-ResolvedBundleMetadata`。
- `verification-run.txt` 现在记录：
  - `bundlePath`：解析后的路径或预期默认版本化 AAB 路径。
  - `bundlePathInput`：用户输入或 `<default>`。
  - `bundlePathSource`：`explicit`、`defaultVersionedDist` 或 `skipped`。
  - `bundlePathStatus`：`exists`、`willBeBuilt`、`missing` 或 `skipped`。

`README.md`、`docs/release.md`

- 更新设备验收日志说明，明确 `verification-run.txt` 会记录 AAB 输入/解析路径和路径状态。

## 验证结果

PowerShell 解析检查：

```powershell
$files=@('scripts/test/verify-device.ps1','scripts/test/smoke-release-bundle.ps1','scripts/test/smoke-release-apk.ps1'); foreach ($file in $files) { $tokens=$null; $errors=$null; [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $file), [ref]$tokens, [ref]$errors) | Out-Null; if ($errors.Count -gt 0) { Write-Error "$file parse failed"; $errors | ForEach-Object { $_.Message }; exit 1 } }; 'parse-ok'
```

结果：通过。

引用检查：

```powershell
rg -n "Get-ResolvedBundleMetadata|bundlePath(Input|Source|Status)?=|ExpectedBundleName|verification-run|smoke-release-bundle" .\scripts\test\verify-device.ps1 .\docs\release.md README.md
```

结果：脚本和文档均能定位新元数据字段。
