# 2026-05-25 持续优化第 82 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 设备验收日志是否能从 `verification-run.txt` 快速定位设备侧诊断证据。

## 发现

脚本已经固定输出：

- `selected-device.txt`
- `devices.txt`
- `getprop.txt`
- `logcat-tail.txt`

但第 80 轮的 `verification-run.txt` 只记录了构建、测试和 AAB smoke 子日志，没有记录这些设备诊断日志。发布或失败归档时，读者需要知道脚本内部约定才能找到 logcat tail。

## 方案

- 方案 A：在 `verification-run.txt` 中记录固定设备诊断日志文件名。改动小，不改变执行流程。
- 方案 B：把设备诊断日志合并进 `verification-run.txt`。单文件更集中，但会把大量 getprop/logcat 内容混入元数据，降低可读性。

本轮采用方案 A。

## 完成项

`scripts/test/verify-device.ps1`

- `verification-run.txt` 新增：
  - `selectedDeviceLog=selected-device.txt`
  - `devicesLog=devices.txt`
  - `getpropLog=getprop.txt`
  - `logcatTailLog=logcat-tail.txt`

`README.md`、`docs/release.md`

- 设备验收日志说明同步补充设备诊断日志。

$files=@('scripts/test/verify-device.ps1','scripts/test/smoke-release-bundle.ps1','scripts/test/smoke-release-apk.ps1'); foreach ($file in $files) { $tokens=$null; $errors=$null; [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $file), [ref]$tokens, [ref]$errors) | Out-Null; if ($errors.Count -gt 0) { Write-Error "$file parse failed"; $errors | ForEach-Object { $_.Message }; exit 1 } }; 'parse-ok'
