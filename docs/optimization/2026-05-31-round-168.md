# 第 168 轮：Settings 数据维护卡局部分组与组内间距收紧

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `DataMaintenanceCard()` 中，动作按钮和反馈块此前都直接作为 `VocabCard` 的并列子项输出。
  - `VocabCard` 默认对每个子项使用 `16.dp` 间距。
  - 结果是“检查按钮 / 修复按钮 / 旧结果 / 新失败”全部同时出现时，虽然结构正确，但动作区内部和反馈区内部缺少更明确的局部分组节奏。
- 前几轮已经补了：
  - 状态摘要
  - 红边动态切换
  - 旧结果与新失败的轻分隔
- 剩余问题已经缩小为纯留白与分组边界，不涉及状态机和文案逻辑。

## 方案

- 方案 A：保持所有元素继续作为 `VocabCard` 并列子项。
  - 优点：零结构调整。
  - 缺点：组内与组间都吃同一层级的 `16.dp`，动作区和反馈区的局部结构感仍然偏弱。
- 方案 B：把动作区和反馈区分别包成局部 `Column`，组内间距收紧到 `12.dp`，组间仍沿用卡片默认节奏。
  - 优点：不引入新容器视觉样式，只调整排版层级，能直接改善 360x800 下的扫描节奏。
  - 缺点：结构比之前多一层组合函数，但仍然只在本文件内。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `DataMaintenanceActions()` 改成局部 `Column(verticalArrangement = Arrangement.spacedBy(12.dp))`，让“检查 / 修复”两按钮在组内更紧凑。
  - 新增 `DataMaintenanceFeedback()`，把旧结果、分隔线和新失败放进一个局部反馈组，同样使用 `12.dp` 组内间距。
  - `DataMaintenanceCard()` 主体保留原有卡片节奏，只把动作区和反馈区视为两个更高层级的块。
