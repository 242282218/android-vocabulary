# 第 223 轮：移动端触控目标修复

## 审查目标

继续美化前端美学设计和交互，但不扩大视觉方案。本轮聚焦移动端可访问性：检查当前自定义控件是否符合 48dp 最小触控目标。

## 调研依据

- Android 官方 Compose accessibility API defaults 文档要求可点击、可触摸或可交互元素应设置足够尺寸，并明确建议最小 48dp。
- 本地 `设计美学研究/packages/mobile-design-knowledge/README.md` 强调移动端优先处理触控、权限状态、离线状态和有限视口下的信息取舍。
- 同类轻量背诵应用的可借鉴点不是增加复杂 UI，而是保持高频交互稳定、易触达。

## 发现

当前自定义控件里还有 44dp 最小高度：

- `core/designsystem/.../Components.kt`
  - `VocabFilterChip` 用于词书选择和状态筛选。
- `feature/settings/.../SettingsRoute.kt`
  - 提醒时间步进按钮。

这类控件位于 Wordbook / Settings 高频路径，小屏上 44dp 会增加误触和触达压力。即使部分 Material 组件会自动扩展语义触控区域，显式 48dp 更稳，也能避免相邻点击区域重叠。

## 修改

文件：

```text
core/designsystem/src/main/java/com/zzz/androidvocab/core/designsystem/Components.kt
feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt
```

改动：

- `VocabFilterChip` 的 `heightIn(min = 44.dp)` 改为 `48.dp`。
- 提醒时间 stepper 的减少 / 增加按钮 `heightIn(min = 44.dp)` 改为 `48.dp`。
