# 第 101 轮：Release readiness 绑定 clean Git worktree

## 审查证据

- `git status --short` 显示当前工作树存在大量 tracked 和 untracked 改动。
- `scripts/test/verify-release-readiness.ps1` 原本只校验 GitHub Actions evidence 的 `commitSha == HEAD`。
- `dist/` 和 `build/` 已在 `.gitignore` 中忽略，最终发布证据可以来自本地产物和 metadata；但源码工作树 dirty 时，CI 证据只能证明 `HEAD`，不能证明本地 release 产物对应的源码状态。

## 方案

- 方案 A：只记录风险。零改动，但最终 release gate 仍可能通过 dirty workspace。
- 方案 B：只把 dirty 状态写入 readiness metadata。诊断更清楚，但不会阻断错误发布。
- 方案 C：新增 `gitWorktreeClean` readiness requirement，dirty workspace 直接失败，并记录 dirty 数量和摘要。

采用方案 C。

## 修改

- `scripts/test/verify-release-readiness.ps1`
  - 新增 `Get-CurrentGitStatusEntries` 和 `Format-GitStatusSummary`。
  - 新增 `gitWorktreeClean` requirement。
  - metadata 记录 `gitWorktreeStatus`、`gitWorktreeDirtyCount`、`gitWorktreeDirtyEntries`。
- `scripts/test/verify-release-scripts.ps1`
  - 增加 readiness clean/dirty fixture 覆盖。
  - 增加静态断言，防止 `gitWorktreeClean` 门禁被误删。
- `README.md`、`docs/release.md`
  - 补充最终 readiness 要求当前 Git worktree 干净。

## 验证

通过：

```powershell
.\scripts\test\verify-release-scripts.ps1
git diff --check -- scripts/test/verify-release-readiness.ps1 scripts/test/verify-release-scripts.ps1 README.md docs/release.md
```

真实 dirty workspace 预期失败路径通过：

```powershell
.\scripts\test\verify-release-readiness.ps1
```

metadata 记录：

```text
runStatus=failed
gitWorktreeStatus=dirty
gitWorktreeDirtyCount=60
gitWorktreeClean=failed
```
