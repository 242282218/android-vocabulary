# 第 195 轮：修正 ScreenLayoutSmokeTest 的假状态与 viewport 夹具，恢复 app connected smoke 全绿

## 审查证据

- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 初始 connected 结果里，`StatsScreen`、`ReviewScreen`、`WordbookScreen` 大量报“找不到文本”。
  - 对 `statsScreenRendersInViewport()` 临时加 `printToLog()` 后，真实语义树显示首屏是：
    - `正在加载统计`
    - `正在从本地复习记录汇总趋势、负载和困难词。`
  - 说明测试假数据没有把页面切到“已加载”态，之前的大量文本失败不是 UI 真丢了，而是页面根本还停在 loading state。
- `feature/stats/.../StatsViewModel.kt`
  - `StatsUiState.isLoading` 默认值是 `true`。
- `feature/review/.../ReviewViewModel.kt`
  - `ReviewUiState.isLoading` 默认值是 `true`。
- `feature/wordbook/.../WordbookViewModel.kt`
  - `WordbookUiState.isLoading` 默认值是 `true`。
- 进一步复测后，失败从 42 个缩到 11 个，再缩到 4 个，且全部只出现在 `768x1024`：
  - `statsScreenKeepsCompactMetricsVisibleOnNarrowViewport`
  - `todayScreenShowsImportErrorWithoutBlockingUsableQueue`
  - `todayScreenShowsImportProgressWithoutBlockingUsableQueue`
  - `wordbookScreenKeepsLongSelectedDetailControllable`
- 对 `renderInViewport()` 打印语义树时发现：
  - 大 viewport 在真实手机 emulator 上会被换算成超出物理屏幕的巨大 px box
  - 未锚定时会发生居中裁切
  - 即使锚到左上角，`768dp x 1024dp` 仍不是当前 1080x1920、420dpi 设备能直接承载的像素窗口

结论：这轮的根因主要有三层，不是 App 页面本身连续坏了。

1. 测试 fake `UiState` 没显式关闭 loading。
2. `assertTextExists()` 把“至少出现一次”写成了“必须唯一命中一次”。
3. viewport 夹具直接拿当前手机 density 去换算 768dp 平板窗口，导致 connected device 上出现测试环境裁切，而不是平板真实布局。

## 方案

- 方案 A：继续按页面逐个改 UI。
  - 优点：看起来直观。
  - 缺点：会把测试夹具错误当成页面问题，改错方向。
- 方案 B：先把 smoke test 的状态构造和 viewport 模拟修正，再看剩余 connected 失败。
  - 优点：先清掉伪失败，剩下的才是可信 UI 问题。
  - 缺点：要调整测试夹具本身，而不是只改断言文案。

采用方案 B。

## 修改

- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - `fakeReviewUiState()` 显式设置 `isLoading = false`
  - `fakeWordbookUiState()` 显式设置 `isLoading = false`
  - `fakeStatsUiState()` 显式设置 `isLoading = false`
  - `assertTextExists()` 从“必须唯一命中”收紧为“至少找到一个节点即可”
  - `renderInViewport()` 改成两层容器：
    - 外层 `fillMaxSize()` + `Alignment.TopStart`
    - 内层 `requiredSize(widthDp.dp, heightDp.dp)`
  - `renderInViewport()` 额外通过 `CompositionLocalProvider(LocalDensity ...)` 按目标 viewport 计算模拟 density：
    - 让 `768x1024` 这类平板窗口在当前 emulator 上按“对应 dp 窗口”渲染
    - 避免被当前手机物理 density 直接放大成超屏像素盒子
