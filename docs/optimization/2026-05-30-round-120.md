# 第 120 轮：SubmitReviewFeedbackUseCase 设置契约测试

## 审查证据

- `SubmitReviewFeedbackUseCase` 从 `settingsRepository.settings` 读取 `targetRetention`，再组装 `SubmitFeedbackCommand`。
- 数据库层已有不同 `targetRetention` 的调度/日志测试，但 domain use case 没有直接断言命令里的 `targetRetention` 来自用户设置。
- 该字段会进入 `ReviewLog` 并影响 FSRS 调度，是发布前数据不变量的一部分。

## 方案

- 方案 A：依赖数据库层间接测试。覆盖不够直接，use case 误改时定位成本高。
- 方案 B：新增独立 domain 单测，直接断言 `targetRetention`、`reviewedAt`、`durationMs` 和 rating/cardId 都被正确写入命令。范围小，契约清晰。
- 方案 C：扩大到 ViewModel 集成测试。能覆盖更多路径，但会混入 UI 状态和提交耗时逻辑，本轮不需要。

采用方案 B。

## 修改

- `core/domain/src/test/java/com/zzz/androidvocab/core/domain/SubmitReviewFeedbackUseCaseTest.kt`
  - 新增 `submitUsesTargetRetentionFromSettings`。

  - 断言提交命令的 `cardId`、`rating`、`reviewedAt`、`durationMs`、`targetRetention`。
