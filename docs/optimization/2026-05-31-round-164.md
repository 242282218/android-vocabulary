# 第 164 轮：Settings 数据维护操作防重入

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - “检查学习数据”和“修复学习数据缓存”按钮在 `inProgress` 时会被禁用。
- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsViewModel.kt`
  - `exportData()` 已有 `if (isExporting.value) return` 防重入。
  - `inspectLearningData()` 和 `repairLearningData()` 没有对应的 VM 级防重入。
- `feature/settings/src/test/java/com/zzz/androidvocab/feature/settings/SettingsViewModelTest.kt`
  - 已有 `exportDataIgnoresDuplicateTriggerWhileRunning()`，但没有覆盖学习数据维护的重复触发。

结论：当前 UI 层虽然会在重组后禁用按钮，但 ViewModel 自身没有边界保护。只要通过测试、未来快捷入口或时序窗口重复调用，仍可能并发执行两次检查/修复。

## 方案

- 方案 A：继续只依赖 UI 按钮禁用。
  - 优点：无需改代码。
  - 缺点：边界不在状态层，任何非 UI 调用都能绕过。
- 方案 B：在 `SettingsViewModel` 中对 `inspectLearningData()` 和 `repairLearningData()` 增加 `inProgress` 防重入。
  - 优点：和 `exportData()` 一致，边界集中，改动小。
  - 缺点：如果以后需要支持排队操作，还需要再扩展。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsViewModel.kt`
  - `inspectLearningData()` 开头增加 `if (dataMaintenance.value.inProgress) return`。
  - `repairLearningData()` 开头增加同样的防重入判断。
- `feature/settings/src/test/java/com/zzz/androidvocab/feature/settings/SettingsViewModelTest.kt`
  - 新增 `inspectLearningDataIgnoresDuplicateTriggerWhileRunning()`。
  - 新增 `repairLearningDataIgnoresDuplicateTriggerWhileRunning()`。
  - 为 `MaintenanceReviewRepository` 增加 `inspectCallCount` / `repairCallCount`，用于精确断言只调用一次。
