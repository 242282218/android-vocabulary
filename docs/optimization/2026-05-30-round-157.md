# 第 157 轮：Wordbook 结果预览上限说明

## 审查证据

- `WordsCard()` 使用 `words.take(30)` 只展示前 30 条。
- 标题 detail 显示 `${shownWords.size}/${words.size} 个结果`，能看出数量差，但没有明确说明列表被截断，也没有提示用户继续缩小搜索范围。
- UI smoke 夹具中 `selectedWordDetail = null` 实际会被默认详情回填，无法构造纯结果列表场景；这会让列表行相关断言在真实执行时容易命中详情里的重复文本。
- 移动端状态参考要求 no-results / filtered-list 状态说明原因和下一步；小屏长列表应清晰表达当前展示范围。

## 方案

- 方案 A：保持 `30/总数` 的 detail，不增加说明。视觉最简，但用户仍可能误以为当前列表就是全部结果。
- 方案 B：保留 detail，同时当总数超过可见数时增加一行轻量说明：仅显示前 N 条，并提示继续输入缩小范围。改动小，信息更明确。

采用方案 B。

## 修改

- `feature/wordbook/src/main/java/com/zzz/androidvocab/feature/wordbook/WordbookRoute.kt`
  - 将结果预览上限提取为 `WORD_RESULT_PREVIEW_LIMIT = 30`。
  - 新增 `resultLimitHint()`，当总结果数超过当前展示数时显示“仅显示前 30 条，共 X 条；继续输入可缩小范围。”。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 新增 35 条结果的 Wordbook smoke，断言预览上限说明存在。
  - 修正 `fakeWordbookUiState()`，增加 `showSelectedWordDetail`，可显式构造无选中详情的列表场景。
