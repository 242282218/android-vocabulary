# 2026-05-25 持续优化第 110 轮

## 当前审查范围

本轮检查第 109 轮建议中提到的 PowerShell 子进程 helper 是否应该提升到公共库，并补跑 APK release 构建路径，覆盖 `apksigner` 输出转换。

## 发现

`Get-PowerShellExecutable` / `Invoke-PowerShellScriptCommand` 目前只有 `scripts/test/smoke-release-bundle.ps1` 使用：

- `-ListDevices` 委托 `smoke-release-apk.ps1`。
- AAB 安装后的 `smoke-release-apk.ps1 -SkipInstall` 启动复核。

当前没有第二个脚本需要同类子进程包装。按项目规则，不为潜在复用上移公共库。

## 完成项

- 保留 `Get-PowerShellExecutable` / `Invoke-PowerShellScriptCommand` 在 `smoke-release-bundle.ps1` 内部，不做过早抽象。
- 补跑 release APK 构建验证，覆盖 `build-release.ps1` 中 `apksigner verify --verbose` 的输出转换路径。

## 验证结果

APK release 构建链路通过：

```powershell
.\scripts\release\build-release.ps1 -AllowUnsigned
```

结果：

```text
BUILD SUCCESSFUL
DOES NOT VERIFY
ERROR: Missing META-INF/MANIFEST.MF
[ok] build-validation APK, not release-ready: ...\dist\AndroidVocabulary-release-v0.1.0-1.apk
```

这确认 `apksigner` stderr/stdout 捕获没有被 PowerShell 错误对象污染，且未签名 APK 仍被清晰标记为本地构建验证产物。

## 剩余风险

- 当前没有正式 release signing 环境，未验证 `[ok] release APK signature verified` 分支。
- 当前没有在线 Android 设备，未验证 APK 安装、启动 smoke。

## 下一轮建议

继续检查 `smoke-release-apk.ps1` 的非 capture ADB 调用。它们目前失败异常只有 exit code，若安装或启动失败，输出可能只留在控制台；可以考虑只对关键命令补充失败输出。
