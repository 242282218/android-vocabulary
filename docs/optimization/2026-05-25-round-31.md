# 2026-05-25 持续优化第 31 轮

## 当前审查范围

本轮审查导出 JSON 的学习事实口径，重点是 `reviewLogs` 是否与统计、队列一样排除已失去词书归属的孤儿日志。

## 发现

`ExportDao.reviewLogs()` 已经通过手写 `JOIN wordbook_memberships` 排除孤儿日志，行为正确；`AndroidExportRepositoryTest.exportUserDataExcludesOrphanReviewRows()` 也覆盖了这个场景。

但 v5 已经引入 `valid_review_logs` 作为统一 view，统计和第 27 轮的 due queue 困难度排序都已使用该 view。导出继续手写 join 虽然行为一致，但会制造重复 SQL，后续如果 valid log 口径变化，导出更容易改漏。

## 方案取舍

1. 把 `ExportDao.reviewLogs()` 改为读取 `valid_review_logs`。行为不变，减少重复 SQL，推荐采用。
2. 保持手写 join。短期无行为风险，但继续留下口径重复。
3. 改导出为包含原始 `review_logs` 和诊断报告。更适合未来高级备份/修复，不适合当前发布前稳定阶段。

本轮采用方案 1。

## 完成项

- `core/database/src/main/java/com/zzz/androidvocab/core/database/ExportDao.kt`
  - `reviewLogs()` 从手写 membership join 改为 `FROM valid_review_logs l`。
  - 排序和返回模型保持不变。
