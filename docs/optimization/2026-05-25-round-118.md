# 2026-05-25 持续优化第 118 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 的日志归档完整性。第 115-117 轮已经让 APK smoke 在首屏超时时写出：

```text
build\apk-smoke\last-window.xml
```

但该文件位于全局 build 目录，下一次 smoke 运行可能清理或覆盖它。

## 发现

`verify-device.ps1` 会把子步骤输出写入本次设备验收日志目录，例如：

```text
smoke-release-bundle.log
verification-failed.txt
```

但如果 AAB 安装后的 APK launch smoke 失败，并且 `smoke-release-apk.ps1` 生成了 UI dump，完整 XML 仍只留在全局 `build\apk-smoke`。设备验收归档缺少该文件，后续复盘只能依赖日志里的 excerpt。

## 方案

- 方案 A：任何失败都复制 `build\apk-smoke\last-window.xml`。实现简单，但可能复制上一轮陈旧文件。
- 方案 B：只在失败消息明确包含 `Last UI dump saved to:` 时复制该路径对应的文件，并在本次 metadata 中记录归档文件名。

本轮采用方案 B，避免把陈旧 dump 错归到本次验收。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Save-ApkSmokeFailureArtifacts`。
- 失败消息包含 `Last UI dump saved to:` 时，将对应 XML 复制到本次日志目录：


- `verification-run.txt` / `verification-failed.txt` / `verification-completed.txt` 新增：
