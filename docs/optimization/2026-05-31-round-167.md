# 第 167 轮：Settings 数据维护卡结果与失败分组分隔

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 上一轮已经补了：
    - `上次检查结果`
    - `本次操作失败`
    - `结果已保留`
  - 但在“旧结果 + 新失败”同时存在时，两段内容仍然直接相邻，缺少视觉边界。
- 设计约束要求界面保持克制，不做“卡中卡”式堆叠，也避免用过重装饰来制造区分。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 已有该状态下的 `SettingsScreen` 烟雾测试入口，因此本轮只需要保证编译链路不回退。

结论：当前问题已经从文案来源澄清，转到局部分组边界不够清晰。需要一个轻量、不引入新容器层级的分隔方式。

## 方案

- 方案 A：在旧结果与新失败之间加入细分隔线。
  - 优点：最小修改，直接建立分组边界，不引入新容器。
  - 缺点：区分力度不如整块背景。
- 方案 B：把旧结果包进单独浅色容器。
  - 优点：视觉分区最强。
  - 缺点：会形成“卡中卡”，不符合当前界面克制风格。

采用方案 A。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 引入 `HorizontalDivider`。
  - 仅当 `message` 和 `errorMessage` 同时存在时，在旧结果块和错误块之间插入一条轻分隔线。
  - 分隔线使用 `outlineVariant` 的半透明颜色，避免抢过正文和状态标签。
