# 2026-05-25 持续优化第 156 轮

## 当前审查范围

本轮接着第 155 轮，审查 release readiness 对设备 AAB smoke 子日志的信任边界。上一轮已让 `deviceBundleSmokeMetadata` 缺失时输出 `<missing>`，但 readiness 仍主要依赖设备父日志里的 bundle smoke 摘要字段。

## 发现

`verification-completed.txt` 中的 `bundleSmokeBundleSha256` 是父日志摘要。即使 readiness 已归档 `smoke-release-bundle-run.txt`，也没有独立读取归档后的子日志原文来交叉确认 `bundleSha256`、`runStatus`、`apkSetSigning` 等关键字段。

## 方案

- 方案 A：继续信任父日志摘要。改动少，但无法发现父日志摘要和子日志原文不一致。
- 方案 B：readiness 复制 bundle smoke 子日志后，读取归档后的 `evidence-smoke-release-bundle-run.txt`，独立校验关键字段。

本轮采用方案 B。它让 release readiness 以最终归档 evidence 为校验对象，避免源目录和归档目录不一致。

## 完成项

## 剩余风险

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，未验证真实设备验收 evidence 和 bundle smoke 子日志正向交叉校验。
- 目前 `deviceAabVerification` 把父日志和子日志校验合并在一个 requirement 中，失败原因会集中在一条记录里。

## 下一轮建议

继续审查 failure evidence 的可诊断性：把 bundle smoke 子日志原文校验拆成单独 requirement，失败时更容易区分父日志缺失、摘要不一致和子日志不一致。
