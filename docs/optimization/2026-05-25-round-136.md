# 2026-05-25 持续优化第 136 轮

## 当前审查范围

本轮接着第 135 轮，审查 smoke 脚本默认查找 `dist/AndroidVocabulary-release-v<versionName>-<versionCode>.*` 时，是否会误用历史遗留的 release 命名验证产物。

## 发现

APK smoke 在安装前已经执行 `apksigner verify`，历史未签名 APK 会被拦截。

AAB smoke 此前只校验 bundletool 生成的 APK Set 签名，没有先校验输入 AAB 本身。由于当前 `dist/` 中仍有历史 `AndroidVocabulary-release-v0.1.0-1.aab`，且该文件实际来自未签名本地验证链路，脚本存在把历史 release 命名 AAB 继续用于 bundletool smoke 的风险。

## 方案

- 方案 A：只在文档强调先跑 `build-bundle.ps1`。改动少，但脚本仍可能误报。
- 方案 B：在 `smoke-release-bundle.ps1` 解析 AAB 后、调用 bundletool 前，先用 `jarsigner -verify` 校验输入 AAB。

本轮采用方案 B。默认正式 smoke 必须通过 AAB 验签；只有显式 `-AllowDebugSigning` 时，才允许未验签 AAB 继续跑本地安装链路，并输出 `not release-ready`。
