# 第 217 轮：把 GitHub Actions release evidence 文档格式纳入脚本回归

## 审查证据

- `README.md`
  - GitHub Actions release evidence 示例仍是旧格式。
  - 缺少 `serverUrl`、`repository` 两个字段，也没说明 readiness 会校验这两个字段与 `runUrl` 的一致性。
- `docs/release.md`
  - 已经同步到新格式，示例和校验说明都齐全。
- `scripts/test/verify-release-scripts.ps1`
  - 目前会校验 writer、workflow 和 readiness 脚本结构，但不会检查 README / release 文档是否仍与真实 evidence 格式一致。

结论：当前风险不是门禁逻辑缺失，而是 README 已经和脚本真实输出漂移。发布时如果按 README 手工准备 `github-actions-evidence.txt`，会直接踩 readiness 门禁。

## 方案

- 方案 A：只修改 `README.md`
  - 优点：改动最小
  - 缺点：以后脚本再次变更时，README 仍可能重新漂移
- 方案 B：同步修 `README.md`，并把关键 evidence 示例格式加入 `verify-release-scripts.ps1` 回归
  - 优点：以后 README 或 `docs/release.md` 漂移会被脚本立即发现
  - 缺点：回归检查会多一条文档结构约束

采用方案 B。

## 修改

- 修改 `README.md`
  - 在 `github-actions-evidence.txt` 示例中补上：
    - `serverUrl=https://github.com`
    - `repository=<owner>/<repo>`
  - 新增说明：
    - `verify-release-readiness.ps1` 会校验 `serverUrl`、`repository`、`runId`、`runUrl` 一致性
    - 并要求 `serverUrl=https://github.com`
- 修改 `scripts/test/verify-release-scripts.ps1`
  - 新增 `Test-ReleaseReadinessDocumentation`
  - 断言 `README.md` 和 `docs/release.md` 都包含当前 GitHub Actions release evidence 的关键格式：
    - artifact 名称
    - `serverUrl` / `repository`
    - `runUrl`
    - 完整 `checks` 列表
    - `verify-release-readiness.ps1` 提示
  - 把该检查接入脚本主回归入口

## 验证

运行：

```powershell
. .\scripts\lib\android-env.ps1
Use-AndroidVocabularyJavaHome
.\scripts\test\verify-release-scripts.ps1
```

结果：通过，输出 `[ok] release script regression checks passed`。
