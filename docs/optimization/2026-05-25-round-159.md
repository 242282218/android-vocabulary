# 2026-05-25 持续优化第 159 轮

## 当前审查范围

本轮接着第 158 轮，审查 release readiness requirement evidence 的路径语义。上一轮已经让 `deviceBundleSmokeArchive` 的 `path` 指向 readiness 归档文件，但其他 requirement 仍只暴露源路径，归档文件和归档 hash 需要回看 metadata 字段。

## 发现

`releaseArtifacts`、`releaseApkSmoke`、`deviceAabVerification`、`deviceBundleSmokeArchive`、`githubActionsEvidence` 的 requirement evidence 各自表达源路径和核心摘要，但没有统一带上 readiness 归档文件名和归档 SHA-256。发布复核时，需要在 requirement 和独立 `*EvidenceArchive*` 字段之间人工关联。

## 方案

- 方案 A：把 requirement 的 `path` 全部改成归档路径。更贴近 readiness 最终证据，但会丢失源路径语义。
- 方案 B：保留原有 `path` 含义，同时追加 `archive` 和 `archiveSha256`。

本轮采用方案 B。它兼容既有字段语义，同时让每条 requirement 都自带可复核归档证据。
