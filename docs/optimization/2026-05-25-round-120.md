# 2026-05-25 持续优化第 120 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 的显式 `-ApkPath` 处理。默认路径已经按当前版本名查找 APK，但手动传入旧版本或非标准命名 APK 时没有提示，发布 smoke 记录容易混用旧产物。

## 发现

`smoke-release-bundle.ps1` 已经会在显式 `BundlePath` 不符合当前版本命名时给出 warning。`smoke-release-apk.ps1` 没有同类提示：

```powershell
.\scripts\test\smoke-release-apk.ps1 -ApkPath .\old-release.apk
```

这种用法可能是有意覆盖默认产物，但也可能是误用了旧 APK。脚本应提示风险，同时不阻止本地调试。

## 方案

- 方案 A：显式 APK 文件名不等于当前版本名时直接失败。最严格，但会影响本地排查旧包或第三方产物。
- 方案 B：只打印 warning，继续执行签名校验、安装和启动 smoke。保持调试灵活性，同时让发布记录中能看到覆盖行为。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 新增 `Warn-IfExplicitApkPathIsNotVersioned`。
- 仅当用户显式传入 `-ApkPath` 且文件名不是当前版本 APK 名时打印 warning。
- 默认 APK 查找、签名校验、安装和启动 smoke 行为不变。
