# 2026-05-25 持续优化第 115 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 的启动 smoke：安装后启动、进程检查、UI 首屏文本识别，以及失败时是否有足够证据定位首屏状态。

## 发现

审查和 fake adb 验证发现两个问题：

1. 脚本使用 `$pid` 保存应用进程号。PowerShell 变量大小写不敏感，`$PID` 是只读自动变量，因此脚本在启动后会报：

```text
Cannot overwrite variable PID because it is read-only or constant.
```

这会导致 APK smoke 在进程检查处错误失败。

2. 首屏文本超时时，脚本只把 UI dump excerpt 放进异常。单独运行 APK smoke 时没有独立归档完整 UI XML，后续排查系统弹窗、错误页或布局遮挡时证据不足。

## 方案

- 方案 A：重写首屏识别，增加 activity/window 解析。信息更多，但会扩大行为面，容易引入设备兼容问题。
- 方案 B：保留现有首屏文本和崩溃判断，只修复 `$PID` 冲突，并在首屏超时时保存最后一次 UI dump。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 将 `$pid` 改为 `$appProcessId`，避免覆盖 PowerShell 只读自动变量 `$PID`。
- 新增 `Save-LastWindowDump`。
- 首屏文本超时且存在 UI dump 时，保存到：

```text
build\apk-smoke\last-window.xml
```

- 异常信息保留 excerpt，并追加完整 UI dump 路径。

fake adb 成功路径通过：当 UI dump 包含 `Today` 时，脚本通过：

```text
EXIT_CODE=0
```
