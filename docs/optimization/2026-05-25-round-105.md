# 2026-05-25 持续优化第 105 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1` 在 AAB 安装完成后调用 `smoke-release-apk.ps1 -SkipInstall` 的失败传播是否可靠。

## 发现

父脚本原本直接执行：

```powershell
& (Join-Path $repoRoot 'scripts\test\smoke-release-apk.ps1') @smokeArgs
if ($LASTEXITCODE -ne 0) {
    throw "installed app launch smoke after bundle install failed with exit code $LASTEXITCODE"
}
```

本地实验确认：同一 PowerShell runspace 内调用脚本时，子脚本 `throw` 会直接中断父脚本，父脚本后续 `$LASTEXITCODE` 检查不一定执行，且 `$LASTEXITCODE` 可能仍是 0。

## 方案

- 方案 A：给直接调用包一层 `try/catch`。实现简单，但仍无法稳定获得子脚本进程级 exit code。
- 方案 B：用独立 PowerShell 子进程执行 `smoke-release-apk.ps1`，捕获 stdout/stderr 和 exit code，失败时把最后输出写进异常。语义更清楚，也和 bundletool 调用的诊断风格一致。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 新增 `Get-PowerShellExecutable`，优先使用当前 `$PSHOME` 下的 PowerShell 可执行文件。
- 新增 `Invoke-PowerShellScriptCommand`，以独立 PowerShell 子进程运行脚本，并捕获 stdout/stderr、exit code 和最后输出。
- AAB 安装后的 `smoke-release-apk.ps1 -SkipInstall` 复核改为通过 `Invoke-PowerShellScriptCommand` 调用。

## 验证结果

PowerShell 解析通过：

```powershell
parse-ok
```

目标脚本 whitespace 检查通过：

```powershell
git diff --check -- scripts/test/smoke-release-bundle.ps1
```

build-only 成功路径通过：

```powershell
.\scripts\test\smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning -BundlePath .\dist\AndroidVocabulary-release-v0.1.0-1.aab -ApksPath .\build\bundle-smoke\round105-debug-signing.apks
```

结果：

```text
[ok] APK Set: .\build\bundle-smoke\round105-debug-signing.apks
[ok] bundle smoke build-only passed; APK Set signing=debug-signing; not release-ready
```

独立 PowerShell 子进程调用 `smoke-release-apk.ps1` 的失败传播已验证：

```powershell
.\scripts\test\smoke-release-apk.ps1 -SkipInstall -DeviceSerial __NO_SUCH_DEVICE__
```

通过子进程捕获时结果为：

```text
exit=1
Device '__NO_SUCH_DEVICE__' is not online. Online devices: <none>.
```

这说明父脚本可以稳定拿到子脚本失败 exit code 和输出。

## 剩余风险

- 当前没有在线 Android 设备，未验证 AAB 安装后真实 `-SkipInstall` 首屏 smoke。
- 当前没有正式 release signing 环境，build-only 验证仍使用 `-AllowDebugSigning`。

## 下一轮建议

继续检查 `smoke-release-bundle.ps1 -ListDevices` 的委托路径。它目前仍直接调用 `smoke-release-apk.ps1 -ListDevices`，如果子脚本在环境缺失时抛错，父脚本也会遇到同一 runspace 失败传播问题。
