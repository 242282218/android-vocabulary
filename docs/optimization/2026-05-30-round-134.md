# 第 134 轮：复习天数跨度安全夹取

## 审查证据

- `core/common/src/main/java/com/zzz/androidvocab/core/common/DateMath.kt` 中 `daysBetween()` 和 `daysUntil()` 都通过 `ChronoUnit.DAYS.between(...)` 得到 Long 后直接 `toInt()`。
- `daysBetween()` 用于 `OfflineReviewRepository.submitFeedback()` 写入 `ReviewLog.elapsedDays`。
- `daysUntil()` 用于 `FsrsKotlinReviewScheduler.schedule()` 计算 `scheduledDaysAfter`。
- 极端日期跨度会在 `toInt()` 阶段溢出，然后再被 `coerceAtLeast(0)` 变成错误值。正常学习路径不应出现百万年跨度，但调度和日志字段属于核心不变量，边界转换应显式安全。

## 方案

- 方案 A：在 `core:common` 内部把 Long 天数统一夹到 `[0, Int.MAX_VALUE]` 后再转 Int，并补 common 单测。范围小，所有调用方自动受益。
- 方案 B：不改代码，只记录“业务日期不会这么大”。成本最低，但保留了隐式假设和错误窄化路径。

采用方案 A。

## 修改

- `core/common/src/main/java/com/zzz/androidvocab/core/common/DateMath.kt`
  - 新增内部 `toNonNegativeDayCount()`。
  - `daysBetween()` / `daysUntil()` 改为先夹取 Long 天数，再转 Int。
- `core/common/src/test/java/com/zzz/androidvocab/core/common/DateMathTest.kt`
  - 覆盖 null start、倒序日期、同日、超大日期跨度夹到 `Int.MAX_VALUE`。
