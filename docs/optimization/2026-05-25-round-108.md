# 2026-05-25 持续优化第 108 轮

## 当前审查范围

本轮审查发布构建脚本和本地验证脚本中的 Gradle 调用失败诊断。重点是失败异常是否保留最后输出，并避免 PowerShell 把 native stderr 包装成不可读的类型名。

## 发现

`build-release.ps1`、`build-bundle.ps1`、`verify-local.ps1` 原本直接调用 `gradlew.bat`，失败异常只包含 exit code。若上层日志截断，排查时需要回翻大量 Gradle 输出。

首次包装后，故意执行不存在的 Gradle task 发现部分 stderr 行被 PowerShell 表示为：

```text
System.Management.Automation.RemoteException
```

这些是空消息的 `ErrorRecord`，直接 `.ToString()` 会污染日志。

## 方案

- 方案 A：继续直接调用 Gradle，只依赖完整控制台日志。实现最少，但失败异常信息不足。
- 方案 B：增加公共 Gradle 调用包装，实时输出不变，失败时把最后 4000 字符写入异常；同时增加 native 输出对象转文本函数，清理 PowerShell `ErrorRecord` 噪声。

本轮采用方案 B。

## 完成项

`scripts/lib/android-env.ps1`

- 新增 `Get-AndroidVocabularyTextTail`。
- 新增 `ConvertTo-AndroidVocabularyOutputText`，把 `ErrorRecord` 优先转为真实错误消息；空消息错误记录保留为空行。
- 新增 `Invoke-AndroidVocabularyGradle`，统一执行 Gradle，实时输出并在失败异常中附带 `Last output`。

`scripts/release/build-release.ps1`

- release APK 构建改用 `Invoke-AndroidVocabularyGradle 'Release APK Gradle build'`。

`scripts/release/build-bundle.ps1`

- release AAB 构建改用 `Invoke-AndroidVocabularyGradle 'Release AAB Gradle build'`。
- `jarsigner` 捕获输出改用 `ConvertTo-AndroidVocabularyOutputText`。

`scripts/test/verify-local.ps1`

- 本地 Gradle 验证改用 `Invoke-AndroidVocabularyGradle 'Local Gradle verification'`。

`scripts/test/verify-device.ps1`、`scripts/test/smoke-release-apk.ps1`、`scripts/test/smoke-release-bundle.ps1`

- 现有 native stdout/stderr 捕获路径改用 `ConvertTo-AndroidVocabularyOutputText`，避免日志中出现 PowerShell 类型名。

- 本轮没有重跑 `build-release.ps1 -AllowUnsigned`，但 APK/AAB 两个脚本使用同一个 `Invoke-AndroidVocabularyGradle` 包装；AAB 成功路径已覆盖公共逻辑。
- 当前没有在线 Android 设备，设备验收相关捕获路径仍未跑真实安装和启动。
- 当前没有正式 release signing 环境，未验证正式签名分支。
