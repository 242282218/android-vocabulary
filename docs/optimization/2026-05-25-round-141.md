# 2026-05-25 持续优化第 141 轮

## 当前审查范围

本轮接着第 140 轮，审查 `verify-release-readiness.ps1` 中 GitHub Actions 证据是否过弱。第 140 轮只要求传入 evidence 文件，不能证明该文件对应当前提交、Android workflow、成功结论和完整质量门。

## 发现

`scripts/test/verify-release-readiness.ps1` 已经汇总 release artifacts、APK smoke、设备 AAB 验收和 CI 证据，但 CI 证据如果只按路径存在判断，人工发布时可能把旧提交、失败 workflow 或缺少 managed-device 检查的结果误当成可发布证据。

## 方案

- 方案 A：继续只要求 evidence 文件存在。改动最少，但证据语义太弱。
- 方案 B：把 evidence 约定为 key-value 文件，并要求字段匹配当前发布门禁。

本轮采用方案 B。它不依赖 GitHub API，也不引入网络和 token 前置条件，适合当前本地 release 门禁。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 读取 GitHub Actions evidence key-value 文件。
- 通过 `git rev-parse HEAD` 获取当前提交。
- 要求：
  - `workflow=Android`
  - `conclusion=success`
  - `commitSha=<当前 git HEAD>`
  - `checks` 包含 `verify-release-scripts`、`verify-vocab-assets`、`ktlintCheck`、`detekt`、`testDebugUnitTest`、`assembleDebug`、`assembleDebugAndroidTest`、`pixel2Api30DebugAndroidTest`
- metadata 写入 `currentCommitSha`、`githubActionsWorkflow`、`githubActionsConclusion`、`githubActionsCommitSha`、`githubActionsChecks`、`githubActionsRequiredChecks`。

`scripts/test/verify-release-scripts.ps1`

- 增加 readiness CI evidence 字段和必需检查项的源码结构回归断言，避免后续误删字段校验。

文档同步：

- `README.md` 增加 CI evidence 文件格式示例。
- `docs/release.md` 在发布前 checklist 中增加 CI evidence key-value 示例。

## 剩余风险

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，缺少正式设备 AAB 验收成功证据。
- CI evidence 仍是人工保存的本地文本文件；它已绑定当前提交和检查项，但不是由 GitHub API 自动下载。

## 下一轮建议

继续审查 GitHub Actions workflow 本身是否真的运行了 readiness 要求的检查项，避免本地 evidence schema 和 CI 实际 job 名称漂移。
