# 2026-05-25 持续优化第 58 轮

## 当前审查范围

本轮审查 `-AllowUnsigned`、`-AllowUnsignedBundle`、`-AllowDebugSigning` 这类本地验证参数的输出语义，重点是脚本是否可能把未签名或 debug signing 产物说成可发布产物。

## 发现

`build-release.ps1 -AllowUnsigned` 和 `build-bundle.ps1 -AllowUnsigned` 旧输出会先打印 warning，但最后仍打印：

```text
[ok] release APK: ...
[ok] release AAB: ...
```

这在复制局部日志时容易被误解为“产物可发布”。实际语义应是：编译链路通过，但 APK 不可安装发布，AAB 不可上传应用商店。

`smoke-release-bundle.ps1 -AllowDebugSigning` 旧输出在 build-only 成功后只写 `bundle smoke build-only passed`，也没有在最终 ok 行强调 debug signing 不能代表 release-ready。

## 完成项

`scripts/release/build-release.ps1`

- 保存 `apksigner verify` 结果到 `$signatureVerified`。
- 只有正式验签通过时才打印 `[ok] release APK: ...`。
- `-AllowUnsigned` 下验签失败时，最终输出改为：

```text
[ok] build-validation APK, not release-ready: ...
```

`scripts/release/build-bundle.ps1`

- 只有 `jarsigner` 验签通过时才打印 `[ok] release AAB: ...`。
- `-AllowUnsigned` 下验签失败时，最终输出改为：

```text
[ok] build-validation AAB, not uploadable: ...
```

`scripts/test/smoke-release-bundle.ps1`

- 记录本次是否使用 debug signing。
- `-BuildOnly -AllowDebugSigning` 成功时输出：

```text
[ok] bundle smoke build-only passed with debug signing; not release-ready
```

- 非 build-only 模式如果用 debug signing 成功，也输出 `not release-ready`。
