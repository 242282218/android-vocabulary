# 2026-05-25 持续优化第 153 轮

## 当前审查范围

本轮接着第 152 轮，审查 release readiness 归档文件是否便于离线复核。上一轮已经把设备验收父日志和 bundle smoke 子日志复制到 `build/release-readiness/evidence-*.txt`，但 metadata 只记录归档文件名，没有记录归档文件自身 hash。

## 发现

如果 `build/release-readiness/evidence-*.txt` 后续被覆盖或手工改写，`release-readiness-run.txt` 里没有直接可比对的归档文件 SHA-256。发布记录仍能保留文件，但复核成本较高。

## 方案

- 方案 A：继续只记录归档文件名。改动少，但离线复核需要重新信任目录内容。
- 方案 B：对每个 readiness 归档文件记录自身 SHA-256；缺失时写 `<missing>`。

本轮采用方案 B。它不改变 release readiness 判定逻辑，只增强发布证据的可复核性。

## 剩余风险

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，未验证真实设备验收 evidence 和 bundle smoke 子日志正向归档 hash。
- readiness 会记录归档 hash，但还没有把归档文件集合清单作为单独字段输出，人工核对仍需看多行 metadata。

## 下一轮建议

继续审查 release readiness 输出的可读性：增加一个 `evidenceArchives=` 汇总清单，列出每个归档名及 SHA-256，减少人工发布复核遗漏。
