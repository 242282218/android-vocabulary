# 2026-05-25 持续优化第 130 轮

## 当前审查范围

本轮接着第 129 轮，审查 `verify-device.ps1` 的失败阶段分类是否会被 `Invoke-LoggedStep` 的错误包装影响。

## 发现

`Invoke-LoggedStep` 会把子脚本失败包装成：

```text
<step> failed. See <log>. Cause: <原始错误>
```

因此 `Resolve-FailureStage` 必须同时支持外层步骤名和内层错误文本。当前实现的优先级是先识别更具体的内部错误，例如 `bundletool build-apks failed`、`installed app launch smoke after bundle install failed`，再回退到 `smokeReleaseBundle`、`buildReleaseBundle`、`connectedDebugAndroidTest`。

## 方案

- 方案 A：继续只靠真实设备失败验证。覆盖真实，但当前没有在线设备，不适合本轮。
- 方案 B：抽取脚本中的 `Resolve-FailureStage` 函数，用函数级样例验证优先级和 fallback。

本轮采用方案 B。

## 完成项
