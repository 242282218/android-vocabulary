# 第 188 轮：按 selectedBooks 统一 Today 页队列、完成数与预计时长的作用域

## 审查证据

- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetTodayOverviewUseCase.kt`
  - Today 队列来自 `reviewRepository.observeTodayQueue(now, settings.selectedBooks, settings.dailyNewLimit)`，已经按当前词书筛选。
  - 但本轮开始前，今日统计和平均耗时没有显式接收 `selectedBooks`。
- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - `observeTodayStats()` 和 `observeAverageReviewDurationMs()` 之前都按全量日志聚合。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeDailyStatsFromLogs()` / `observeAverageDurationMs()` 之前没有词书过滤条件。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/DailyStatsCacheRebuildTest.kt`
  - 新增按词书 SQL 回归后，暴露出另一处根因：我初版把“新学数”改成了 `elapsedDays IS NULL`，但项目真实口径一直是 `first_reviews.firstLogId = l.id`。

结论：问题不止是“缺少 selectedBooks 过滤”，还包括“按词书统计 SQL 和 `review_daily_stats` 视图的判新词口径漂移”。如果只补过滤，不统一口径，Today 页的已学新词数和剩余新词额度仍会错。

## 方案

- 方案 A：页面层对全量统计做减法修补。
  - 优点：表面改动少。
  - 缺点：复制统计规则，Today/Stats/数据库真值会继续分叉。
- 方案 B：让 `StatsRepository -> StatsDao` 显式接收 `selectedBooks`，把过滤下推到仓储和 SQL，并确保 SQL 口径与 `review_daily_stats` 一致。
  - 优点：作用域和统计口径都统一，Today 队列、完成数、预计时长使用同一事实域。
  - 缺点：要同步改接口、测试桩和数据库级回归。

采用方案 B。

## 修改

- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/Repositories.kt`
  - `StatsRepository.observeTodayStats()`、`observeAverageReviewDurationMs()` 新增 `selectedBooks` 参数。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/GetTodayOverviewUseCase.kt`
  - 把 `settings.selectedBooks` 下传到今日统计和平均耗时查询，统一队列与统计的作用域。
- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - `observeTodayStats()`、`observeAverageReviewDurationMs()` 显式接收 `selectedBooks`，为空时退化为“全部词书”。
  - `observeTodayStats()` 里 `dueCount` 也改为使用传入的 `selectedBooks`，不再偷偷回读 settings。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeDailyStatsFromLogs()`、`observeAverageDurationMs()` 新增 `bookCodes` 过滤。
  - `observeDailyStatsFromLogs()` 的“新学数/复习数”计算改回与 `review_daily_stats` 一致的 `first_reviews` 口径，避免 `elapsedDays` 判定漂移。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - Today 新词额度计算依赖的“今天已学新词数”改为按同一组 `bookCodes` 查询，避免词书筛选切换时串 scope。
- `core/domain/src/test/java/com/zzz/androidvocab/core/domain/UseCasesTest.kt`
  - 新增 `todayOverviewUsesSelectedBooksForStatsAndAverageDuration()`，锁定 domain 层参数下传。
- `core/stats/src/test/java/com/zzz/androidvocab/core/stats/OfflineStatsRepositoryTest.kt`
  - 新增 `todayStatsAndAverageDurationUseSelectedBooks()`，锁定仓储层会把 `selectedBooks` 下推到 DAO。
  - 补齐 `FakeStatsDao` 新接口和观测字段。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/DailyStatsCacheRebuildTest.kt`
  - 适配 DAO 新签名。
  - 新增 `todayStatsQueriesFilterSelectedBooks()`，直接用真实 Room SQL 验证按词书过滤后的 `TodayStats` 和平均耗时。
- `feature/today/src/test/java/com/zzz/androidvocab/feature/today/TodayViewModelTest.kt`
- `feature/stats/src/test/java/com/zzz/androidvocab/feature/stats/StatsViewModelTest.kt`
  - 同步 `StatsRepository` 测试桩签名。
