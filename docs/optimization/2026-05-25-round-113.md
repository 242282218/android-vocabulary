# 2026-05-25 持续优化第 113 轮

## 当前审查范围

本轮继续审查设备验收脚本的失败可追溯性，重点检查 `verify-device.ps1` 调用 AAB smoke 子脚本时的参数绑定是否可靠。

## 发现

上一轮新增了失败态元数据：

```text
verification-failed.txt
runStatus=failed
failureMessage=...
```

但 fake adb 验证暴露出新的根因问题：`verify-device.ps1` 使用字符串数组 splatting 调用 `smoke-release-bundle.ps1` 时，命名参数可能被位置绑定误解析。复现命令传入：

```powershell
.\scripts\test\verify-device.ps1 -DeviceSerial FAKE113 -SkipConnectedTests -SkipBundleBuild -BundlePath .\missing-round113.aab -LogDir <dir>
```

实际错误却是：

```text
Device '-BundlePath' is not online. Online devices: FAKE113.
```

这说明 `-BundlePath` 被当成了 `DeviceSerial`，失败原因偏离真实问题。

## 方案

- 方案 A：继续用字符串数组，调整数组顺序或脚本参数顺序。改动小，但仍依赖位置绑定细节，后续新增参数容易再次误绑。
- 方案 B：改用 hashtable splatting，以参数名绑定脚本参数。行为更明确，能避免脚本参数顺序变化影响调用方。

本轮采用方案 B，只修改 `verify-device.ps1` 内部对 PowerShell 子脚本的同进程调用边界。

## 完成项

`scripts/test/verify-device.ps1`

- `build-release-bundle` 子步骤从字符串数组参数改为 hashtable splatting。
- `smoke-release-bundle` 子步骤从字符串数组参数改为 hashtable splatting。
- `DeviceSerial`、`BundlePath` 和开关参数均显式按参数名转发，避免 `-BundlePath` 被误当成设备序列号。

## 验证结果

fake adb 缺失 AAB 失败路径已回归：

```powershell
.\scripts\test\verify-device.ps1 `
  -DeviceSerial FAKE113 `
  -SkipConnectedTests `
  -SkipBundleBuild `
  -BundlePath .\missing-round113.aab `
  -LogDir <dir>
```

结果符合预期：

```text
Cause: Cannot find path '.\missing-round113.aab' because it does not exist.
```

并写出失败态元数据：

```text
runStatus=failed
bundlePathStatus=missing
failureMessage=smoke-release-bundle failed...
```
