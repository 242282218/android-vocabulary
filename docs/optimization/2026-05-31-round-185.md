# 第 185 轮：修复 Review 提交后刷新窗口被误报为“今天已完成”

## 审查证据

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 上一轮已加入 `submittedCardId`，提交成功后会先本地隐藏刚提交的旧卡。
  - 当队列流暂时还只含这张旧卡时，`item == null`，但这并不等于真正完成，只是等待下一张或等待队列刷新。
- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewRoute.kt`
  - 之前逻辑只要 `item == null` 就直接渲染“今天已完成”。
  - 这会把提交成功后的短暂刷新窗口误报成完成态，主学习路径上会出现错误反馈。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 之前只锁定了“旧卡被隐藏”和“有下一张时切到下一张”。
  - 缺少“等待刷新时不能冒充完成态”和“真正离队后才进入完成态”的测试。

结论：需要在 Review 会话态里显式区分“真实完成”和“正在推进到下一张”。

## 方案

- 方案 A：增加 `isAdvancingToNextCard` 状态，让 UI 渲染一个过渡态。
  - 优点：最小改动，语义准确，不伪造队列数据。
  - 缺点：需要补状态测试和一个额外 UI 分支。
- 方案 B：本地 optimistic 推断下一张或剩余数，直接跳过刷新窗口。
  - 优点：视觉更连贯。
  - 缺点：容易和真实仓库队列偏离，风险更高，不适合当前数据正确性优先阶段。

采用方案 A。

## 修改

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - `ReviewUiState` 新增 `isAdvancingToNextCard`。
  - 当 `submittedCardId` 仍在队列里、但可见队列已经为空时，标记为“正在推进到下一张”。
  - 只有提交过的旧卡真正离开队列后，才清空这个过渡态。
- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewRoute.kt`
  - 新增“正在准备下一张”过渡卡片和 header 文案。
  - 避免在刷新窗口里误报“今天已完成”。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - `submittedCardIsHiddenWhileQueueStillContainsStaleEntry()` 现在锁定 `isAdvancingToNextCard == true`。
  - `nextCardAppearsEvenIfQueueRefreshStillContainsSubmittedCardFirst()` 现在锁定切到下一张后过渡态会退出。
  - 新增 `completionStateWaitsUntilSubmittedCardActuallyLeavesQueue()`，锁定只有旧卡真正离队后才进入完成态。
