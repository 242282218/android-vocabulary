# 2026-05-25 持续优化第 35 轮

## 当前审查范围

本轮审查发布词库校验脚本，重点确认 `sources.json` 不只是随包存在和 hash 匹配，还能被 App 按 UTF-8 正常解析，并保留发布阻断来源的合规元数据。

## 发现

`verify-vocab-assets.ps1` 已经校验了 publish manifest、词书数量、hash、`sourcesHash`、`assetFingerprint` 和词条中的 publish-blocking `sourceFlags`。但对 `sources.json` 只做了存在和 hash 校验，没有实际解析 JSON，也没有检查 publish-blocking 来源元数据。

这意味着如果有人同时更新 `sourcesHash` 和一个结构损坏的 `sources.json`，脚本仍可能通过；App 首次导入时才会在解析来源说明时失败。发布阶段应在构建前拦住这种问题。

## 完成项

`scripts/test/verify-vocab-assets.ps1`

- 用显式 UTF-8 读取 `sources.json` 后实际执行 `ConvertFrom-Json`。
- 校验 `generatedAt` 和 `sources` 列表存在。
- 校验每个来源至少包含 `name`、`url`、`license`、`licenseStatus`、`redistributable`、`publishBlocking`、`notes`。
- 校验 `KyleBing/english-vocabulary` 与 `exam-data/NETEMVocabulary` 仍作为 publish-blocking 来源保留。
- 校验 publish-blocking 来源不能标记为 `redistributable=true`，且必须保留 `reviewAction`。
- 继续使用 UTF-8 正文计算 `sourcesHash`，避免 PowerShell 默认编码影响中文 JSON。
