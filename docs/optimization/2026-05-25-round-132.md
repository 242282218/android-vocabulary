# 2026-05-25 持续优化第 132 轮

## 当前审查范围

本轮接着第 131 轮，审查 `verify-release-scripts.ps1` 是否应接入默认本地验证和 GitHub Actions，并处理接入 CI 前的跨平台脚本前提。

## 发现

`verify-release-scripts.ps1` 不需要真机，运行时间短，适合成为默认质量门。但直接接入 Ubuntu CI 前有几个 Windows 假设：

- `android-env.ps1` 只识别 `bin\java.exe`。
- Gradle wrapper 只查 `gradlew.bat`。
- `jarsigner` 只查 `jarsigner.exe`。
- `smoke-release-bundle.ps1` 启动 bundletool 时硬编码 `bin\java.exe`。
- `verify-device.ps1` 的 `connectedDebugAndroidTest` 仍硬编码 `gradlew.bat`。
- 新增回归脚本的 fake ADB 只生成 `adb.bat`。

## 方案

- 方案 A：只接入 `verify-local.ps1`，暂不进 CI。风险较小，但 CI 不能防止发布脚本回归。
- 方案 B：修复共享脚本的跨平台工具解析，再同时接入 `verify-local.ps1` 和 GitHub Actions。

本轮采用方案 B。
