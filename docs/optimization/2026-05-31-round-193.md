# 第 193 轮：收紧 Settings 提醒卡片的关闭态，避免把次级时间配置挤进首屏

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `ReminderCard` 之前无论提醒是否开启，都会直接渲染 `ReminderTimeStepper`。
  - 关闭提醒时，卡片首屏仍然出现“小时 / 分钟”两组 stepper，主决策和次级配置混在一起。
  - 同时卡片顶部文案仍然显示具体时间，容易让关闭态误读成仍然生效。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 已有提醒缺权限、系统通知关闭、数据维护失败等断言，但还没有覆盖“提醒关闭时应保持紧凑”的状态。
- `D:\PROJECT_ZZZZZZZZZ\设计美学研究\packages\mobile-design-knowledge\rules\small-screen-layout.md`
  - 小屏单屏只承载一个主要决策；二级信息应渐进披露，而不是和主任务抢同一屏。
- `D:\PROJECT_ZZZZZZZZZ\设计美学研究\packages\mobile-design-knowledge\rules\mobile-forms-and-states.md`
  - 权限和关闭状态必须说明原因、影响和下一步；提交/配置 UI 不能在无效状态下继续堆满首屏。
- `D:\PROJECT_ZZZZZZZZZ\设计美学研究\packages\design-core\principles\motion-and-state.md`
  - 状态切换的核心是解释当前可操作范围；关闭态不该继续暴露一整块当前无效的配置控件。

结论：提醒卡片之前的问题不是缺少信息，而是关闭态信息过多。用户当前只需要决定“开或关”，不需要在关闭态立即面对完整的时间 stepper。

## 方案

- 方案 A：保留当前布局，只把 stepper 灰掉。
  - 优点：改动最小。
  - 缺点：无效控件仍然占首屏，密度问题没解决，只是从“可操作噪音”变成“禁用噪音”。
- 方案 B：关闭提醒时隐藏时间 stepper，只保留状态摘要和计划时间；开启后再展开时间配置。
  - 优点：主决策更清楚，首屏更克制，符合移动端渐进披露。
  - 缺点：调整时间多一步前置条件，必须先开启提醒。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 提醒时间摘要改为通过 `formatReminderSummary()` 生成：
    - 开启时：`每日 07:30`
    - 关闭时：`开启后按 07:30 提醒`
  - `ReminderTimeStepper` 改为只在 `settings.reminderEnabled == true` 时渲染。
  - 保留权限拒绝 / 系统通知关闭的恢复路径逻辑，不把已有错误恢复能力藏掉。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 新增 `settingsScreenKeepsReminderOffStateCompact()`：
    - 断言关闭态显示 `已关闭`
    - 断言显示 `开启后按 07:30 提醒`
    - 断言不再渲染 `小时 减少` stepper 控件
    - 断言关闭态不会无故出现 `打开通知设置`
