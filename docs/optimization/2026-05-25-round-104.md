# 2026-05-25 持续优化第 104 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1` 的 bundletool 调用在失败时是否能保留足够诊断信息，并能被 `verify-device.ps1` 的日志归档路径完整记录。

## 发现

`smoke-release-bundle.ps1` 原本直接调用：

```powershell
& (Join-Path $env:JAVA_HOME 'bin\java.exe') @bundleToolJavaArgs @buildApksArgs
if ($LASTEXITCODE -ne 0) {
    throw "bundletool build-apks failed with exit code $LASTEXITCODE"
}
```

控制台能看到 bundletool 输出，但异常本身只有 exit code。单独运行时还可以从控制台回看；被设备验收脚本包装后，如果日志截断或只看异常文本，失败原因不够直接。

## 方案

- 方案 A：保持直接调用，只依赖外层 `Invoke-LoggedStep` 日志文件。实现最少，但异常文本仍不自带 bundletool 失败原因。
- 方案 B：新增局部 `Invoke-BundleToolCommand`，实时输出 bundletool 日志，同时捕获 stdout/stderr，失败时在异常里带最后 3000 字符。影响面集中，诊断更直接。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 新增 `Get-TextTail`，限制失败异常中的输出长度。
- 新增 `Invoke-BundleToolCommand`，统一执行 bundletool `build-apks` 和 `install-apks`。
- bundletool 输出现在先转成纯字符串，再进入 `Tee-Object`，避免 PowerShell 把 native stderr 渲染成 `java.exe : ... NativeCommandError` 外壳。
- `build-apks` / `install-apks` 失败时异常包含 exit code 和 `Last output`。

`scripts/test/verify-device.ps1`

- `Invoke-LoggedStep` 写日志前也把对象转成字符串，避免归档日志混入 PowerShell 错误对象格式。
