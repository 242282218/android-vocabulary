# 2026-05-25 持续优化第 98 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 在默认构建 AAB 时，`verification-run.txt` 中的 AAB 路径状态是否足够准确。

## 发现

第 79 轮新增了 `bundlePathStatus`。当前逻辑在运行开始时写入 `verification-run.txt`：

- 默认路径存在：`exists`
- 默认路径不存在且未跳过构建：`willBeBuilt`
- 跳过构建但默认路径不存在：`missing`

这是运行开始时的计划状态，而不是运行结束后的最终状态。如果 `verify-device.ps1` 使用默认路径且先执行 `build-release-bundle`，构建完成后实际 AAB 已存在，但 `verification-run.txt` 仍会显示 `willBeBuilt`。

这不是执行错误，但发布归档语义偏弱：读者需要结合 `build-release-bundle.log` 才能知道最终是否生成了 AAB。

## 方案

- 方案 A：保留 `bundlePathStatus` 作为启动时状态，新增 `bundlePathStatusAtStart` / `bundlePathStatusAfterBuild` 会更准确，但需要在构建后重写元数据。
- 方案 B：当前不改代码，只记录语义边界。因为 `verify-device.ps1` 的成功条件已经依赖 `build-release-bundle` 和 `smoke-release-bundle` 都通过，`willBeBuilt` 不会单独作为成功证据。

本轮先采用方案 B，不改代码。第 99 轮继续实现启动态和完成态元数据拆分。

## 剩余风险

- 当前没有在线 Android 设备，未实测带构建的完整设备验收成功路径。
- 当前没有正式 release signing 环境，未验证正式 AAB 安装级 smoke。
