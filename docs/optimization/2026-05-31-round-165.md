# 第 165 轮：Settings 数据维护结果与失败分层表达

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `DataMaintenanceCard()` 会同时渲染 `message` 和 `errorMessage`。
  - `DataMaintenanceMessage()` 只显示 “需要处理 / 状态正常” 和正文。
  - `DataMaintenanceError()` 固定标题为 “处理失败”。
- 前两轮已把状态机改成：失败时保留旧 `report/message`，因此现在确实会出现“上次检查结果 + 本次失败提示”并存的合法状态。
- 现状问题是：用户能看到两段内容，但界面没有说明 `message` 是“上次检查结果”，容易误解成刚刷新出的结果。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 已有 `SettingsScreen` 的窄屏烟雾测试入口，适合补一条文案层验证，不需要引入新测试支架。

## 方案

- 方案 A：保持现状，只同时显示结果和失败。
  - 优点：零改动。
  - 缺点：结果来源不明确，用户容易把旧诊断误判成最新状态。
- 方案 B：当 `message` 和 `errorMessage` 同时存在时，把结果标成“上次检查结果”，把错误标成“本次操作失败”。
  - 优点：信息结构清楚，改动只在文案层，不动状态机。
  - 缺点：界面会多两行提示，但密度仍可控。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - `DataMaintenanceMessage()` 增加 `isStale` 参数；当存在错误提示时，在结果上方显示 “上次检查结果”。
  - `DataMaintenanceError()` 增加 `hasPreviousResult` 参数；当页面仍显示旧结果时，把错误标题改成 “本次操作失败”。
  - `DataMaintenanceCard()` 负责把这两个状态传下去，不改底层状态模型。
- `app/src/androidTest/java/com/zzz/androidvocab/ScreenLayoutSmokeTest.kt`
  - 新增 `settingsScreenSeparatesPreviousMaintenanceResultFromCurrentFailure()`。
  - 补 `fakeSettingsUiState(dataMaintenance = ...)`，验证窄屏下 “上次检查结果 / 本次操作失败 / 学习数据修复失败：disk full” 同时可见。
