# 2026-05-25 持续优化第 95 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1` 的默认 AAB 选择逻辑，判断是否应像 APK smoke 一样回退到 Gradle 输出目录。

## 发现

`smoke-release-bundle.ps1` 当前默认只查找：

```text
dist\AndroidVocabulary-release-v<versionName>-<versionCode>.aab
```

找不到时会列出 `dist` 和 `app\build\outputs\bundle\release` 中现有 AAB，并提示传 `-BundlePath` 或先运行 `build-bundle.ps1`。

本机当前状态：

- `dist\AndroidVocabulary-release-v0.1.0-1.aab` 存在。
- `dist\app-release.aab` 作为历史本地产物仍存在。
- `app\build\outputs\bundle\release\app-release.aab` 存在。

如果默认回退到 Gradle 输出目录的 `app-release.aab`，会绕过 `build-bundle.ps1` 的版本化归档和签名验证记录，削弱发布链路可追溯性。

## 方案

- 方案 A：保持默认只验证 `dist` 中当前版本化 AAB；需要验证其他 AAB 时显式传 `-BundlePath`。发布链路更清晰。
- 方案 B：像 APK smoke 一样回退到 Gradle 输出目录。更方便本地调试，但容易把未归档、未验签的 `app-release.aab` 当成发布验收对象。

本轮采用方案 A，不改脚本逻辑。

## 完成项

`README.md`

- 补充说明默认 AAB smoke 只查找版本化 `dist` AAB。
- 需要验证其他 AAB 时，应显式传 `-BundlePath`。

## 验证结果

源码与文档引用检查：

```powershell
rg -n "Get-DefaultBundle|No AAB found for current version|Available AABs|Pass -BundlePath|build-bundle|BundlePath|app-release\.aab|版本化 AAB|正式上传" scripts/test/smoke-release-bundle.ps1 docs/release.md README.md docs/optimization/2026-05-25-round-94.md -S
```

结果：默认 AAB 选择、缺失提示、显式 `-BundlePath` 和版本化 AAB 说明均可定位。

当前 `dist` AAB 检查：

```powershell
Get-ChildItem .\dist -Filter '*.aab' -File -ErrorAction SilentlyContinue | Select-Object Name,FullName,Length,LastWriteTime
```

结果：存在版本化 AAB 和历史 `app-release.aab`；文档与脚本默认路径均指向版本化 AAB。

当前 Gradle bundle 输出检查：

```powershell
Get-ChildItem .\app\build\outputs\bundle\release -Filter '*.aab' -File -ErrorAction SilentlyContinue | Select-Object Name,FullName,Length,LastWriteTime
```

结果：存在 `app-release.aab`，但默认 smoke 不会隐式使用它。

## 剩余风险

- 当前没有在线 Android 设备，未验证 AAB 安装级 smoke。
- 当前没有正式 release signing 环境，当前版本化 AAB 仍是 build-validation 产物，不是可上传 AAB。

## 下一轮建议

继续审查 `smoke-release-bundle.ps1` 的 `-BundlePath` 显式路径行为：是否应在显式传入非版本化 `app-release.aab` 时输出 warning，提醒它不是默认发布归档产物。
