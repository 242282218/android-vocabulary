# 第 205 轮：修正 submitFeedback 的 ReviewLog → FSRS → ReviewCard 顺序

## 审查证据

- `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - 原实现顺序是：
    1. `prepareReviewResult()` 里先调用 `scheduler.schedule(...)`
    2. 再 `insertLog(...)`
    3. 再 `upsertCard(...)`
  - 这和项目数据不变量“先写 `ReviewLog`，再计算 FSRS，最后更新 `ReviewCard`”冲突。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryStatsAndRollbackTest.kt`
  - 原测试只覆盖了 `insertLog` 在 `upsertCard` 之前，没有覆盖 scheduler 调用点。
- `core/model/src/main/java/com/zzz/androidvocab/core/model/ReviewModels.kt`
  - `ReviewLog` 当前同时承载事实字段和 scheduler after-snapshot 字段，因此不能简单把插入顺序前移，否则会丢失 replay/repair 依赖的 snapshot。

## 方案

- 方案 A：把不变量收紧成“先持久化日志，再写卡片”，接受 scheduler 仍发生在日志插入前
  - 优点：改动最小
  - 缺点：没有修正真正的顺序冲突，只是解释口径变化
- 方案 B：两阶段日志
  - 做法：
    1. 先插入一条 fact-first `ReviewLog`，after-snapshot 字段为空
    2. 再计算 FSRS
    3. 在同一事务内把同一条日志补全 snapshot 字段
    4. 最后更新 `ReviewCard`
  - 优点：把实现推进到真实不变量，同时保留 snapshot replay 能力和单条最终日志结构
  - 缺点：需要给 `ReviewDao` 增加日志更新接口，并补顺序测试

采用方案 B。

## 修改

- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/ReviewDao.kt`
  - 新增 `updateLog(log: ReviewLogEntity)`
- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - 把 `submitFeedback()` 改成两阶段：
    1. `preparePendingReviewLog(...)`
    2. `insertLog(...)`
    3. `scheduleReviewResult(...)`
    4. `updateLog(...)` 用 scheduler 结果补全 snapshot
    5. `upsertCard(...)`
  - 新增 `PENDING_REVIEW_LOG_ALGORITHM_VERSION = "<pending>"`
  - 新增 `ReviewLog.applyScheduleSnapshot(...)`
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryTestSupport.kt`
  - 给测试 DAO 代理补 `updateLog(...)`
  - 新增 `OperationRecordingScheduler`
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryStatsAndRollbackTest.kt`
  - 将顺序测试升级为覆盖：
    - `insertLog`
    - `schedule`
    - `updateLog`
    - `upsertCard`
  - 追加断言：最终落库日志已从 `<pending>` 收敛到真实 `algorithmVersion`，且 `stateAfter` / `dueAtAfter` 已写回
