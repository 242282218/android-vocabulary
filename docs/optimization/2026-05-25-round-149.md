# 2026-05-25 持续优化第 149 轮

## 当前审查范围

本轮接着第 148 轮，审查 APK smoke evidence 输入是否可追溯。第 148 轮已经让设备验收 evidence 可显式指定，但 `verify-release-readiness.ps1` 仍固定读取 `build/apk-smoke/smoke-release-apk-run.txt`。

## 发现

如果正式 APK smoke 后又运行了其他 APK smoke，固定 metadata 文件可能被覆盖。虽然 readiness 会校验 `apkSha256`、版本和当前 release APK hash，但正式发布证据链仍应能显式指向本次保留的 APK smoke metadata。

## 方案

- 方案 A：继续读取默认 `build/apk-smoke/smoke-release-apk-run.txt`。兼容性最好，但证据输入不可显式固定。
- 方案 B：增加 `-ApkSmokeEvidencePath`，未传时保留默认路径；正式发布文档要求显式传入本次 `smoke-release-apk-run.txt`。

本轮采用方案 B。它保持现有默认行为，同时提升正式发布证据可追溯性。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 新增参数 `-ApkSmokeEvidencePath`。
- 新增 `Get-ApkSmokeMetadataPath`：
  - 未传参数时沿用默认 `build/apk-smoke/smoke-release-apk-run.txt`。
  - 传入参数时解析该路径；不存在时保留未解析绝对路径，便于失败 metadata 指向用户输入。
- readiness metadata 增加：
  - `apkSmokeEvidenceMode=default|explicit`
  - `apkSmokeEvidenceInput=<default>|<path>`

`scripts/test/verify-release-scripts.ps1`

- 增加源码结构回归断言，锁定显式 APK smoke evidence 参数、路径解析和 metadata 字段。

文档同步：

- `docs/release.md`
