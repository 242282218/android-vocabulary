# 2026-05-25 持续优化第 92 轮

## 当前审查范围

本轮审查 `build-bundle.ps1` 的 AAB 选择逻辑，确认 Gradle 输出目录存在残留文件时不会误阻断发布构建。

## 发现

`bundleRelease` 当前实际输出为：

```text
app\build\outputs\bundle\release\app-release.aab
```

旧逻辑要求该目录中恰好只有一个 `.aab`：

```powershell
$bundleFiles = Get-ChildItem -Path $bundleDir -Filter '*.aab' -File
if ($bundleFiles.Count -ne 1) { ... }
```

这对干净目录没问题，但如果输出目录中残留历史 AAB 或人工放入的诊断文件，脚本会误阻断。发布脚本不应按时间猜测，也不应因为无关残留拒绝当前 Gradle 标准输出。

## 方案

- 方案 A：精确选择 Gradle 标准输出 `app-release.aab`，其他 `.aab` 只 warning。改动小，不引入时间排序猜测。
- 方案 B：构建前清理整个 bundle 输出目录。也能解决残留，但会删除本地诊断证据，破坏性更强。

本轮采用方案 A。

## 完成项

`scripts/release/build-bundle.ps1`

- 精确查找 `app\build\outputs\bundle\release\app-release.aab`。
- 如果该文件缺失，列出当前可用 AAB。
- 如果存在额外 `.aab`，输出 warning 并忽略。
- 归档到 `dist\AndroidVocabulary-release-v<versionName>-<versionCode>.aab` 的行为不变。
