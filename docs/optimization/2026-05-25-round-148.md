# 2026-05-25 持续优化第 148 轮

## 当前审查范围

本轮接着第 147 轮，审查最终 readiness 门禁的设备验收证据输入是否可追溯。上一轮已经让 `verify-release-readiness.ps1` 校验父级设备验收 metadata 和归档 bundle smoke 子日志的 AAB hash，但设备验收证据文件仍由脚本自动选择最新 `verification-completed.txt`。

## 发现

当 `build/device-verification/` 下存在多次设备验收日志时，自动选择最新记录可能不是本次 release checklist 中保留的那次验收。虽然 hash 和版本校验能过滤一部分错误记录，但正式发布证据链仍应能显式指定本次验收文件。

## 方案

- 方案 A：继续自动选择最新 `verification-completed.txt`。兼容性最好，但正式发布时可追溯性弱。
- 方案 B：增加 `-DeviceVerificationEvidencePath`，未传时保留自动选择最新记录；正式发布文档要求显式传入本次 `verification-completed.txt`。

本轮采用方案 B。它不破坏已有用法，同时让正式发布路径固定证据文件。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 新增参数 `-DeviceVerificationEvidencePath`。
- 新增 `Get-DeviceVerificationMetadataPath`：
  - 未传参数时沿用最新 `verification-completed.txt`。
  - 传入参数时解析该路径；不存在时保留未解析绝对路径，便于失败 metadata 指向用户输入。
- readiness metadata 增加：
  - `deviceVerificationEvidenceMode=latest|explicit`
  - `deviceVerificationEvidenceInput=<latest>|<path>`

`scripts/test/verify-release-scripts.ps1`

- 增加源码结构回归断言，锁定显式设备验收证据参数、路径解析和 metadata 字段。

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有在线 Android 设备，未验证显式设备证据参数在正向 release readiness 中通过。
- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- APK smoke evidence 仍固定读取 `build/apk-smoke/smoke-release-apk-run.txt`，没有显式证据路径参数，存在被后续 smoke 覆盖后的可追溯性风险。

## 下一轮建议

继续审查 APK smoke evidence 输入方式：为 `verify-release-readiness.ps1` 增加 `-ApkSmokeEvidencePath`，正式发布 checklist 显式传入本次 APK smoke metadata。
