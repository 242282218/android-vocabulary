# 2026-05-25 持续优化第 143 轮

## 当前审查范围

本轮接着第 142 轮，审查 GitHub Actions evidence 是否能追溯到具体 CI 运行。第 142 轮已经让 CI 自动上传 `github-actions-release-evidence` artifact，但 evidence 只记录 workflow、commit 和检查项，发布记录中仍缺少具体 run 的定位信息。

## 发现

当前 evidence 能证明“某个 Android workflow 对当前 commit 通过”，但不能直接定位到 GitHub Actions 的具体运行页面。发布复盘或审计时，还需要人工从 GitHub 页面按提交查找对应 run，证据链不够闭合。

## 方案

- 方案 A：只在文档中要求人工保留 GitHub Actions 页面链接。无需改脚本，但容易漏记。
- 方案 B：CI evidence 自动写入 `runId`、`runAttempt`、`runUrl`，readiness 门禁校验这些字段存在且格式合理。

本轮采用方案 B。不调用 GitHub API，不引入 token，只使用 GitHub Actions 自带环境变量。

## 完成项

`scripts/test/write-github-actions-evidence.ps1`

- 读取 `GITHUB_RUN_ID`、`GITHUB_RUN_ATTEMPT`、`GITHUB_SERVER_URL`、`GITHUB_REPOSITORY`。
- evidence 增加：
  - `runId=<GITHUB_RUN_ID>`
  - `runAttempt=<GITHUB_RUN_ATTEMPT>`
  - `runUrl=<GITHUB_SERVER_URL>/<GITHUB_REPOSITORY>/actions/runs/<GITHUB_RUN_ID>`

`scripts/test/verify-release-readiness.ps1`

- 增加 `Test-PositiveIntegerString`，要求 `runId` 和 `runAttempt` 是正整数。
- 增加 `Test-GitHubActionsRunUrl`，要求 `runUrl` 指向对应 `runId`。
- readiness metadata 增加：
  - `githubActionsRunId`
  - `githubActionsRunAttempt`
  - `githubActionsRunUrl`
- `githubActionsEvidence` 失败/通过摘要中带上 run 追溯字段。

`scripts/test/verify-release-scripts.ps1`

- 回归断言覆盖 `runId`、`runAttempt`、`runUrl`。
- fake CI evidence writer 测试补齐 `GITHUB_RUN_ID`、`GITHUB_RUN_ATTEMPT`、`GITHUB_SERVER_URL`、`GITHUB_REPOSITORY`。

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有真实 GitHub Actions 运行结果，未验证 artifact 下载链路。
- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，缺少正式设备 AAB 验收成功证据。
