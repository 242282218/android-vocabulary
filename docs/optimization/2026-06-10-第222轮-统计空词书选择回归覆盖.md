# 第 222 轮：统计空词书选择回归覆盖

## 审查目标

延续第 221 轮，继续检查当前大批未提交改动中仍缺少证据的统计口径。重点是“空词书选择表示全部词书”这一产品语义是否在统计查询链路里有足够回归保护。

## 调研依据

- AnkiDroid 这类成熟 SRS 项目强调统计和筛选口径稳定，复杂功能可以不跟，但数据口径不能漂移。
- ForgetMeNot / StackSRS 更接近轻量离线背诵工具，本项目应保持简单筛选语义，避免空选择导致用户看到空统计。
- 本地 `设计美学研究` 的移动端规则强调有限视口内状态清晰，统计页不应因为隐式空筛选造成“看起来没学过”的误导。

## 发现

当前实现已经用 `effectiveSelectedBookCodeNames()` 把空选择扩展为全部词书，并且已有 `reviewLoadExpandsEmptySelectedBooksInBookOrder()` 覆盖未来复习负载。

但以下统计路径之前没有一起覆盖：

- 今日统计。
- 今日到期数。
- 平均复习耗时。
- 日活热力。
- 保持率。
- 连续学习。
- 困难词。

这些查询都是发布前数据正确性风险点。若后续有人把其中一条改回 `selectedBooks.map { it.name }`，空选择就会查不到数据，UI 上会表现为统计突然归零。
