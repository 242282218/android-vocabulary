# 第 220 轮：提醒设置写入失败时不应崩溃

## 审查证据

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsViewModel.kt`
  - `updateReminder()` 和 `updateReminderTime()` 之前直接在 `viewModelScope.launch` 里调用 `UpdateSettingsUseCase`。
  - 这两条路径没有 `try/catch`，一旦 DataStore 写入失败，主线程协程会直接抛异常。
- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 提醒卡片已经有现成的 `reminderErrorMessage` 展示位。
  - 说明这条链路最适合先补“失败可见、但不崩溃”的闭环。
- `core/datastore/src/main/java/com/zzz/androidvocab/core/datastore/SettingsDataStore.kt`
  - `updateReminderEnabled()` / `updateReminderTime()` 最终都走 `dataStore.edit { ... }`，确实存在 I/O 失败可能。

结论：提醒设置目前属于“写入失败直接崩”的路径，且 UI 已有错误展示位但没接上，优先级高于继续做无关清理。

## 方案

- 方案 A：只在 repository 层吞掉异常
  - 优点：改动小
  - 缺点：UI 无法知道保存失败，用户会误以为设置已生效
- 方案 B：在 `SettingsViewModel` 捕获提醒设置异常，保留页面状态并通过 `reminderErrorMessage` 显示错误
  - 优点：不崩溃，且失败对用户可见
  - 缺点：目前只覆盖提醒这条设置链路

采用方案 B。

## 修改

- 修改 `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsViewModel.kt`
  - `updateReminder()` 和 `updateReminderTime()` 增加 `CancellationException` 透传与普通异常捕获
  - 写入失败时改为设置 `reminderErrorMessage`
  - 新增 `Throwable.toReminderSettingsMessage()`，把 `DatabaseWriteFailed` 映射成更准确的：
    - `提醒设置保存失败：<reason>`
- 修改 `feature/settings/src/test/java/com/zzz/androidvocab/feature/settings/SettingsViewModelTest.kt`
  - 新增 `updateReminderStoresFailureInsteadOfCrashing()`
  - 新增 `updateReminderTimeStoresFailureInsteadOfCrashing()`
  - 扩展 `FakeSettingsRepository`，支持对提醒开关和提醒时间写入注入异常
