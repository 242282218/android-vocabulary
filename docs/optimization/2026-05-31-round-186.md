# 第 186 轮：同步 Review 与 Today 的短暂会话态，消除跨页面旧剩余数

## 审查证据

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - Review 页面已经有本地 `submittedCardId` 过滤逻辑，能在本页先隐藏刚提交的旧卡。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayViewModel.kt`
  - Today 页面之前完全依赖 `GetTodayOverviewUseCase()` 的仓库队列。
  - 这意味着用户在 Review 提交成功后立刻切回 Today，Today 仍可能短暂显示包含旧卡的剩余数。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayRoute.kt`
  - Hero 卡片的剩余数、按钮文本和 header 文案之前都没有“同步中”状态。
  - 当最后一张卡刚提交、但仓库队列还没刷新时，Today 会短暂误导为还有一张，或者继续给出“开始学习”入口。

结论：问题根因不是 Today 展示逻辑本身，而是 Review 和 Today 没有共享“当前会话刚消费了一张卡、但真实队列还没移除”的瞬时状态。

## 方案

- 方案 A：在 Today 页面单独猜测并减一。
  - 优点：改动少。
  - 缺点：Today 无法知道是哪张卡被消费，也不知道何时该停止猜测，属于脆弱 workaround。
- 方案 B：增加一个进程内共享的 Review 会话协调器，由 Review 和 Today 共用。
  - 优点：根因修复，状态来源单一，不碰数据库或持久化不变量。
  - 缺点：要加一个小的共享类，并补跨页面测试。

采用方案 B。

## 修改

- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ReviewSessionCoordinator.kt`
  - 新增进程内 `ReviewSessionCoordinator`，统一维护当前会话里“刚提交成功、但真实队列未移除”的 `submittedCardId`。
- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - Review 改为写入/读取共享协调器，而不再只靠本页私有状态。
  - 当真实队列不再包含这张卡时，清理共享会话态。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayViewModel.kt`
  - 组合 Today 概览与共享协调器。
  - 当 Today 仍收到含旧卡的原始队列时，本地过滤掉那张刚提交的旧卡。
  - 若过滤后队列为空但原始队列里仍有该卡，标记 `isRefreshingReviewSession = true`。
  - 当真实队列已经移除该卡时，清理共享会话态。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayRoute.kt`
  - Header 文案新增“学习记录已保存，正在同步今日队列”。
  - Hero 卡片新增“同步中”状态。
  - 同步窗口内按钮禁用并显示“正在同步”，避免误导用户再次进入旧队列。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 适配共享协调器注入，锁定 Review 现有会话语义不回退。
- `feature/today/src/test/java/com/zzz/androidvocab/feature/today/TodayViewModelTest.kt`
  - 新增：
    - `submittedCardIsHiddenFromTodayWhileQueueStillContainsStaleEntry()`
    - `todayShowsNextCardCountWhilePendingSubmittedCardIsStillInRawQueue()`
    - `todayClearsRefreshingStateWhenSubmittedCardActuallyLeavesQueue()`
