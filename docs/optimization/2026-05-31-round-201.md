# 第 201 轮：把 stale current-version release artifact 证据透传到 release readiness

## 审查证据

- `scripts/test/verify-release-readiness.ps1`
  - 当前会读取 `build/release-artifacts/release-artifacts-run.txt`，但只拿 `releaseApkSha256`、`releaseBundleSha256` 和 remediation。
  - 问题是 `verify-release-artifacts.ps1` 已经产出了 `staleCurrentVersionArtifacts`，readiness 没继续带上来，导致最终失败信息仍偏泛化。
- `scripts/test/verify-release-artifacts.ps1`
  - 已经能输出：
    - `staleCurrentVersionArtifacts`
    - `releaseApkOlderThanBuildValidation`
    - `releaseBundleOlderThanBuildValidation`
    - 更具体的 `releaseArtifactsRemediation`
- `scripts/test/verify-release-scripts.ps1`
  - 已有 release readiness 的正向夹具和失败夹具，但还没有覆盖“releaseArtifacts 失败且带 stale current-version artifact 证据”的场景。
- `build/release-readiness/release-readiness-run.txt`
  - 本轮修改前，`releaseArtifacts` requirement 的 evidence 没有 `staleCurrentVersionArtifacts=...`
  - 本轮修改后，已看到：
    - `releaseArtifactsStaleCurrentVersionArtifacts=AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk`
    - `releaseArtifacts=failed|...;staleCurrentVersionArtifacts=AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk;remediation=...`

## 方案

- 方案 A：只透传 `staleCurrentVersionArtifacts`
  - 优点：改动最小，直接修复当前信息断层，回归面小
  - 缺点：不额外暴露时间戳和 older-than 标志
- 方案 B：连同时间戳和 `OlderThanBuildValidation` 标记一起透传
  - 优点：metadata 更完整，定位信息更细
  - 缺点：readiness 输出更重，测试夹具和断言都要同步扩张

采用方案 A。

## 修改

- 修改 `scripts/test/verify-release-readiness.ps1`
  - 读取 `staleCurrentVersionArtifacts`
  - 在 readiness metadata 中新增：
    - `releaseArtifactsStaleCurrentVersionArtifacts=...`
  - 在 `releaseArtifacts` requirement evidence 中新增：
    - `staleCurrentVersionArtifacts=...`
  - 当上游 remediation 没显式带出 stale artifact 名称时，自动在 readiness remediation 末尾补一句，避免信息再次丢失
- 修改 `scripts/test/verify-release-scripts.ps1`
  - 增加对上述新 key 和文案的静态断言
  - 扩充正向夹具，要求 completed metadata 包含 `releaseArtifactsStaleCurrentVersionArtifacts=<none>`
  - 新增失败夹具：模拟 `releaseArtifacts` 失败且带 stale current-version artifact 名称，验证 readiness 输出会把这条线索保留下来

## 验证

1. 运行：

```powershell
.\scripts\test\verify-release-scripts.ps1
```

结果：通过。

2. 运行：

```powershell
.\scripts\test\verify-release-readiness.ps1
```

结果：按预期失败，但失败信息已更具体。

关键证据：

- `build/release-readiness/release-readiness-run.txt`
  - `runStatus=failed`
  - `failedRequirementNames=gitWorktreeClean, releaseArtifacts, releaseApkSmoke, deviceAabVerification, deviceBundleSmokeArchive, githubActionsEvidence`
  - `releaseArtifactsRemediation=... Current-version release-named artifacts are older than the matching build-validation outputs: AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk. ...`
  - `releaseArtifactsStaleCurrentVersionArtifacts=AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk`
  - `releaseArtifacts=failed|...;staleCurrentVersionArtifacts=AndroidVocabulary-release-v0.1.0-1.aab, AndroidVocabulary-release-v0.1.0-1.apk;remediation=...`

结论：release readiness 现在已经不会丢失“当前版本 release 命名产物其实比 build-validation 更旧”这条根因线索。
