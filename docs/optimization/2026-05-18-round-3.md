# 2026-05-18 持续优化第 3 轮

## 当前状态判断

第 2 轮后，今日 due 队列会在相同到期时间下优先处理最近更困难的词。继续审查数据可恢复性时，发现导出 JSON 的 `dailyStats` 直接读取 `daily_stats` 缓存表，而项目规则定义 `ReviewLog` 才是真实来源，`DailyStats` 只是缓存。

## 对标项目可借鉴点

- 离线优先应用导出应尽量导出可重放事实，而不是依赖可能过期的聚合缓存。
- Anki 类 SRS 的学习历史必须可审计、可重算，统计应从复习日志派生。

## 差距清单

### P1

- 导出统计依赖缓存。影响数据迁移和故障恢复；根因是 `AndroidExportRepository` 直接读 `daily_stats`；建议导出时用 `review_logs` 派生每日统计；收益是即使缓存缺失也能导出完整统计；风险低。

### P2

- 应用内还没有显式 “重建统计缓存” 入口。
- 导出暂未包含 schema checksum 或数据完整性摘要。

## 本轮要做的优化项

1. `ExportDao` 增加从 `review_logs` 派生每日统计的查询。
2. `AndroidExportRepository` 的 `dailyStats` 改为使用派生结果。
3. 补缓存缺失场景测试。

## 验证方案

- `:core:database:testDebugUnitTest`
- `scripts/test/verify-local.ps1`

## 本轮风险

- 导出时多一个聚合查询，数据量与本地复习日志成正比；第一版用户规模下可接受。若未来日志很大，可分页或预聚合。

## 下一轮建议

1. 把 `daily_stats` 缓存重建做成显式 use case / worker。
2. 增强 UI instrumentation：长词、长释义、360dp、深色模式。
3. 评估多词书共享词是否应共用卡片，避免同词重复学习。
