# 第 194 轮：修正设备脚本优先命中中文路径 SDK，恢复 emulator 上线并跑出真实 instrumentation 结果

## 审查证据

- `scripts/lib/android-env.ps1`
  - `Get-AndroidSdkDir()` 之前的候选顺序是：
    - `ANDROID_HOME`
    - `ANDROID_SDK_ROOT`
    - 仓库内 `.tools/android-sdk`
    - `local.properties` 的 `sdk.dir`
  - 当前仓库路径是 `D:\PROJECT_ZZZZZZZZZ\安卓背单词`，包含中文目录名。
  - `local.properties` 已明确配置：
    - `sdk.dir=D\:\\AndroidVocabularyTools\\android-sdk`
  - 但脚本实际仍优先返回仓库内 `.tools/android-sdk`，把 ASCII 路径 SDK 抢在后面。
- 真实设备链路排查：
  - `verify-device.ps1 -ListDevices` 初始只看到 `127.0.0.1:5555 offline`，后续重启 adb 后变成 `emulator-5554 offline`。
  - 抓取 emulator 日志后，`build/emulator-debug/emulator-stderr.log` 明确报错：
    - `qemu: could not load PC BIOS 'bios-256k.bin'`
  - `build/emulator-debug/emulator-stdout.log` 同时显示 QEMU 启动参数中的 `-L` 指向仓库内中文路径下的 `emulator/lib/pc-bios`。
- 进一步验证：
  - 外部 SDK `D:\AndroidVocabularyTools\android-sdk\emulator\lib\pc-bios\bios-256k.bin` 实际存在。
  - 说明问题不是 BIOS 文件缺失，而是脚本把 emulator 绑定到了包含中文路径的仓库内 SDK。

结论：之前拿不到设备验收证据，不是 App 本身先挂，而是设备脚本先选错了 SDK。QEMU 在当前环境下无法稳定从中文路径加载 BIOS，导致 emulator 进程起了、端口开了，但 adb 只能看到 `offline` 或根本看不到设备。

## 方案

- 方案 A：不改脚本，每次手工导出 `ANDROID_HOME` 或手工指定外部 SDK。
  - 优点：改动最小。
  - 缺点：不可复用，`verify-device`、`smoke-release-bundle` 等后续脚本仍会继续踩同一个坑。
- 方案 B：修正 `Get-AndroidSdkDir()` 的候选顺序，优先使用环境变量和 `local.properties` 的显式 SDK，再退回仓库内 `.tools`。
  - 优点：根因修复，所有依赖 `Get-AndroidTool()` 的脚本都会自动受益。
  - 缺点：本地有多个 SDK 时，行为会更依赖显式配置。

采用方案 B。

## 修改

- `scripts/lib/android-env.ps1`
  - 调整 `Get-AndroidSdkDir()` 候选顺序：
    - 先 `ANDROID_HOME`
    - 再 `ANDROID_SDK_ROOT`
    - 再 `local.properties` 的 `sdk.dir`
    - 最后才回退到仓库内 `.tools/android-sdk`
  - 增加英文注释，说明为什么要把 repo-local SDK 作为 fallback：
    - 避免 emulator/QEMU 因 Unicode 路径触发 BIOS 加载失败

## 验证

1. 工具解析验证：

```powershell
. .\scripts\lib\android-env.ps1; Write-Output "SDK_DIR=$(Get-AndroidSdkDir)"; Write-Output "ADB=$(Get-AndroidTool -Names @('adb.exe','adb') -RelativeDirs @('platform-tools'))"; Write-Output "EMU=$(Get-AndroidTool -Names @('emulator.exe','emulator') -RelativeDirs @('emulator'))"
```

结果：

- `SDK_DIR=D:\AndroidVocabularyTools\android-sdk`
- `ADB=D:\AndroidVocabularyTools\android-sdk\platform-tools\adb.exe`
- `EMU=D:\AndroidVocabularyTools\android-sdk\emulator\emulator.exe`

2. 设备上线验证：

```powershell
. .\scripts\lib\android-env.ps1; .\scripts\test\verify-device.ps1 -ListDevices
```

结果：

- `emulator-5554 device product:sdk_gphone64_x86_64 ...`

3. 真实 instrumentation 验证：

```powershell
.\scripts\test\verify-device.ps1 -DeviceSerial emulator-5554 -SkipBundleBuild -SkipBundleSmoke
```

结果：

- 设备链路本身已恢复，可正常进入 `connectedDebugAndroidTest`
- 但测试失败，失败阶段为：
  - `connectedDebugAndroidTest`
- 失败日志目录：
  - `build/device-verification/v0.1.0-1-20260531-062345/`
- 主要失败集中在：
  - `ScreenLayoutSmokeTest`
  - 共 `42` 个失败

这说明本轮设备脚本根因已修掉，当前 blocker 已从“模拟器起不来”前移到“真实设备 smoke test 断言失败”。
