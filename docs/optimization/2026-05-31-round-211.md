# 第 211 轮：封住 Today 队列主路径外漏 malformed cardId

## 审查证据

- `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - `getQueueItem(cardId)` 已在上一轮支持 canonicalize / repair。
  - 但 `observeTodayQueue()` 仍直接把 `dueRows/newRows` 映射成 `toQueueItem(now)`，没有经过同样的修复逻辑。
- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - `submit()` 直接用 `uiState.item.card.id` 作为后续提交的 `cardId`。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ReviewSessionCoordinator.kt`
  - 只保存一个 raw `submittedCardId`。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ObserveSubmittedCardQueueStateUseCase.kt`
  - 通过 `observeTodayQueue()` 返回的 `queue.items.any { it.card.id == submittedCardId }` 判断卡片是否仍在队列中。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/DatabaseViews.kt`
  - `word_card_view` 通过 `wordId + bookCode` 左连接 `review_cards`。
  - 如果 Today 队列继续把 malformed cache 暴露给 UI，后续提交会再次把坏 id 往主路径传递。

## 方案

- 方案 A：只在 `ReviewQueueRow.toQueueItem()` 层面把 id 改成 canonical
  - 优点：改动最小
  - 缺点：只掩盖表现层；坏缓存行仍留在数据库里，和仓库层现有修复语义不一致
- 方案 B：抽出队列行 canonicalize helper，让 `observeTodayQueue()` 和 `getQueueItem()` 共用同一套 repair 逻辑
  - 优点：主路径与显式读取路径保持一致；不仅返回 canonical id，也会顺手修复缓存
  - 缺点：比方案 A 多一个内部 helper，但仍局限在仓库层

采用方案 B。

## 修改

- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - 新增 `queueRowToItem(row, now)`
  - `observeTodayQueue()` 改为对 due/new 队列统一走 `queueRowToItem()`
  - `readQueueItem()` 命中缓存行时也复用 `queueRowToItem()`，避免两套分叉逻辑
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryTest.kt`
  - 新增 `todayQueueCanonicalizesMalformedCachedCardIdBeforeExpose()`
  - 断言 Today 队列对外暴露的 `card.id` 已经是 canonical，并且数据库中的 malformed cache 已被清理
