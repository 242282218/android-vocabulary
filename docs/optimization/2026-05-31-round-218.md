# 第 218 轮：修复 streak 统计被 365 天窗口截断

## 审查证据

- `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - `observeStreakStats()` 之前会先算 `today.minusDays(365)`，再调用 `statsDao.observeActiveDays(sinceDay, ...)`。
  - `currentStreak` 和 `maxStreak` 都基于这个被裁过的活跃日集合计算。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeActiveDays()` 的 SQL 也带 `l.localDay >= :sinceDay` 过滤。
- `core/stats/src/test/java/com/zzz/androidvocab/core/stats/OfflineStatsRepositoryTest.kt`
  - 之前只有“会调用 streak 查询”和一般结果断言，没有覆盖“连续学习超过 365 天”的场景。

结论：当前实现会把历史连续学习超过 365 天的用户直接截断，导致 `maxStreak` 不可从完整 `ReviewLog` 复算，也会让超长连续学习的 `currentStreak` 失真。

## 方案

- 方案 A：保留 365 天窗口，只给 `maxStreak` 单独加一个全量查询
  - 优点：理论上能少查一点数据
  - 缺点：DAO 和仓库逻辑要拆成两套，复杂度更高
- 方案 B：streak 统计统一改成基于全量 distinct `localDay`
  - 优点：实现最小，语义最直接，完整满足“统计可从日志复算”
  - 缺点：会读取全部活跃日，但上限只是有学习记录的日期数，成本可接受

采用方案 B。

## 修改

- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeActiveDays()` 去掉 `sinceDay` 参数
  - SQL 改为按选中词书读取全量 distinct `localDay`
- 修改 `core/stats/src/main/java/com/zzz/androidvocab/core/stats/OfflineStatsRepository.kt`
  - `observeStreakStats()` 不再裁最近 365 天
  - 删除 `STREAK_LOOKBACK_DAYS`
  - `currentStreak` / `maxStreak` 统一基于全量活跃日集合计算
- 修改 `core/stats/src/test/java/com/zzz/androidvocab/core/stats/OfflineStatsRepositoryTest.kt`
  - 新增 `streakStatsAreNotTruncatedToRecent365Days()`
  - 断言连续 400 天的活跃记录会得到 `currentStreak=400`、`maxStreak=400`
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/DailyStatsCacheRebuildTest.kt`
  - 同步 `observeActiveDays()` 新签名
