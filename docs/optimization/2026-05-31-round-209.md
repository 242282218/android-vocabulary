# 第 209 轮：修复 malformed cardId 污染每日统计的 SQL 根因

## 审查证据

- `core/database/src/main/java/com/zzz/androidvocab/core/database/DatabaseViews.kt`
  - `first_reviews` 和 `review_daily_stats` 之前按 `review_logs.cardId` 识别“同一张卡”。
  - 问题是 `cardId` 不是稳定事实来源；当同一 `wordId + bookCode` 的历史日志里混入 malformed `cardId` 时，SQL 会把它当成第二张卡。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeDailyStatsFromLogs()` 也复用了同样的 `JOIN first_reviews f ON f.cardId = l.cardId` 语义。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/OfflineReviewRepositoryTest.kt`
  - 已证明仓库层可以用日志里的 `wordId + bookCode` 修复 malformed `cardId` 的 cache。
  - 但这不覆盖 SQL 统计层，意味着根因仍在 view/DAO。
- `core/database/src/test/java/com/zzz/androidvocab/core/database/DailyStatsCacheRebuildTest.kt`
  - 原先只覆盖 orphan log 被忽略、同时间戳 tie-break、book filter。
  - 缺口是没有覆盖“同一词的日志使用不同 cardId”时，`newCount/reviewCount` 是否被污染。

## 方案

- 方案 A：保持 SQL 不动，只在仓库层或导出层对 malformed `cardId` 做补丁
  - 优点：改动小
  - 缺点：治标不治本，`review_daily_stats`、`observeDailyStatsFromLogs()`、迁移后旧库 view 都会继续算错
- 方案 B：把“逻辑卡片身份”统一收敛为 `wordId + bookCode`，修正当前 view、StatsDao 查询和 `9 -> 10` 迁移
  - 优点：直接修根因，SQL 层和仓库层语义一致
  - 缺点：涉及 schema 版本升级和 migration 测试

采用方案 B。

## 修改

- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/DatabaseViews.kt`
  - 新增逻辑卡片标识 SQL：`l.bookCode || '|' || l.wordId`
  - `first_reviews` 改为按 `wordId + bookCode` 选首条日志
  - `review_daily_stats` 改为按逻辑卡片身份连接 `first_reviews`
- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/StatsDao.kt`
  - `observeDailyStatsFromLogs()` 改为按逻辑卡片身份连接 `first_reviews`
- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/VocabDatabase.kt`
  - 数据库版本从 `9` 升到 `10`
- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/Migrations.kt`
  - 保留 v9 的旧 view SQL，用于 `8 -> 9`
  - 新增 `MIGRATION_9_10`
  - `9 -> 10` 只重建 `first_reviews` / `review_daily_stats` 两个 view
- 修改 `core/database/src/main/java/com/zzz/androidvocab/core/database/DatabaseModule.kt`
  - 注册 `MIGRATION_9_10`
- 修改 `core/database/src/test/java/com/zzz/androidvocab/core/database/DailyStatsCacheRebuildTest.kt`
  - 新增 `rebuildDailyStatsCacheTreatsMalformedCardIdAsSameLogicalCard()`
  - 断言同一词的有效 `cardId` 和 malformed `cardId` 日志会被算成：
    - `newCount = 1`
    - `reviewCount = 1`
    - `completedCount = 2`
- 修改 `core/database/src/androidTest/java/com/zzz/androidvocab/core/database/VocabDatabaseMigrationTest.kt`
  - 新增 `migratesVersionNineToTen()`
  - 新增 `migratesVersionOneToTen()`
  - 断言升级后的 `first_reviews` / `review_daily_stats` 会自动纠正旧库里 malformed `cardId` 带来的统计歧义
- 生成 schema：
  - `core/database/schemas/com.zzz.androidvocab.core.database.VocabDatabase/10.json`
