# 2026-05-25 持续优化第 85 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 的首屏 smoke 失败诊断，重点是崩溃日志是否会在进程未启动或首屏文本超时时被带出来。

## 发现

脚本原顺序是：

1. 清空 logcat。
2. `monkey` 启动应用。
3. `pidof` 检查进程。
4. 等待首屏文本。
5. 最后才检查 `AndroidRuntime:E` 崩溃日志。

这会产生两个诊断缺口：

- 应用启动即崩溃时，`pidof` 为空，脚本直接报 `App process is not running`，没有带出崩溃堆栈。
- 应用进程存在但首屏文本一直不可见时，`Wait-ForVisibleAppText` 超时直接抛错，也不会走到后面的崩溃检查。

## 方案

- 方案 A：提取 `Get-FatalCrashText`，在 `pidof` 失败、首屏等待循环和超时错误中复用崩溃检查。改动小，不改变 smoke 流程。
- 方案 B：失败时 dump 全量 logcat 到文件。诊断信息更多，但脚本当前不是聚合日志脚本，输出会很噪。

本轮采用方案 A。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 新增 `Get-FatalCrashText`。
- 新增 `Throw-WithFatalCrashContext`。
- `pidof` 为空时，如有 `AndroidRuntime` 崩溃日志，会把 fatal crash 一并输出。
- `Wait-ForVisibleAppText` 每轮等待后检查崩溃，首屏超时时也会附带 fatal crash。

## 剩余风险

- 当前没有在线 Android 设备，未实测真实崩溃时的 logcat 捕获效果。
- `logcat -d -t 500 AndroidRuntime:E *:S` 仍依赖设备日志缓冲区，极端日志洪泛下可能截不到早期崩溃。
