# 2026-05-25 持续优化第 119 轮

## 当前审查范围

本轮审查 `verify-device.ps1` 的失败 metadata 是否能直接标出失败阶段，而不是只依赖长 `failureMessage` 人工判断。

## 发现

第 118 轮已经把 APK smoke 的 UI dump 归档进本次设备验收目录，但失败阶段仍主要靠：

```text
failureMessage=...
connectedTestsLog=...
bundleBuildLog=...
bundleSmokeLog=...
```

这能定位问题，但不够直接。发布归档里常见失败至少需要区分：

- `connectedDebugAndroidTest`
- `buildReleaseBundle`
- `bundletoolBuildApks`
- `bundletoolInstallApks`
- `installedAppLaunchSmoke`
- `deviceDiagnostics`

另外，第 118 轮文档里的 `git diff --check` 示例把记录文件写成了 round-117，实际应为 round-118。

## 方案

- 方案 A：只依赖日志文件名和 `failureMessage`。无需改代码，但复盘时需要读长错误文本。
- 方案 B：保留现有日志，同时在 metadata 增加短字段 `failureStage`。优先根据失败消息识别更细阶段，无法识别时回退到主流程当前阶段。

本轮采用方案 B。

## 完成项

`scripts/test/verify-device.ps1`

- 新增 `Resolve-FailureStage`。
- `Save-RunMetadata` 新增 `failureStage` 字段。

```text
installedAppLaunchSmoke
```

- 当前没有在线 Android 设备，未验证真实 bundletool 安装失败和安装后启动 smoke 失败的 `failureStage`。

## 下一轮建议

继续审查 `smoke-release-apk.ps1` 的显式 `-ApkPath` 处理。AAB smoke 已经会警告显式 `BundlePath` 不符合当前版本命名；APK smoke 对显式 APK 路径还没有同类提示，可能导致发布记录混用旧版本 APK。
