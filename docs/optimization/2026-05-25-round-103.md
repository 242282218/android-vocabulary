# 2026-05-25 持续优化第 103 轮

## 当前审查范围

本轮继续审查发布验收脚本中的 native 子进程 stderr 捕获，重点是 `2>&1` 和 `*>&1 | Tee-Object` 在 `$ErrorActionPreference='Stop'` 下是否会提前中断，导致脚本来不及检查 exit code。

## 发现

本地最小实验确认：

- native 命令直接写 stderr 但不重定向时，脚本能继续执行并读取 `$LASTEXITCODE`。
- 使用 `2>&1` 捕获 stderr/stdout 时，stderr 会触发 `NativeCommandError`，脚本会在读取 `$LASTEXITCODE` 前进入 catch。
- 使用 `*>&1 | Tee-Object` 记录子进程日志时，也会出现同类提前中断，且可能丢失日志内容。

受影响的关键路径：

- `scripts/test/smoke-release-apk.ps1` 的 `Invoke-AndroidDebugBridge -Capture`。
- `scripts/test/verify-device.ps1` 的 `Invoke-LoggedStep`。
- `scripts/release/build-bundle.ps1` 的 `jarsigner` 输出捕获。

## 方案

- 方案 A：新增一个全局 PowerShell native runner。复用更好，但会扩大公共脚本 API，且当前脚本已有局部捕获风格。
- 方案 B：在现有捕获点临时把 `$ErrorActionPreference` 调整为 `Continue`，捕获输出和 exit code 后立即恢复。影响面小，和前几轮 `adb` / `apksigner` 修法一致。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- `Invoke-AndroidDebugBridge -Capture` 现在在执行 ADB 时临时使用 `$ErrorActionPreference='Continue'`。
- 失败信息包含 exit code，并保留 stdout/stderr 文本；无输出时明确显示 `<no output>`。

`scripts/test/verify-device.ps1`

- `Invoke-LoggedStep` 现在在 `*>&1 | Tee-Object` 期间临时使用 `$ErrorActionPreference='Continue'`。
- 子步骤失败时仍抛出 `<step> failed. See <log>. Cause: ...`，但日志更可能保留 stderr/stdout。

`scripts/release/build-bundle.ps1`

- `jarsigner -verify` 捕获路径改为临时 `Continue`，避免未签名 AAB 的 stderr 直接中断。

## 剩余风险

- 当前没有在线 Android 设备，`Invoke-AndroidDebugBridge -Capture` 和 `Invoke-LoggedStep` 的真实设备路径仍未跑安装、启动、logcat 或 `connectedDebugAndroidTest`。
- 当前没有正式 release signing 环境，未验证正式签名 AAB 的 `jar verified` 分支。
