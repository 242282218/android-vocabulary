# 2026-05-25 持续优化第 28 轮

## 当前审查范围

本轮审查发布和设备验收链路，目标是确认当前机器能完成哪些发布前验证，哪些仍受设备或正式签名限制。

## 对照原则

- 发布脚本应把“可发布产物”和“仅验证编译链路的产物”明确区分。
- 设备验收应可重复执行，并把 connected tests、AAB 安装和首屏 smoke 串成一条命令。
- 无设备或无正式 keystore 时，脚本应明确失败边界或降级说明，不能让用户误以为已完成发布验收。

## 本轮发现

1. `scripts/test/verify-device.ps1 -ListDevices` 可执行，但当前没有在线设备，输出为空设备列表。
2. `.tools/bundletool/bundletool.jar` 已存在，可以执行 AAB build-only smoke。
3. `scripts/release/build-bundle.ps1 -AllowUnsigned` 会显式提示缺少 release signing 环境变量，并在验签阶段报告 AAB 未签名。
4. `scripts/test/smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning` 会使用本机 debug keystore 生成 APK Set，边界清楚。

## 完成项

本轮没有修改代码。现有脚本已经清楚区分未签名构建链路、debug 签名本地拆包和正式签名发布链路。

## 验证结果

设备列表检查：

```powershell
.\scripts\test\verify-device.ps1 -ListDevices
```

结果：命令通过，但无在线设备。

未签名 AAB 构建链路：

```powershell
.\scripts\release\build-bundle.ps1 -AllowUnsigned
```

结果：通过，生成 `dist\app-release.aab`；脚本明确提示 release signing 未配置，产物未验签，不可视为可上传产物。

AAB build-only smoke：

```powershell
.\scripts\test\smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning
```

结果：通过，生成 `build\bundle-smoke\app-release.apks`；bundletool 使用 debug keystore，仅验证本地拆包链路。

## 剩余风险

- 当前没有在线真机或模拟器，未执行 `connectedDebugAndroidTest`、AAB 设备安装、首屏 smoke 和 logcat 崩溃检查。
- 未配置正式 release signing 环境变量，AAB/APK 仍不是可发布产物。

## 下一轮建议

1. 继续审查 release APK smoke 脚本和签名校验，确认 APK 链路与 AAB 链路边界一致。
2. 有设备后执行：

```powershell

```

3. 正式发布前配置 release signing 环境变量后重新运行 `build-release.ps1`、`build-bundle.ps1` 和安装级 smoke。
