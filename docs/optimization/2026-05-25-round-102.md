# 2026-05-25 持续优化第 102 轮

## 当前审查范围

本轮继续审查设备验收脚本中 `adb devices` 的错误输出捕获，重点是 `$ErrorActionPreference='Stop'` 下 native stderr 是否会提前中断脚本并丢失诊断信息。

## 发现

三处脚本仍直接调用 `adb devices`：

```powershell
$output = & $adb devices
```

或：

```powershell
& $script:AdbPath devices -l
```

PowerShell 在 `$ErrorActionPreference='Stop'` 下可能把 native stderr 转成 `NativeCommandError`，导致脚本在检查 `$LASTEXITCODE` 前就中断。这样会让设备枚举失败时丢失 stderr、exit code，和前几轮修复的 `apksigner`、诊断命令、logcat tail 问题一致。

## 方案

- 方案 A：在 `scripts/lib/android-env.ps1` 增加共享 adb 捕获函数。优点是复用更好；缺点是扩大公共脚本 API，当前只服务发布验收脚本，影响面偏大。
- 方案 B：在三个脚本内各自增加局部 `Invoke-AdbDevicesCommand`，只包住 `adb devices` / `adb devices -l`。优点是外科式修改，行为边界清楚；缺点是有少量重复。

本轮采用方案 B，保持发布脚本稳定期的最小影响面。

## 完成项

`scripts/test/verify-device.ps1`

- 新增局部 `Invoke-AdbDevicesCommand`。
- `Get-ConnectedDeviceSerials` 现在捕获 stdout/stderr、exit code，并在失败时带出完整输出。
- `-ListDevices` 分支改为同一捕获路径，稳定输出 `adb devices -l` 结果。

`scripts/test/smoke-release-apk.ps1`

- 新增局部 `Invoke-AdbDevicesCommand`。
- `Get-ConnectedDeviceSerials` 和 `-ListDevices` 分支改为受控捕获。

- `Get-ConnectedDeviceSerials` 改为受控捕获。
- `-ListDevices` 继续委托 APK smoke 脚本，因此复用其受控捕获路径。
