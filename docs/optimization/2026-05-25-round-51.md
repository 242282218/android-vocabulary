# 2026-05-25 持续优化第 51 轮

## 当前审查范围

本轮审查 release APK 的产物选择和归档策略，重点是版本递增后 Gradle 输出目录中残留旧 APK 时，脚本是否会失败或按时间选错包。

## 发现

`app/build.gradle.kts` 会把 release APK 命名为：

```text
AndroidVocabulary-release-v<versionName>-<versionCode>.apk
```

旧逻辑里 `scripts/release/build-release.ps1` 要求 `app/build/outputs/apk/release` 中只能有一个 APK。版本递增后，如果旧版本 APK 残留在该目录，脚本会因为数量不等于 1 失败，即使当前版本 APK 已经正确生成。

`scripts/test/smoke-release-apk.ps1` 的默认 APK 查找也按 `LastWriteTime` 在 `dist/` 和 Gradle 输出目录里选最新 APK。历史产物并存时，这不是发布验收应依赖的不变量。

## 完成项

`scripts/lib/android-env.ps1`

- 新增 `Get-GradlePropertyValue()`，从 `gradle.properties` 读取项目版本号。
- 新增 `Get-AndroidVocabularyReleaseApkName()`，生成当前版本的 release APK 文件名。

`scripts/release/build-release.ps1`

- 不再要求 release 输出目录只有一个 APK。
- 改为精确查找当前版本 APK：`AndroidVocabulary-release-v<versionName>-<versionCode>.apk`。
- 如果找不到当前版本 APK，错误信息会列出已有 APK，便于定位残留或构建异常。

`scripts/test/smoke-release-apk.ps1`

- 默认 APK 查找改为优先查找当前版本 APK。
- 不再按 `LastWriteTime` 猜测最新 APK。
- 找不到当前版本 APK 时列出可用 APK，并提示传 `-ApkPath` 或先跑 release 构建。

## 剩余风险

- 当前验证使用 `-AllowUnsigned`，没有正式签名环境，不能代表可安装或可发布 APK。
- 当前没有在线设备，未执行 APK 安装、启动首屏 smoke。
- AAB 在 `dist/` 中仍使用 `app-release.aab` 固定名称，发布留档不如 APK 清晰，下一轮继续审查。

## 下一轮建议

继续审查 AAB 归档命名和默认选择逻辑，考虑将 `dist/app-release.aab` 改为带当前版本号的文件名，避免发布留档时无法从文件名识别版本。
