# 2026-05-25 持续优化第 116 轮

## 当前审查范围

本轮接着第 115 轮，审查 `build\apk-smoke\last-window.xml` 的生命周期，避免成功 smoke 后仍残留上一轮失败的 UI dump，导致发布验收归档被误读。

## 发现

第 115 轮新增了首屏超时时保存最后一次 UI dump：

```text
build\apk-smoke\last-window.xml
```

但如果一次失败写入了该文件，下一次 APK smoke 成功时不会自动删除旧文件。单独查看 `build\apk-smoke` 时，可能把旧失败 dump 误认为本轮结果。

## 方案

- 方案 A：每次成功后删除旧 dump。能减少误读，但如果中途早失败，旧 dump 仍可能留下。
- 方案 B：普通 smoke 开始时先删除旧 dump，只有本轮首屏超时才重新写入。这样成功、早失败、首屏失败三类结果都更明确。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 新增 `Get-LastWindowDumpPath`。
- 新增 `Clear-LastWindowDump`。
- 非 `-ListDevices` 的普通 smoke 开始时先清理旧的 `last-window.xml`。
- `Save-LastWindowDump` 复用统一路径，失败时仍写出本轮 UI dump。
