# 第 110 轮：Settings 数据维护状态语义

## 审查证据

- `SettingsRoute.DataMaintenanceCard` 原来成功或风险结果只显示正文消息，失败只显示红色文本。
- 检查/修复属于数据维护操作，移动端状态需要明确表达完成、需要处理、失败和恢复路径。
- `SettingsViewModelTest` 已覆盖检查成功、修复成功和检查失败后再次检查，但缺少修复失败后状态复位和错误展示的回归测试。
- `ui-ux-pro-max` 查询结果强调成功动作要明确确认，错误不能只依赖视觉颜色。

## 方案

- 方案 A：只改正文文案。最小，但状态仍不够可感知。
- 方案 B：数据维护结果增加状态 pill 和 live region；失败增加“处理失败”标题；补修复失败 ViewModel 测试。改动小，复用现有设计系统。
- 方案 C：改成完整分步维护流程。更清晰，但会扩大页面结构和测试面。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 数据维护成功/风险结果增加 `状态正常` / `需要处理` 状态 pill。
  - 结果区域使用 `LiveRegionMode.Polite`。
  - 错误区域增加 `处理失败` 标题，并使用 `LiveRegionMode.Assertive`。
- `feature/settings/src/test/java/com/zzz/androidvocab/feature/settings/SettingsViewModelTest.kt`
  - 新增 `repairLearningDataStoresFailureAndStopsProgress`。
  - 覆盖修复失败后 `inProgress=false`、无成功消息、错误消息可见。
