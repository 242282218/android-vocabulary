# 2026-05-25 持续优化第 57 轮

## 当前审查范围

本轮审查 `dist/` 中历史 AAB 产物的误用风险，重点是旧的 `dist/app-release.aab` 仍存在时，发布文档和默认脚本是否会引导人工误用。

## 发现

当前 `dist/` 中同时存在：

```text
AndroidVocabulary-release-v0.1.0-1.aab
AndroidVocabulary-release-v0.1.0-1.apk
app-release.aab
```

第 52 轮后，`smoke-release-bundle.ps1` 默认只查找版本化 AAB，已经不会自动选择旧的 `app-release.aab`。但人工查看 `dist/` 时仍可能误把旧文件当成待上传产物。

## 完成项

`docs/release.md`

- 在 AAB 构建说明中明确：如果本地仍存在旧的 `dist/app-release.aab`，只视为历史产物。
- 默认 AAB smoke 和正式上传都应使用版本化 AAB：

```text
dist/AndroidVocabulary-release-v<versionName>-<versionCode>.aab
```

## 验证结果

引用检查：

```powershell
rg -n "app-release\.aab|版本化 AAB|AndroidVocabulary-release-v<versionName>-<versionCode>" docs\release.md README.md -S
```

结果：`docs/release.md` 已明确旧 `app-release.aab` 是历史产物，README 和发布文档均指向版本化产物。

Diff 检查：

```powershell
git diff --check -- docs\release.md docs\optimization\2026-05-25-round-56.md
```

结果：通过，仅有 LF/CRLF 提示。

## 剩余风险

- 本轮没有删除 `dist/app-release.aab`，这是刻意选择，避免破坏本地历史产物或排查证据。
- 如果人工显式用 `-BundlePath .\dist\app-release.aab`，脚本仍会按指定文件执行；这是显式覆盖行为，不属于默认发布路径。

## 下一轮建议

继续审查发布脚本参数语义，特别是 `-AllowUnsigned`、`-AllowDebugSigning` 这类本地验证参数是否在组合使用时会让输出被误认为可发布。
