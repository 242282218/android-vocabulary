# 第 184 轮：提交成功后本地隐藏旧卡，并修正空卡片背面可见误判

## 审查证据

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 提交成功前后，页面当前卡片完全依赖 `GetTodayQueueUseCase()` 的队列刷新结果。
  - 如果仓库写入已成功，但队列流暂时还带着旧卡，UI 会继续显示刚提交过的卡片。
- 同文件里 `isBackVisible = item?.card?.id == backCardId`
  - 当 `item == null` 且 `backCardId == null` 时，这个表达式会变成 `true`。
  - 结果是旧卡虽然被本地隐藏，UI 状态仍会误判成“背面可见”。
- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ClockProviderExt.kt`
  - `observeNow()` 是一个每 60 秒 tick 的无限流。
  - `ReviewViewModelTest` 里如果在常驻订阅场景下继续用 `advanceUntilIdle()`，测试会一直追时钟，导致假性超时。

结论：这轮要同时修两件事：

1. Review 会话内要在本地先隐藏刚提交成功的卡片。
2. 测试必须改成只推进当前时刻，不能在无限时间流上跑 `advanceUntilIdle()`。

## 方案

- 方案 A：继续完全依赖队列流刷新，不做本地消费态。
  - 优点：实现最少。
  - 缺点：提交成功后的短窗口内，旧卡仍可能继续显示，不满足会话消费语义。
- 方案 B：ViewModel 记录刚提交成功的 `submittedCardId`，在队列真正移除前先本地过滤。
  - 优点：改动小，只影响 Review 页会话态，能直接切断旧卡重复展示。
  - 缺点：需要补测试覆盖本地过滤与刷新交接。

采用方案 B。

## 修改

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 新增 `submittedCardId` 本地会话态。
  - `uiState` 组合时先过滤掉刚提交成功、但队列流还没移除的卡片。
  - 当队列流里已经不存在该卡片时，自动清空 `submittedCardId`。
  - 修正 `isBackVisible` 判定，避免 `null == null` 把空卡片误判成背面可见。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 新增并收口：
    - `submittedCardIsHiddenWhileQueueStillContainsStaleEntry()`
    - `nextCardAppearsEvenIfQueueRefreshStillContainsSubmittedCardFirst()`
  - 调整失败重试相关测试，常驻订阅场景改用 `runCurrent()`，不再在无限时间流上使用 `advanceUntilIdle()`。
