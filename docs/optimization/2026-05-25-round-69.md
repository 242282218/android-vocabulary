# 2026-05-25 持续优化第 69 轮

## 当前审查范围

本轮审查 `smoke-release-bundle.ps1 -ApksPath` 自定义输出路径是否会让 APK Set 的签名性质在 release 记录中失真。

## 发现

第 67 轮已经让默认 APK Set 文件名带上：

```text
release-signing
debug-signing
```

但调用方显式传入 `-ApksPath` 时，脚本必须尊重该路径。例如 `-ApksPath .\build\bundle-smoke\custom.apks` 仍会生成不带签名类型的文件名。这样不影响 bundletool 构建和安装，但会影响后续人工查看验证记录。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 保留 `-ApksPath` 自定义能力。
- 当自定义文件名不包含当前签名类型时，输出 warning：

```text
Custom ApksPath does not include signing label '<debug-signing|release-signing>'.
```

- 继续输出明确的签名类型：

```text
[info] APK Set signing=<debug-signing|release-signing>
```

`docs/release.md`

- 在 AAB 安装级验证段补充：显式传入 `-ApksPath` 时，文件名也应包含签名类型，或保留脚本输出作为验证记录。

## 验证结果

PowerShell 解析检查：

```powershell
$tokens = $null; $parseErrors = $null; $null = [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path 'scripts/test/smoke-release-bundle.ps1'), [ref]$tokens, [ref]$parseErrors)
```

结果：通过。

引用检查：

```powershell
rg -n "Custom ApksPath|signing label|ApksPath|release-signing|debug-signing|APK Set signing" scripts/test/smoke-release-bundle.ps1 docs/release.md -S
```

结果：脚本和 release 文档均包含自定义路径的签名标签提示。

实际 warning 路径验证：

```powershell
.\scripts\test\smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning -ApksPath .\build\bundle-smoke\custom.apks
```

结果：通过，输出包含：

```text
WARNING: Custom ApksPath does not include signing label 'debug-signing'.
[info] APK Set signing=debug-signing
[ok] APK Set: .\build\bundle-smoke\custom.apks
[ok] bundle smoke build-only passed with debug signing; not release-ready
```

空白检查：

```powershell
git diff --check -- scripts/test/smoke-release-bundle.ps1 docs/release.md docs/optimization/2026-05-25-round-68.md
```

结果：通过，仅有 `docs/release.md` 的 LF/CRLF 工作区提示。

## 剩余风险

- 本轮仍只验证了 `bundletool build-apks --mode=universal`，没有在线设备执行 `install-apks`。
- 当前没有正式 release signing 环境，未验证 `release-signing` 路径。
- 本地新增的 `build\bundle-smoke\custom.apks` 是 ignored 中间产物，不是发布产物。
