# 2026-05-19 持续优化第 24 轮

## 当前状态判断

项目已采用 Kotlin + Jetpack Compose + Room 的长期维护路线。第 23 轮已把提醒调度决策抽成可测试逻辑，本轮继续检查 UI 与页面结构后发现，五个主页面都重复编写滚动容器、页面 padding 和纵向间距；卡片边框也写在卡片内部内容层，导致视觉层级不够稳定。Review 四档反馈按钮使用 `fillMaxWidth(0.48f)` 依赖经验比例，在窄屏和不同字体缩放下不如等分布局可靠。

## 对标设计参考

参考 `D:\PROJECT_ZZZZZZZZZ\设计美学研究` 中的 Premium、组件质感、留白与栅格、Dashboard 布局原则：

- 组件样式从 token 和基础组件派生，不在页面里临时写一套。
- 中性色承担主要画面，蓝色只用于主动作和关键数据，绿色用于完成状态。
- 移动端 gutter 保持稳定，卡片内部 padding 一致。
- Dashboard 信息层级先 KPI，再趋势和明细，避免颜色过多。

## 差距清单（按 P0/P1/P2/P3）

### P0

- 暂无新增 P0。数据、调度和导入链路本轮未发现必须立刻阻断的问题。

### P1

- 页面容器重复实现。影响范围是 Today、Review、Wordbook、Stats、Settings；根因是 design system 缺少页面级基础容器；建议抽成 `VocabScreen`。
- Review 反馈按钮布局比例脆弱。影响范围是 360px 窄屏与字体缩放；根因是手写 `fillMaxWidth(0.48f)`；建议改为 `FlowRow` 内等分权重。

### P2

- 卡片边框与宽度由页面内容隐式撑开。影响范围是视觉一致性和窄屏稳定性；建议 `VocabCard` 默认 `fillMaxWidth`，边框放到卡片外层。
- 统计热力图色阶偏装饰。影响范围是 Apple 风格克制感；建议用 surface / green / primary 语义色阶替代暖色装饰色。

### P3

- 后续可进一步把页面 KPI block 抽成更明确的 dashboard primitive，但本轮不为少量场景增加复杂抽象。

## 本轮完成项

1. 新增 `VocabScreen`，统一页面滚动、留白与纵向间距。
2. `VocabCard` 默认填满宽度，外层统一边框，阴影降低到 1dp，内部 padding 收敛到 20dp。
3. Today、Review、Wordbook、Stats、Settings 改用 `VocabScreen`。
4. Review 空状态改成卡片状态，不再在滚动容器中使用 `fillMaxSize`。
5. Review 四档反馈按钮改为 `FlowRow` 等分布局。
6. 统计热力图色阶改用更克制的完成/主色语义。
