# 第 187 轮：用全词书原始队列清理 Review 会话态，避免筛选变化时过早清理

## 审查证据

- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - 上一轮 Review 会在当前页面的过滤后队列里检查 `submittedCardId` 是否还存在，并据此清理共享协调器。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayViewModel.kt`
  - Today 也是基于当前过滤后的 `TodayOverview.queue` 来决定是否清理共享协调器。
- `core/database/src/main/java/com/zzz/androidvocab/core/database/OfflineReviewRepository.kt`
  - `observeTodayQueue()` 会按 `selectedBooks` 过滤。
  - `selectedBooks` 为空时，仓库语义是“全部词书”。

结论：之前的共享协调器清理信号不够强，会把“用户切换词书筛选导致当前页面看不见这张卡”和“这张卡真的已经离队”混为一谈。这样会存在过早清理风险：如果用户在队列刷新前切换筛选，再切回原筛选，旧卡理论上可能重新暴露。

## 方案

- 方案 A：继续沿用当前过滤后队列清理协调器。
  - 优点：实现已存在。
  - 缺点：信号不可靠，筛选变化会污染会话态判断。
- 方案 B：新增 domain usecase，专门观察“全词书原始队列里，这张刚提交的卡还在不在”，并只用它决定协调器何时清理。
  - 优点：根因更准确，Today/Review 仍可继续用各自过滤队列决定 UI 展示。
  - 缺点：要补一个新 usecase 和测试。

采用方案 B。

## 修改

- `core/domain/src/main/java/com/zzz/androidvocab/core/domain/ObserveSubmittedCardQueueStateUseCase.kt`
  - 新增 `SubmittedCardQueueState`。
  - 新增 `ObserveSubmittedCardQueueStateUseCase`，在有 pending `submittedCardId` 时固定观察“全词书原始队列”，给出：
    - `submittedCardId`
    - `isStillInRawQueue`
  - 没有 pending 卡时直接返回空状态，不额外访问仓库。
- `feature/review/src/main/java/com/zzz/androidvocab/feature/review/ReviewViewModel.kt`
  - Review 不再用过滤后队列决定何时清理协调器。
  - 改为只在 raw queue 明确不再包含该卡时，才清理共享会话态。
  - UI 里的隐藏/推进下一张判断仍然基于当前过滤后的可见队列。
- `feature/today/src/main/java/com/zzz/androidvocab/feature/today/TodayViewModel.kt`
  - Today 同样改为只根据 raw queue 决定协调器清理。
  - `isRefreshingReviewSession` 仍按当前过滤后队列决定，避免用户切换到不含该卡的词书时错误显示“同步中”。
- `core/domain/src/test/java/com/zzz/androidvocab/core/domain/UseCasesTest.kt`
  - 新增：
    - `submittedCardQueueStateUsesAllBooksQueue()`
    - `submittedCardQueueStateSkipsRepositoryWhenNothingPending()`
  - 直接锁定新 usecase 的原始队列语义。
- `feature/today/src/test/java/com/zzz/androidvocab/feature/today/TodayViewModelTest.kt`
  - 新增 `keepsSubmittedCardPendingWhenOnlyFilteredQueueDropsIt()`。
  - 锁定“当前过滤队列里看不见这张卡，不等于可以清理共享协调器”。
- `feature/review/src/test/java/com/zzz/androidvocab/feature/review/ReviewViewModelTest.kt`
  - 适配新 usecase 注入，保持原有会话语义测试继续成立。
