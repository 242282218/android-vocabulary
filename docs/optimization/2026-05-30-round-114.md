# 第 114 轮：Today 导入状态不阻断可用学习队列

## 审查证据

- `TodayScreen` 原来在 `isImporting` 或 `errorMessage` 存在时直接 `return`，会隐藏后续 `overview`。
- `TodayViewModel` 通过 `combine` 同时输出 `overview`、`isImporting` 和导入错误；因此本地 Room 已有可用队列时，导入中或导入失败状态可能与可学习队列同时存在。
- `AssetVocabularyRepository.importPublishSafeVocabulary()` 会校验 assets / manifest / hash；这些失败不应在已有本地学习数据可用时阻断离线学习入口。
- 移动状态设计参考要求失败状态说明原因、影响和恢复动作；关键 CTA 不能被可恢复状态永久遮挡。

## 方案

- 方案 A：保持导入中/失败全屏状态。简单，但会在已有本地队列时误挡“开始学习”。
- 方案 B：当 `overview` 已有学习证据时，把导入中/失败显示为状态卡；首装或无学习证据时继续全屏导入/错误。范围小，不改变 ViewModel 数据流。
- 方案 C：给 ViewModel 增加显式 `hasImportedVocabulary` 状态。语义更精确，但需要 Repository/DAO 额外暴露导入状态，改动更大。

采用方案 B。
