# 2026-05-25 持续优化第 68 轮

## 当前审查范围

本轮审查 `build\bundle-smoke` 历史 APK Set 产物是否可能被误当成正式发布产物。

## 发现

本地存在多个 APK Set：

```text
build\bundle-smoke\AndroidVocabulary-release-v0.1.0-1.apks
build\bundle-smoke\AndroidVocabulary-release-v0.1.0-1-debug-signing.apks
build\bundle-smoke\app-release.apks
```

`build\bundle-smoke` 属于 `build/` 目录，被 `.gitignore` 忽略；这些 `.apks` 是 bundletool 安装验证中间产物，不是应用商店上传产物。第 67 轮已经让新产物默认带 `release-signing` / `debug-signing` 后缀，但旧的无后缀历史产物仍可能在本地目录中存在。

## 完成项

`docs/release.md`

- 在 AAB 安装级验证段补充说明：
  - APK Set 会写入 `build\bundle-smoke\`。
  - 文件名包含 `release-signing` 或 `debug-signing`。
  - APK Set 只是 bundletool 安装验证中间产物。
  - 正式上传只使用 `dist\AndroidVocabulary-release-v<versionName>-<versionCode>.aab`。

## 剩余风险

- 旧的无后缀 `.apks` 仍存在于本地 `build\bundle-smoke`，但属于 ignored 中间产物；不影响仓库和正式上传路径。
- 当前没有正式 release signing 环境，尚未生成 `release-signing` 后缀 APK Set。
- 当前没有在线设备，尚未验证 AAB `install-apks`。

## 下一轮建议

继续审查 `smoke-release-bundle.ps1` 的 `-ApksPath` 自定义路径行为。当前默认路径能标记签名类型，但用户显式传入路径时可能仍会覆盖已有不同签名性质的 APK Set，需要确认文档或脚本是否应给出更明确提示。
