# 2026-05-18 持续优化第 6 轮

## 当前状态判断

第 5 轮后，核心统计口径进一步统一到 `ReviewLog`。继续检查部署可行性时，发现项目已经能 `assembleRelease`，但缺少一键 release 验证脚本、产物归档位置和发布前检查说明。

## 对标项目可借鉴点

- 可发布项目应把 release 构建做成可重复脚本，而不是依赖开发者记命令。
- Android 内部分发至少需要 release 构建、词库合规校验、质量门禁、APK 产物路径和真机冒烟清单。

## 差距清单

### P1

- release 构建没有统一入口。影响部署可行性；根因是 README 只覆盖 debug 验证；建议增加 `scripts/release/build-release.ps1`；收益是发布前检查可重复；风险低。

### P2

- 缺少 release 说明文档。影响后续分发和交接；根因是发布阻断项散落在 README 和项目规则里；建议补 `docs/release.md`；收益是签名、安装、冒烟和阻断项更清楚；风险低。

### P3

- 正式签名 keystore 尚未接入 Gradle 环境变量配置。
