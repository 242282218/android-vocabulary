# 2026-05-25 持续优化第 158 轮

## 当前审查范围

本轮接着第 157 轮，审查 split 后的 `deviceBundleSmokeArchive` evidence 指向。上一轮已经把 bundle smoke 子日志原文校验拆成独立 requirement，但它的 failure evidence path 仍复用设备验收目录中的源路径变量。

## 发现

`deviceBundleSmokeArchive` 实际读取的是 `build/release-readiness/evidence-smoke-release-bundle-run.txt`，但 failure evidence 的 `path` 指向源路径或 `<missing>`。成功路径下这会让复核者误以为 requirement 校验的是设备验收目录中的源文件，而不是 readiness 归档文件。

## 方案

- 方案 A：继续输出源路径。可追溯原始来源，但和实际校验对象不一致。
- 方案 B：输出 readiness 归档路径，并额外保留 `deviceBundleSmokeMetadata` 作为源路径。

本轮采用方案 B。`deviceBundleSmokeMetadata` 继续表达源路径，`deviceBundleSmokeArchiveMetadata` 和 requirement path 表达归档路径。
