## 当前审查范围

本轮接着第 160 轮，审查 `release-readiness-run.txt` 是否还有重复 metadata key。上一轮把 GitHub Actions 路径字段改为 `githubActionsEvidenceMetadata`，但还没有把“无重复 key”固化成回归检查。

## 发现

当前生成的 `release-readiness-run.txt` 已无重复 key，但缺少自动回归保护。以后新增 metadata 或 requirement 时，仍可能再次出现同名 key 覆盖问题。

## 方案

- 方案 A：只依赖人工检查。无改动，但容易回归。
- 方案 B：在 `verify-release-scripts.ps1` 中加入 metadata key 唯一性检查；如果当前 readiness metadata 存在则解析并拒绝重复 key，同时静态禁止旧的 `githubActionsEvidence=$githubEvidence` 写法。

本轮采用方案 B。它是轻量检查，不需要设备或正式签名环境。
