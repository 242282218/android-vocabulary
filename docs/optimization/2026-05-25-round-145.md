# 2026-05-25 持续优化第 145 轮

## 当前审查范围

本轮接着第 144 轮，审查 APK smoke 证据是否绑定具体 APK 文件。第 144 轮已经让 release artifact 审计记录 APK/AAB SHA-256，并让 readiness 重算 `dist/` 中 release 产物 hash；但 APK smoke metadata 仍只记录路径和文件名匹配，没有记录实际安装 APK 的 SHA-256。

## 发现

`build/apk-smoke/smoke-release-apk-run.txt` 当前缺少 `apkSha256`。这意味着 release readiness 只能判断 APK smoke 使用了当前版本化文件名，不能确认被安装 APK 与 release artifact 审计记录中的 APK 是同一个文件。

## 方案

- 方案 A：继续只校验 APK 路径和版本化文件名。改动少，但证据链不能防止同名文件替换。
- 方案 B：APK smoke metadata 写入实际 APK SHA-256，readiness 要求它与 `release-artifacts-run.txt` 中的 `releaseApkSha256` 一致。

本轮采用方案 B。它不改变设备安装流程，只增强证据绑定。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 新增 `Get-ApkSmokeSha256Value`。
- metadata 增加 `apkSha256`。
- `-SkipInstall` 时写入 `apkSha256=<not used>`，避免跳过安装被误判为完整 APK smoke。

`scripts/test/verify-release-readiness.ps1`

- 读取 APK smoke metadata 中的 `apkSha256`。
- `releaseApkSmoke` 要求：
  - `runStatus=completed`
  - 当前 `versionName` / `versionCode`
  - `skipInstall=False`
  - `apkPathMatchesCurrentVersionedName=True`
  - `apkSha256` 是 64 位小写 SHA-256
  - `apkSha256` 等于 release artifact metadata 中的 `releaseApkSha256`
- readiness metadata 增加 `apkSmokeSha256`。

`scripts/test/verify-release-scripts.ps1`

- 增加 APK smoke SHA-256 metadata 写入的回归断言。
- 增加 readiness 对 APK smoke SHA-256 比对逻辑的源码结构回归断言。
- 更新 APK smoke early failure metadata 回归，要求失败归档中包含 `apkSha256=<unresolved>`。

文档同步：

- `README.md`
- `docs/release.md`

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- AAB 设备验收 metadata 仍未绑定 release AAB SHA-256。
