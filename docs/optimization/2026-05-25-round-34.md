# 2026-05-25 持续优化第 34 轮

## 当前审查范围

本轮继续审查数据库层 `review_logs` 读取口径，重点确认哪些查询应该读取完整事实表，哪些查询应该只读取仍有关联词书归属的有效复习日志。

## 发现

`valid_review_logs` 已作为有效日志视图被统计、导出和到期队列使用，但 `ReviewDao` 中两个修复/诊断用 cardId 查询仍手写 `review_logs` 与 `wordbook_memberships` join。该写法语义等价，但重复了有效日志条件，后续容易出现统计、导出、修复口径不一致。

`observeNewQueue()` 也用原始 `review_logs` 判断词条是否学过。对当前有词书归属的词条来说，使用 `valid_review_logs` 更贴近“有效学习事实”语义；孤儿日志仍由 `countOrphanLogs()` 单独诊断，不应参与正常队列和修复流程。

## 方案取舍

1. 保持现状，只记录风险。
   - 优点：零行为改动。
   - 缺点：有效日志条件继续散落在多个 SQL 中，后续维护容易漏改。
2. 将等价的有效日志查询收敛到 `valid_review_logs`。
   - 优点：修复、统计、导出、队列共享同一有效日志口径。
   - 缺点：需要补测试确认有日志但 card 缓存缺失时不会重新进入新词队列。

本轮采用方案 2。`getLogs(cardId)` 保留读取原始 `review_logs`，用于指定 card 的完整重放；`countOrphanLogs()` 保留读取原始 `review_logs`，用于孤儿日志诊断。
