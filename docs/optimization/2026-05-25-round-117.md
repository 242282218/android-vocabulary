# 2026-05-25 持续优化第 117 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 的崩溃日志提取路径，重点确认补充 crash context 时不会掩盖原始启动失败。

## 发现

审查和 fake adb 验证发现两个问题：

1. `pidof` 返回空输出但 exit code 为 0 时，脚本直接执行：

```powershell
(... | Select-Object -First 1).Trim()
```

如果没有第一行输出，会先触发 `$null.Trim()`：

```text
You cannot call a method on a null-valued expression.
```

真实的 “App process is not running” 和崩溃上下文逻辑都不会执行。

2. `Throw-WithFatalCrashContext` 为原始错误补充 logcat 崩溃上下文时，如果读取 logcat 本身失败，原始错误有被 logcat 失败覆盖的风险。

## 方案

- 方案 A：让所有 logcat 读取都容错。会降低 `Assert-NoFatalCrash` 的严格性，可能放过真实崩溃。
- 方案 B：只让 `Throw-WithFatalCrashContext` 的补充上下文读取容错；主动断言 `Assert-NoFatalCrash` 仍保持严格失败。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- `pidof` 输出先保存为 `$appProcessIdText`，空输出时转为空字符串，避免 `$null.Trim()`。
- `Throw-WithFatalCrashContext` 捕获 `Get-FatalCrashText` 的读取失败，保留原始错误并追加：

```text
Unable to read fatal crash context: ...
```
