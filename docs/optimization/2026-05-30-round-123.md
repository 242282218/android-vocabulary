# 第 123 轮：数据维护 manual-only 状态回归保护

## 审查证据

- `SettingsRoute.DataMaintenanceCard()` 只有在 `repairableIssueCount > 0` 时显示“修复学习数据缓存”。
- `SettingsViewModel` 的检查文案会同时展示可修复项和需人工确认项。
- 现有测试覆盖混合问题和修复成功，但没有单独锁住 legacy / orphan 这类 manual-only 问题，后续改动容易把它们误当成可自动修复。

## 方案

- 方案 A：只依赖 UI 条件判断。代码少，但可修复状态散在 UI 表达式里，测试不容易直接覆盖。
- 方案 B：把可修复状态收敛为 `DataMaintenanceUiState.hasRepairableIssues`，UI 使用该状态，并补 manual-only ViewModel 回归测试。范围小，能锁住业务语义。
- 方案 C：新增 Compose UI 测试直接断言按钮不存在。覆盖更贴近界面，但测试成本更高，且本轮重点是状态语义。

采用方案 B。

## 修改

- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsViewModel.kt`
  - `DataMaintenanceUiState` 新增派生状态 `hasRepairableIssues`。
- `feature/settings/src/main/java/com/zzz/androidvocab/feature/settings/SettingsRoute.kt`
  - 数据维护卡片用 `hasRepairableIssues` 控制修复按钮显示。
- `feature/settings/src/test/java/com/zzz/androidvocab/feature/settings/SettingsViewModelTest.kt`
  - 新增 `inspectLearningDataKeepsManualOnlyIssuesNonRepairable`。
  - 覆盖 legacy + orphan 只产生人工确认项、`hasRepairableIssues == false`、文案计数正确。
