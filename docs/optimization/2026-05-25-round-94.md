# 2026-05-25 持续优化第 94 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 的默认 APK 选择逻辑，确认在归档产物和 Gradle 输出产物之间的选择是否清晰可诊断。

## 发现

`Get-DefaultApk` 当前按固定顺序查找当前版本化 APK：

1. `dist\AndroidVocabulary-release-v<versionName>-<versionCode>.apk`
2. `app\build\outputs\apk\release\AndroidVocabulary-release-v<versionName>-<versionCode>.apk`

如果两处都找不到，会列出这两个目录中现有的 APK，并提示传 `-ApkPath` 或先运行 `build-release.ps1`。脚本随后会输出：

```text
[info] verifying APK signature: <resolvedApkPath>
```

因此默认选择结果会进入 smoke 日志，执行者能判断实际验证的是归档产物还是 Gradle 输出产物。

当前本机两处都存在当前版本 APK：

- `dist\AndroidVocabulary-release-v0.1.0-1.apk`
- `app\build\outputs\apk\release\AndroidVocabulary-release-v0.1.0-1.apk`

默认 smoke 会优先验证 `dist` 中的归档产物。这符合发布验收目标。

## 完成项

本轮未修改代码。现有逻辑已经满足：

- 不按时间猜测 APK。
- 不因额外 APK 存在而误阻断。
- 缺失时列出可用 APK。
- 成功路径打印实际验签文件。

## 验证结果

源码与文档引用检查：

```powershell
rg -n "Get-DefaultApk|No APK found for current version|Available APKs|verifying APK signature|ApkPath|dist|outputs\\apk\\release" scripts/test/smoke-release-apk.ps1 docs/release.md README.md docs/optimization/2026-05-25-round-93.md -S
```

结果：默认 APK 选择、缺失错误、显式 `-ApkPath` 示例和实际验签路径输出均可定位。

当前 `dist` APK 检查：

```powershell
Get-ChildItem .\dist -Filter '*.apk' -File -ErrorAction SilentlyContinue | Select-Object Name,FullName,Length,LastWriteTime
```

结果：存在 `AndroidVocabulary-release-v0.1.0-1.apk`。

当前 Gradle release APK 输出检查：

```powershell
Get-ChildItem .\app\build\outputs\apk\release -Filter '*.apk' -File -ErrorAction SilentlyContinue | Select-Object Name,FullName,Length,LastWriteTime
```

结果：存在 `AndroidVocabulary-release-v0.1.0-1.apk`。
