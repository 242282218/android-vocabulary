# 2026-05-25 持续优化第 111 轮

## 当前审查范围

本轮审查 `smoke-release-apk.ps1` 中非 capture ADB 调用失败时的诊断信息。

## 发现

`Invoke-AndroidDebugBridge` 的非 capture 分支原本直接执行 ADB：

```powershell
& $script:AdbPath @deviceArgs @Arguments
if ($LASTEXITCODE -ne 0) {
    throw "adb ... failed with exit code $LASTEXITCODE"
}
```

这类调用覆盖 `install`、`logcat -c`、`monkey`、`uiautomator dump`。失败时控制台可能有 ADB 输出，但异常本身只有 exit code。被 AAB smoke 或设备验收脚本包装时，定位安装/启动失败不够直接。

## 方案

- 方案 A：只对 `install` 和 `monkey` 单独包输出。影响更小，但同类 ADB 失败语义继续分散。
- 方案 B：在 `Invoke-AndroidDebugBridge` 的非 capture 分支统一实时输出并捕获最后输出。所有非 capture ADB 调用共享一致失败诊断。

本轮采用方案 B。

## 完成项

`scripts/test/smoke-release-apk.ps1`

- 非 capture ADB 调用现在临时使用 `$ErrorActionPreference='Continue'`。
- ADB stdout/stderr 通过 `ConvertTo-AndroidVocabularyOutputText` 转成纯文本，并用 `Tee-Object` 保持实时输出。
- 失败时异常包含 exit code 和 `Last output`，最长保留 2000 字符。
