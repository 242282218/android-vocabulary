# 2026-05-25 持续优化第 67 轮

## 当前审查范围

本轮审查 AAB smoke 生成的 APK Set 产物是否能在 release 验证记录中区分正式签名和 debug signing。

## 发现

`smoke-release-bundle.ps1` 原本默认把 APK Set 写到：

```text
build\bundle-smoke\AndroidVocabulary-release-v<versionName>-<versionCode>.apks
```

这个文件名只体现 AAB 版本，不体现 bundletool 生成 APK Set 时使用的是正式 release signing，还是 `-AllowDebugSigning` 触发的本地 debug signing。

风险是本地验证记录中 `.apks` 文件看起来像正式产物，但实际可能是 debug keystore 生成的安装包集合。

## 完成项

`scripts/test/smoke-release-bundle.ps1`

- 在调用 `Add-BundleToolSigningArgs` 后再决定默认 `-ApksPath`。
- 默认 APK Set 文件名增加签名类型后缀：

```text
AndroidVocabulary-release-v<versionName>-<versionCode>-release-signing.apks
AndroidVocabulary-release-v<versionName>-<versionCode>-debug-signing.apks
```

- 输出新增：

```text
[info] APK Set signing=<release-signing|debug-signing>
```

- 显式传入 `-ApksPath` 时仍尊重调用方路径，不强制改名。

## 验证结果

PowerShell 解析检查：

```powershell
$tokens = $null; $parseErrors = $null; $null = [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path 'scripts/test/smoke-release-bundle.ps1'), [ref]$tokens, [ref]$parseErrors)
```

结果：通过。

实际构建 APK Set：

```powershell
.\scripts\test\smoke-release-bundle.ps1 -BuildOnly -AllowDebugSigning
```

结果：通过，输出包含：

```text
[info] APK Set signing=debug-signing
[ok] APK Set: D:\PROJECT_ZZZZZZZZZ\安卓背单词\build\bundle-smoke\AndroidVocabulary-release-v0.1.0-1-debug-signing.apks
[ok] bundle smoke build-only passed with debug signing; not release-ready
```

产物检查：

```powershell
Get-ChildItem build/bundle-smoke -Filter 'AndroidVocabulary-release-v0.1.0-1*.apks'
```

结果：生成了 `AndroidVocabulary-release-v0.1.0-1-debug-signing.apks`。旧的无后缀 `AndroidVocabulary-release-v0.1.0-1.apks` 是本轮改动前的历史本地产物，不再是脚本默认输出。

空白检查：

```powershell
git diff --check -- scripts/test/smoke-release-bundle.ps1 README.md docs/release.md docs/optimization/2026-05-25-round-66.md
```

结果：通过，仅有 README 和 `docs/release.md` 的 LF/CRLF 工作区提示。

## 剩余风险

- 本轮没有在线设备，因此只验证了 `bundletool build-apks --mode=universal`，未验证 `bundletool install-apks`。
- 当前没有正式 release signing 环境，因此只验证了 debug signing 文件名；`release-signing` 路径仍需在正式签名环境中执行。

## 下一轮建议

继续审查 `build\bundle-smoke` 历史产物是否会误导发布记录，必要时在文档中说明该目录是中间验证输出，正式上传只看 `dist\*.aab`。
