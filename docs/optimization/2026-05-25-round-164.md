# 2026-05-25 持续优化第 164 轮

## 当前审查范围

本轮接着第 163 轮，审查 release readiness 默认设备验收 evidence 选择逻辑。上一轮已经用隔离 fixture 证明正向 evidence 可以通过，但默认设备验收路径仍按文件写入时间选择最新 `verification-completed.txt`。

## 发现

按时间选择最新设备验收完成日志有误用风险：如果较新的 `verification-completed.txt` 来自旧 AAB、错版本 AAB 或调试验证目录，readiness 会先读取它，再在后续 requirement 中失败。这个行为不会放过错误发布，但失败原因会被“较新的不相关日志”污染，降低发布门禁的可诊断性。

## 方案

- 方案 A：保留“最新 completed 文件”策略。兼容性最好，但默认路径容易被不相关日志遮挡。
- 方案 B：默认只选择最新且匹配当前 `versionName`、`versionCode` 和当前 release AAB SHA-256 的 completed 日志；显式 `-DeviceVerificationEvidencePath` 保持原样。

本轮采用方案 B。正式发布仍建议显式传入本次设备验收 evidence；默认路径只作为更稳的兜底。
