# 第 130 轮：Release manifest 备份策略回归

## 审查证据

- `app/src/main/AndroidManifest.xml` 当前设置 `android:allowBackup="false"`。
- `app/src/main/res/xml/backup_rules.xml` 和 `data_extraction_rules.xml` 当前处于删除状态，manifest 也没有再声明 `fullBackupContent` / `dataExtractionRules`。
- `verify-release-scripts.ps1` 之前没有锁住 manifest 备份策略，后续误改可能让本地学习数据进入系统备份路径。

## 方案

- 方案 A：只依赖人工审查 manifest。成本低，但发布前容易漏。
- 方案 B：在 `verify-release-scripts.ps1` 中加入 manifest 备份策略检查，要求 `allowBackup=false`，并禁止在 backup 关闭时声明 `fullBackupContent` / `dataExtractionRules`。范围小，可纳入现有 `verify-local.ps1` 前置检查。
- 方案 C：新增独立 `verify-release-manifest.ps1`。职责更清晰，但需要接入更多脚本和文档，本轮不需要。

采用方案 B。

## 修改

- `scripts/test/verify-release-scripts.ps1`
  - 新增 `Test-ReleaseManifestBackupPolicy`。
  - 回归流程中调用该检查，锁住 `allowBackup=false` 和无 backup/data extraction 引用。
