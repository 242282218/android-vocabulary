# 2026-05-25 持续优化第 150 轮

## 当前审查范围

本轮接着第 149 轮，审查 release artifact audit evidence 输入是否可追溯。前两轮已经让 APK smoke 和设备验收 evidence 可显式指定，但 `verify-release-readiness.ps1` 仍固定读取 `build/release-artifacts/release-artifacts-run.txt`。

## 发现

正式 release readiness 应明确绑定本次 release artifact 审计记录。如果后续又运行了 artifact 审计，固定路径可能被覆盖。虽然 readiness 会重算当前 `dist/` APK/AAB SHA-256 并与 metadata 比对，但正式发布记录仍应能显式指向本次保留的审计 evidence。

## 方案

- 方案 A：继续读取默认 `build/release-artifacts/release-artifacts-run.txt`。兼容性最好，但证据输入不可显式固定。
- 方案 B：增加 `-ReleaseArtifactsEvidencePath`，未传时保留默认路径；正式发布文档要求显式传入本次 `release-artifacts-run.txt`。

本轮采用方案 B。它保持现有默认行为，同时让 release readiness 的三类本地 evidence 都可显式指定。

## 完成项

`scripts/test/verify-release-readiness.ps1`

- 新增参数 `-ReleaseArtifactsEvidencePath`。
- 新增 `Get-ReleaseArtifactsMetadataPath`：
  - 未传参数时沿用默认 `build/release-artifacts/release-artifacts-run.txt`。
  - 传入参数时解析该路径；不存在时保留未解析绝对路径，便于失败 metadata 指向用户输入。
- readiness metadata 增加：
  - `releaseArtifactsEvidenceMode=default|explicit`
  - `releaseArtifactsEvidenceInput=<default>|<path>`

`scripts/test/verify-release-scripts.ps1`

- 增加源码结构回归断言，锁定显式 release artifacts evidence 参数、路径解析和 metadata 字段。

文档同步：

- `README.md`
- `docs/release.md`

## 剩余风险

- 当前没有正式 release signing 环境，未验证 readiness 正向成功路径。
- 当前没有在线 Android 设备，未验证显式三类本地 evidence 参数在正向 release readiness 中通过。
- readiness metadata 记录了输入 evidence 路径和关键字段，但没有把本次读取的原始 evidence 文件复制归档到 `build/release-readiness/`。
