# 2026-05-25 持续优化第 89 轮

## 当前审查范围

本轮审查 APK 签名验证失败诊断，覆盖 `smoke-release-apk.ps1` 和 `build-release.ps1`。

## 发现

`apksigner verify --verbose` 失败时会向 stderr 输出：

```text
DOES NOT VERIFY
ERROR: Missing META-INF/MANIFEST.MF
```

脚本顶部设置了 `$ErrorActionPreference = 'Stop'`。本地验证发现，在这种情况下直接执行：

```powershell
& $apkSigner verify --verbose .\dist\AndroidVocabulary-release-v0.1.0-1.apk 2>&1
```

会触发 `NativeCommandError` 并提前终止脚本。影响有两点：

- `smoke-release-apk.ps1` 的最终错误可能只剩脚本调用栈，不稳定保留 verbose 输出。
- `build-release.ps1 -AllowUnsigned` 可能在进入 `AllowUnsigned` 分支前就被打断，无法稳定输出 `build-validation APK, not release-ready`。

## 方案

- 方案 A：在调用 `apksigner` 时临时把 `$ErrorActionPreference` 调整为 `Continue`，捕获 stdout/stderr 和 exit code，再恢复原设置。按 exit code 统一判断。改动小，保留现有输出语义。
- 方案 B：改用 `cmd /c` 包一层。能规避 PowerShell native stderr 行为，但会引入额外 shell 转义风险。

本轮采用方案 A。

```powershell
$files=@('scripts/test/smoke-release-apk.ps1','scripts/release/build-release.ps1'); foreach ($file in $files) { $tokens=$null; $errors=$null; [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $file), [ref]$tokens, [ref]$errors) | Out-Null; if ($errors.Count -gt 0) { Write-Error "$file parse failed"; $errors | ForEach-Object { $_.Message }; exit 1 } }; 'parse-ok'
```

结果：通过。

`apksigner` 捕获实验：

```powershell
. .\scripts\lib\android-env.ps1; Use-AndroidVocabularyJavaHome; $apkSigner = Get-AndroidTool -Names @('apksigner.bat', 'apksigner') -RelativeDirs @('build-tools'); $previousErrorActionPreference = $ErrorActionPreference; $ErrorActionPreference = 'Continue'; try { $signatureOutput = & $apkSigner verify --verbose .\dist\AndroidVocabulary-release-v0.1.0-1.apk 2>&1; $signatureExitCode = $LASTEXITCODE } finally { $ErrorActionPreference = $previousErrorActionPreference }; $signatureText = ($signatureOutput -join "`n").Trim(); "exit=$signatureExitCode"; "text=$signatureText"
```

结果：能稳定得到 `exit=1`，并捕获 `DOES NOT VERIFY` / `ERROR: Missing META-INF/MANIFEST.MF`。
